### Release integrity (C1) — landed 2026-08-23

- **Buys** — A green release means reviewed generated clients are current, static checks passed, and a required deployment was not silently skipped.
- **Evidence** — `publish.yml` regenerated clients after the primary validation job, direct snapshot/manual publishes bypassed that job, formatting and lint were non-blocking in `script/ci-validate.ts`, and the Railway job exited successfully when `RAILWAY_TOKEN` was absent.
- **Implementation** — Validation regenerates the HttpApi clients and fails on tracked drift; formatting and lint are blocking. Direct publishes run the same central validation unless the `ci-pipeline` caller explicitly marks them prevalidated. A missing Railway credential fails the required deploy job.
- **Done when** — `ci-targeted.test.ts` pins all four invariants, a direct publish cannot reach `Publish` without validation, and the normal `live-main` path does not duplicate validation.

  **A fifth silent-drift channel, found 2026-08-25 and closed.** C1's premise is that a green release means the static checks actually ran. Dependency _patches_ were outside that: `patchedDependencies` is keyed by an exact `name@version`, so bumping the dependency stops the patch applying, and bun reports nothing. Every signal a reviewer reads still says the patch is there — the entry sits in `package.json`, the `.patch` file sits in `patches/`. The lockfile quietly drops the unappliable key, which is the one place it showed, and nobody reads that hunk.

  Two live instances, both fixed. `@modelcontextprotocol/sdk` went 1.25.2 → 1.26.0 on the release bump and dropped the patch that stops an SSE reconnect storm when a server answers a JSON-RPC _error_ rather than a result; the regression test that commit shipped (`test/mcp/streamable-http-transport.test.ts`) was red for 25 days, asserting 1 request and getting 11. The one-line change still applies verbatim to 1.26.0, so the fix was purely re-keying. Separately `packages/app` resolved `ghostty-web@0.4.0` while the patch covered only the `0.3.0` that nikcli and remote use, so the desktop terminal ran without the guard that keeps `String.fromCodePoint` from throwing on a lone surrogate or an out-of-range codepoint; 0.4.0 had fixed one of the five sites upstream and left four, which are now patched.

  `script/check-patched-deps.ts` is the missing signal, blocking in `ci-validate.ts`. It reads `bun.lock` rather than `node_modules`, so it answers the same before and after an install. It fails on a patch whose version is not installed, a missing patch file, a patch file nothing references, and a workspace resolving to a version no patch covers. That last check is scoped to workspaces on purpose: a stray copy pulled in by an unrelated third-party dependency is not evidence of anything, and flagging those is how a check becomes noise people learn to skip. A package may carry one entry per version its workspaces use, so coverage is compared against the whole patched set — comparing per entry makes each entry accuse the others, which is a bug this check had before its own tests caught it.

  Verified by mutation both ways: four mutations of the script each turn exactly one test in `test/release/patched-deps.test.ts` red, and the two fixture cases reproduce the two real bugs rather than describing them. The fixtures are synthetic roots passed as an argument, because asserting against the live tree would only ever pin today's state.

A stalled reader is evicted with a stated reason instead of growing an unbounded internal queue; `/global/event` went from one `GlobalBus` listener per client to one total. The HTTP wire is unchanged — boundaries emit the literal `"NotFoundError"` rather than forwarding `_tag`, which also fixes two sites that produced the tag by coincidence.
- **Tool output schemas** (was T2, landed 2026-08-14). A tool may declare an `output` zod codec; the wrapper parses `result.value` after execute and rejects a malformed success for that call only. Code Mode receives `Tool.encoded(result, codec)` — the validated value when a codec exists, otherwise the model-facing string. Truncation still bounds only `output`. Tools without a codec are unchanged. Built-ins are not required to declare a codec. See [v2/tools.md](./v2/tools.md) §"One Response Value, Not Three".
- **Provider policy** (was P1, landed 2026-08-14). `Policy` centrally evaluates `experimental.policies` with full or trailing-prefix wildcards and ordered last-match-wins. Legacy enabled/disabled fields translate with their old precedence; the provider catalog, HTTP provider list, CLI auth picker, and session auth picker consume the evaluator, while TUI disconnect writes deny statements. Unit tests cover matching, translation, overrides, filtering, and schema validation; HTTP integration covers legacy allowlist filtering. See [v2/provider-policy.md](./v2/provider-policy.md).
- **Scoped tool registration** (was T1, landed 2026-08-14). `ToolRegistry.register` returns a handle whose `close` removes exactly that stack entry and reveals the next-latest occupant of the id. Config-dir and plugin tools live in a reloadable derived cache; runtime registrations live in a separate non-reloadable cache, so a hot reload cannot drop sdk-next tools. See [v2/tools.md](./v2/tools.md) §"Registration Is An Overlay Stack".
- **Durable pending input** (was S1, landed 2026-08-14). Busy input lives in `session_pending` until atomic batched promotion, outside transcript history. The TUI restores queued message cards with `press ctrl-enter to send`: Enter queues, Ctrl/Cmd+Enter with text steers the new input, and the same shortcut with an empty composer changes the oldest queued card to steering until promotion. See [v2/durable-pending-input.md](./v2/durable-pending-input.md).
- **Instruction sync** (was S3, landed 2026-08-14). Request assembly admits a `session.instructions.updated` delta of content hashes, stores bodies once in `instruction_blob`, and renders the system prefix from the fold. See [v2/instruction-sync-proposal.md](./v2/instruction-sync-proposal.md).

### Encode optionals as absent keys (E4)

**The original framing was wrong. Measured 2026-08-18 by deleting the helper and running the
route tests; corrected below before anyone repeats it.**

- **Buys** — The remaining `jsonSafe` handlers (`session.ts`, `provider.ts`, `config.ts`) stop doing `JSON.parse(JSON.stringify(...))` before HttpApi encodes.
- **Evidence** — `Schema.optional` is `optionalKey(UndefinedOr(self))` (`node_modules/effect/src/Schema.ts:2022`), so `undefined` is a valid _union member_ — and the HTTP encode path serializes that member as **`null`**. `jsonSafe` is what turns a present `undefined` into an _absent key_; it is load-bearing, not the defensive placeholder its own comment claims. Deleting it while the schemas stay `Schema.optional` produces:
  - `POST /session/:id/unrevert` → `revert: null` instead of absent (fails `httpapi-session.test.ts:270`)
  - `GET /session/:id/context` → `model: null`
  - `GET /config` → **400** (`httpapi-config.test.ts:113`, the test written for exactly this)

  Flipping those response schemas to `optionalKey` instead does not work on its own either: `optionalKey` _rejects_ a present `undefined` at encode time, and the producers emit one — `session/context-breakdown.ts:362` (`detail: firstLine ? … : undefined`) and `:418` (`model`), and `delegation/manager.ts` `projectJob`, which assigns all ten optional `JobItem` members unconditionally.

  **A schema-level probe lies about this.** `Schema.encodeUnknownEffect` returns the JS object with the present-`undefined` own property still attached, and the `Result`'s `toJSON` renders it through `JSON.stringify`, which drops it — so the probe prints `{"a":"x"}` and reads as "key dropped". (The success field is `.success`, not `.value`.) Only a real request through `Server.fetch` shows the `null`. Verify this class of change end to end, never with a probe.

- **Depends on** — nothing, but it is **not** the small item it looked like. It is producer-by-producer: each response schema flips to `optionalKey` **and** its producer stops writing present-`undefined`, together, per endpoint. **Scope closed 2026-08-19 (fifth slice).** `httpapi/session.ts` is down to three `jsonSafe` call sites — `v2Entries`, `v2State`, `v2Events` — the `Schema.Unknown` payloads that keep it permanently. The `provider.ts` and `config.ts` calls that remain are the live-`fetch` records, not optionality; both carry a comment saying so, and removing them is a different item.
- **How to do a slice** — The compiler will not help: `exactOptionalPropertyTypes` is off, so `field?: X` still accepts `undefined` and every producer bug is a runtime 400. Flip the schema, then grep the producers three ways — `draft.<field> = undefined`, an object literal that assigns an optional member unconditionally, and any value typed `T | null` handed to a `string` member (`null` fails `optionalKey` exactly like a present `undefined`, and that is what broke `sessionWarp`'s detach path). Use `setOptional` from `@/util/optional-key`, or `...(v !== undefined && { k: v })` in a literal. Then run the **whole** suite, not the route test: the three producers this slice missed were caught by `httpapi-workspace.test.ts` and `workspace-warp-route.test.ts`, not by the session tests.
- **`MessageV2` was the last slice, and it was smaller than it looked. Landed 2026-08-19.** 53 `Schema.optional` across the message and part schemas, and 144 part literals across 19 files — but the Effect encoder only ever sees them on **four** handlers (`messages`, `message`, `command`, `shell`), and three of those read rows that were round-tripped through `JSON.stringify` on write, so they cannot carry a present `undefined`. **Corrected 2026-08-19:** an earlier draft of this bullet claimed a part that fails to encode inside an SSE frame is silently withheld. It is not. SSE is a raw streaming response — `EventFeed.frame()` is `JSON.stringify`, which drops present-`undefined` and never consults the schema, and its one failure path already logs (`event encoding failed`). The streaming producers are not on the encode path at all; `command` and `shell`, which return freshly built messages, are.
- **The config 400 was one unconditional key, not the converter.** Measured 2026-08-19 with the encode-failure log from the first slice: `config.ts`'s agent transform returned `{ ...agent, options, permission, steps }` where `steps = agent.steps ?? agent.maxSteps`, so every agent that declares neither carried a present `undefined`. `Schema.Unknown` at the JSON boundary is `Schema.Json`, which walks the value and rejects it — hence a 400 rather than a `null`. Spreading the key fixed `GET /config` with no schema change at all. `util/zod-effect.ts:165` still decides optionality for the whole `nikcli.json` document in one place, but it did not have to move, and it should not move without its own evidence.
- **`/provider` and `/config/providers` keep `jsonSafe` for a different reason entirely.** Not optionality: a provider whose credential comes from the account sign-in carries a live `fetch` **function** in `options` (`provider/provider.ts` ~539), and `options` is `Schema.Record(String, Unknown)`, which rejects a function at the JSON boundary. The round-trip launders it out. Removing it there needs the function to stop living in a schema-declared record — a different item, and one no unit test would have caught: the test catalog is empty, so this only appears against real models.dev data.
- **`jsonSafe` cannot leave `session.ts` entirely.** `v2Entries` / `v2State` / `v2Events` declare `Schema.Unknown` on purpose (the entry variant set grows without a contract bump — see non-goals), and `Schema.Unknown` rejects a present `undefined` regardless of what the producers do. Those three keep the round-trip until entries stop carrying `undefined`, which is a different item. Amend "Done when" accordingly: the target is `session.ts` down to the `Unknown` payloads, not zero.
- **Costs if skipped** — Nothing user-visible. `jsonSafe` produces the correct wire shape today; this is a cost and clarity item, not a bug.
- **Done when** — Per endpoint: the response schema uses `optionalKey`, the producer omits the key, and a route test asserts the key is _absent_ (not `null`) with a service object that leaves the field unset. `session.ts` keeps `jsonSafe` only for the three deliberately open SessionV2 payloads; `provider.ts` and `config.ts` keep it only where live `fetch` functions must be removed before JSON encoding. Curl `GET /session`, `GET /session/:id`, `GET /config`, and `GET /provider` against real data with unset optionals. These criteria were met on 2026-08-19.
- **Already paid for** — The two live 400s this same failure mode was causing are fixed (see 2026-08-18 landed work): `mission.ts` `featureMutate` and `config/tui.ts` `plugin_meta`. Grep for `= undefined` on a field whose response schema is `optionalKey` before adding one.

#### Bootstrap teardown reports success as failure (R3) — landed 2026-09-09

- **Buys** — CLI commands whose exit code means what it says. Every `bootstrap`-based command currently prints its correct answer and then exits **1**.
- **Evidence (measured 2026-09-09, compiled binary, real home)** — `nikcli api path.get` prints the right JSON, then `All fibers interrupted without error`, then `Error: Unexpected error, check log file`, exit 1. **`nikcli stats` — untouched by any work in this session — fails identically**, so this is not X3's. `nikcli debug paths`, which never calls `bootstrap`, exits 0. The logged stack is `causeSquash`, i.e. an interrupt-only `Cause` squashed into a thrown `Error`, raised after `state disposal completed`.
- **Where it is not** — `Instance.dispose` guards its disposer walk and its runtime dispose, but the `ScopedCache.invalidate` between them was unguarded. That was hardened for consistency with its two neighbours (teardown must never reject), and it did **not** change the symptom — so the escape is above `dispose`, in the exit replay `withInstance` / `InstanceScope.with` performs. That is where the next pass should start.
- **Why it is `Now`** — It is not cosmetic: an exit code is what scripts and CI branch on, and every command in the CLI currently lies about whether it worked. It also silently degrades X3, which exists to be called from scripts.
- **Done when** — `nikcli stats` and `nikcli api path.get` exit 0 on success from a compiled binary; a command whose body genuinely throws still exits non-zero; and the case is pinned by a test so an interrupt during teardown can never again be reported as a command failure. The pre-existing `test/server/httpapi-top-level.test.ts` failure (a post-dispose `/path` returning 500 with the same `All fibers interrupted without error`) is the same defect seen from the test side, and should close with it.
- **Cause** — `withInstanceAsync` runs the body as a fiber on the instance's own `ManagedRuntime`, and `Instance.dispose` tears that runtime down. Disposing from _inside_ the body made the body interrupt itself at the last moment: the fiber's Exit became an interruption, `InstanceScope.with` faithfully replayed it in the caller, and `runPromise` squashed an interrupt-only `Cause` into `Error("All fibers interrupted without error")`. The bridge was not at fault — it was reporting exactly what happened.
- **Fix** — `bootstrap` disposes _after_ `withInstanceAsync` returns, re-entering the ALS scope `dispose` needs through `Instance.provide` without forking onto the runtime being disposed. Nothing is running on it when it goes away.
- **Verified on the compiled binary** — `nikcli api path.get`, `nikcli stats`, `nikcli api --list` and `nikcli debug paths` all exit **0**; `nikcli api sessionLst` and `nikcli api GET /nope` still exit **1**, so real failures still fail. `test/cli/bootstrap-exit.test.ts` pins both directions, and it was checked against the old shape: **5 of 5 fail without the fix, 5 of 5 pass with it.** `test/cli/` is 216/0.
- **Confirmed against the report that found it** — `nikcli analytics publish --month` did its work ("Published 101 rows.") and then exited 1. Measured on one machine, same command, both binaries: the installed `1.332.0` release exits **1** with `All fibers interrupted without error`; the rebuilt binary exits **0** and prints nothing extra. `analytics` goes through the same `bootstrap` wrapper, so the defect was never analytics-specific — it was every command that uses it.
- **Operational note for anyone replacing an installed binary to test this** — overwriting `~/.nikcli/bin/nikcli` in place makes macOS `SIGKILL` it (exit 137, no output): the kernel caches the code-signature validation per file, and rewriting a validated binary at the same inode invalidates it. `rm` first, then copy.
- **Two things tried and reverted, reported rather than left in** — Guarding `ScopedCache.invalidate` inside `dispose` (kept: teardown must never reject, and its two neighbours were already guarded, but it did not change the symptom) and detaching `runtime.dispose()` (reverted: it fixed nothing and quietly removed the guarantee that teardown finished).
- **Not in scope** — Catching the cause at the CLI's top-level handler, which would hide the symptom at the last possible boundary.

### Revision-bearing release identity (C3) — implemented 2026-09-09

- **Buys** — A release decision that can be wrong. Before this, every post-deploy signal available agreed with itself no matter what happened: `railway up --detach` exits 0 on an accepted upload, `GET /global/health` answers `{ healthy: true, version }`, and two uploads of `1.330.0` — or an older container that was never replaced — produce the identical response. Nothing in that chain could contradict a claim of success.
- **Evidence (source, 2026-09-09)** — The gap is the one [release-identity discovery](./PRODUCT_ROADMAP.md#prove-release-identity) named against source and stopped at. `Installation.VERSION` is the compile-time `NIKCLI_VERSION` define (`packages/util/src/version.ts`, `packages/nikcli/script/build.ts`), falling back to `"local"`; no SHA, digest, or build time was baked or served. `.github/workflows/ci-pipeline.yml` recorded the service name and captured no deployment identity. This is admitted rather than left as discovery because both halves of the promotion rule hold: the evidence is in the repository, and the gate below is runnable.
- **Association model, as implemented** — Expected identity is the commit that passed validate+publish (`GITHUB_SHA` in CI, git `HEAD` by hand). It is written into the upload context by `script/railway-deploy.sh` after the rsync loop — after, because `rsync --delete` would remove it — and `Dockerfile.serve` reads it into `NIKCLI_REVISION` for `build.ts`, which bakes it as a define beside `NIKCLI_VERSION`. Observed identity is whatever a later probe reads back from health. The chain is SHA → binary → image → service/environment → probe.
- **Why baked and not an environment variable** — A variable can be set on an image that does not contain that code, which reproduces the lie one level down. A define cannot: the string is inside the binary that was compiled from that commit.
- **Why `optionalKey`, not required** — A required `revision` would turn "the old container is still serving" into a decode failure in the probe, and that case is exactly what the field exists to report. Optional keeps it a readable observation: absent means the instance predates the field, which is a mismatch, not a crash. Additive, so it is a C1 drift item (`GlobalHealth` regenerated) rather than a contract bump.

### Declared failures on the typed channel (E8) — landed 2026-08-26

E5 closed the session HTTP boundary: declared errors are mapped from the typed channel and `catchDefect(asSessionError)` is gone. It recorded one remainder in its own text and did not claim it. **On the id.** This was drafted as `E6` while the near plan was empty, and the queue was refilled with its own `E6` (the pin bump) in parallel. - **Buys** — A declared domain error is a failure, not a defect, at the point it is raised. A handler that maps it needs one arm, not two, and a caller that forgets to map it gets a type error rather than a 500.
- **Evidence** — Two sites, both in the repository at the time of writing:

### Declare the part-id mismatch as a 400 (E9) — landed 2026-09-05

E8 closed two of the three `throw`s its sweep found inside an `Effect.gen` body and named the third in writing: "`httpapi/session.ts:908` throws a bare `Error` on a part-id mismatch; turning that into a declared 400 is a wire change (500 today) and needs its own item with a regenerated client, so it is not folded in here." E9 is that item. It is separate for the reason E8 gave — it changes the wire and the generated clients, which E8's acceptance gate explicitly did not cover.

- **Buys** — A caller that sends a part body naming a different part than the URL gets a 400 it can read and act on, instead of a 500 that looks like the server broke. The mismatch also stops being a defect at the point it is raised, so a handler that drops the mapping is a compile error rather than a silent 500.
- **Evidence** — `PATCH /session/:sessionID/message/:messageID/part/:partID` compared the decoded body's `id` / `messageID` / `sessionID` against the three path parameters and raised the disagreement with `throw new Error(...)` inside `Effect.gen`. The endpoint declared `error: [NotFound, Busy]` only, so nothing in the contract described the outcome. Unlike the pty case E8 fixed, there was no `catchDefect` arm compensating for it: `declaredErrors` is a single `Effect.catch(asSessionError)` since E5, and `asSessionError` ends in `Effect.die`. So the mismatch was a genuine 500 on the wire, not a 404 held up by a defect arm.
- **Implementation** — A `PartMismatch` response schema in the same `{ name, data }` shape as `NotFound` and `Busy`, annotated `httpApiStatus: 400` with identifier `SessionPartMismatchError`, added to the `partUpdate` endpoint's error list and to that endpoint only. A `PartMismatchError` tagged error class carries `sessionID` / `messageID` / `partID` / `message`, and the handler raises it with `Effect.fail`. The mapping is `asPartUpdateError`, a separate combinator (`partUpdateErrors`) rather than a new arm on `asSessionError`: widening `DeclaredError` would give every handler that pipes `declaredErrors` a failure type its own contract does not declare. The detail string is unchanged, so the message a caller reads is the one the `throw` produced — it is now in `data.message` with a 400 around it.
- **Depends on** — E5 (the typed boundary and the `Cause.hasDies` assertion style) and E8 (the rule that a declared error is a failure at the raise). Independent of E6; it uses no API newer than `beta.83`.
- **Done when** — Met. The `partUpdate` contract declares the 400 and no other endpoint does; the raise is `Effect.fail`, not `throw`; `bun run generate:httpapi-clients` output is committed with the slice and names `SessionPartMismatchError`; a route test pins the 400 status and body, and a service-level test asserts `Cause.hasDies === false` on the handler's failure so a re-introduced `throw` goes red.

**Not folded in: the zod parse above the check.** `MessageV2.Part.parse(payload)` on the line before can throw for a body the Effect payload schema accepted but zod rejects, and that is still a defect and still a 500. Three tests in an `invalidation` block pin that contract — entry and disposers and state cells survive, an explicit directory works unscoped, a missing scope throws — so the keyed runtime can swap the mechanism without changing the behaviour, and so nothing drifts back to dispose-as-invalidate.

  **Two of the three post-dispose consequences are fixed, and the tests are inverted rather than deleted** (2026-08-25). The objection that stopped this last time was that a `disposed` flag "changes the lifecycle contract for all 215 synchronous `Instance.*` reads while the migration that owns that contract is still open, and it would paper over the fact that three call sites are asking for the wrong verb". The second half is void — `Instance.invalidate` fixed those three call sites. The first half only ever applied to blinding the accessors, which is not what was needed:

  - A disposer registered after teardown was added to a set that had already been walked and would not be walked again, reached through a cache entry that had been deleted. It was dropped in silence. The context is marked disposed before the first disposer runs, so a late registration runs immediately instead — including one that arrives from inside another disposer during the walk, which is why the flag is set before it and not after.

  **What did follow through is the code path** (2026-08-25). `withInstanceAsync` had two implementations: an `init` caller went through `Instance.provide` and a hand-rolled fork onto `AppRuntime` that squashed the Cause, while everyone else went through `InstanceScope.with`.   - **`background/run.ts` served one project's runs to another.** `listCache` is a two-second cache over `BackgroundRunRepo.list(projectID())` — rows of _one project id_, held in a module-level `let`. `listForParent`, `listForJob`, `listForRelatedSession` and `countRunningForParent` all filter over it, so for two seconds after any project listed its background runs, every other project in the process got that project's rows; and a mutation in one project invalidated the cache of all of them. It is `Instance.state` now. Every caller already stood in an instance scope — each is preceded by a repo call keyed on `projectID()` — so keying it costs no new scope requirement.
  - **`browser-control.ts` pointed every workspace at the first one's daemon.** `cachedSocket` was one module-level promise resolved from `Instance.directory`. `config/tui.ts` twenty lines of code away already documents the right shape ("Keyed by directory: one process can drive several instances"); this one did not have it. Keyed by directory now, with `undefined` for the no-scope case.

    That case is the second half of the bug. Both shutdown callers — the TUI worker's `shutdown` RPC and `serve`'s signal handler — call `closeAll()` from outside any instance scope, where `Instance.directory` **throws** rather than answering `undefined`. The global cache is the only reason that ever worked: if a session had used browser-control, `closeAll` reused its socket; if not, the read threw, the caller's `.catch` logged a warning, and the daemon and its Chromium children were left for the ten-minute idle timer. Both call sites carried a comment asserting the opposite — `serve.ts` said the read "falls back to `findWorkspaceRoot()`", `worker.ts` said it "becomes undefined after dispose" — so the wrong model was written down twice and believed. `closeAll` now sweeps every socket the process resolved, which is strictly more than either comment described: a session may have reached a daemon for a worktree other than the directory the process was launched in.

  - **`brain`'s process-wide single-flight is left alone, and this is why.** `Brain.trigger` holds `pending` at module scope, so a second instance joins the first's review and receives _its_ result; `shouldTrigger` holds `lastSessionScanAt` the same way, so one instance's scan throttles every other for ten minutes. Both are real. Neither is an instance-scoping bug to fix here, because the surrounding design is deliberately machine-global: `Flock.acquire("brain")` and `readLastBrainAt()`'s lock file both live under `Global.Path.state`, so "when did brain last run" and "may brain run" are already one answer per machine — while brain's _output_ (`memory.instruction.md`, `.nikcli/habits.md`) is per instance directory. Keying `pending` would fix a third of an inconsistency and hide the rest. It is a brain-behaviour decision, not a cleanup.

  Verified by mutation, against the three tests in `test/background/instance-scoped-caches.test.ts`: putting the background cache back at module scope (1 red), keying every socket under one entry (2 red), and shutting down only the caller's own socket (1 red).

  **The test was red for the wrong reason twice before it measured anything.** A cross-project assertion needs two projects, and two temp directories are not two projects: every directory without VCS gets the project id `global`, so the first version watched project B legitimately read project A's row, and stayed red after the fix. `git init` was not enough either — the id comes from the root commit, and a repository without one is `global` again. Nor was `git init` plus an empty commit: two empty commits with the same author in the same second hash identically, so both directories got the same id and the test kept failing on a fix that worked. Only a commit with distinct content separates them. A red test is not evidence that it is testing the right thing.

  **What the remaining clause costs, measured.** `util/context.ts` has two production importers: `project/instance.ts` and `workspace/workspace-context.ts` — and the second is a separate AsyncLocalStorage for `workspaceID` that has nothing to do with instances. Retiring the first means the 187 synchronous ambient reads across 78 files have somewhere else to go. Classified by the frame they sit in: 105 are inside `async` functions, ~75 inside plain synchronous ones (`function memoryPath(): string { return path.join(Instance.directory, ...) }` and its kind), and 7 inside `Effect.gen`. Only the last group can become `yield*` for free. The synchronous ~75 each need their signature — and their callers' signatures — to become async or Effect, which is the async-ification cascade, not a migration. The sequencing that follows: the keyed `ManagedRuntime` can own bootstrap and disposal, and `Instance.provide` can become a thin test helper, while ALS still carries "which instance am I in" for the synchronous reads. `util/context.ts` reaching zero production importers is the _last_ step, not a precondition, and it is worth its own decision.

  **The 187 reads are threaded, and 22 are left standing on purpose** (2026-08-26). The classification above said ~75 of them sit in plain synchronous functions and would each drag their callers into an async cascade. That turned out to be the wrong unit of work: almost none of those functions needed to become async, because the instance did not have to be _fetched_ there — it had to be _passed_. Nine waves of threading later the grep for `Instance.directory|worktree|project` outside `instance-state.ts` reads **22 code sites in 11 files**, from 194.

  The lever each time was the same: give the entry interface a place to put the instance, then let the compiler find everyone underneath it.

  - **`init` now receives the context it is bootstrapping.** `Instance.provide`'s `init?: () => Promise<any>` became `init?: (instance: Context) => Promise<any>`, and `InstanceBootstrap` takes it. That one signature paid for `InstanceReload.watch`, `Routine.restoreSchedulers`, `SessionSyncBridge.init` and `SyncCliInit.initRemoteSyncFromEnv` at once — four startup paths that each re-read the scope they had just been started inside. `InstanceReload.reload` takes its directory too: the watcher fires on a debounce timer, where "which instance am I in" is whatever scope the watch was armed in.
  - **`SessionProcessor.CreateInput` carries the instance.** The processor's coalesced part-flush ran `SyncEvent.run(..., { projectID: Instance.project.id })` inside a `setTimeout` callback, one frame removed from the turn that scheduled it. `session/prompt.ts` and `session/compaction.ts` both had an `InstanceContext` in hand at the call site already.
  - **`FilePathFilters.relativePrefix` takes the root it is relative to.** It read `Instance.directory` to compute a prefix for paths coming out of an index that was rooted at a _specific_ directory — the two agree only as long as nobody searches from a second instance. `FFF`'s handle carries its `root` now, and `searchBackend` asks the index rather than the scope.
  - **Two module-level maps became `Instance.state`.** `config/tui.ts`'s reload override and `session/mode.ts`'s mode memo were both `Map<directory, …>` keyed by an ambient read — correct, but keyed by hand, and outliving the instances they described. `Instance.state` is the same keying and disposes with the instance.
  - **`workspace/connection.ts` was reading the wrong project, not just the wrong way.** `rememberWorkspaceEvent` ran inside a detached SSE reconnect loop and journaled under `Instance.project.id`; it takes the workspace's own `projectID` now, which is the value that is actually correct there.
  - **The chatbot chain was the longest thread**, and the only one where the ambient read was load-bearing: a bot's platform callbacks fire on the network, outside any scope, and `registerAiHandler` captured `Instance.directory` to re-enter. It takes the instance from `ensureAiBot` ← `chatBotStart` / `ChatbotWebhook.handle` / the CLI `bot start` command, and the webhook route reads the scope once at the raw-`Request` boundary where the router put it.

  **What is left, and why each one is the boundary rather than a remainder.** `project/instance.ts` (4) is the definition site; `effect/instance-state.ts` (3) is `ambient()` itself; `effect/instance-scope.ts` (4) and `effect/runtime.ts` (3) are the two Promise→Effect bridges that _build_ an `InstanceContext` to bind. `server/httpapi/event.ts`, `server/mobile/events.ts` are raw SSE entries; `server/httpapi/sync.ts` deliberately reads a _different_ directory's project; `file/fff.ts` and `background/run.ts` are each one funnel serving a whole module (`Instance.state`'s root, and `projectID()`); `browser-control.ts` (2) keys the daemon socket and is documented above; `sync/sync-event.ts` is one `projectID()` of the same kind. Threading the last two funnels would put a parameter on ~25 exported functions to remove one read each — the async cascade the earlier classification feared, in the one place it is real.

  Verified: `bun turbo typecheck --filter=nikcli-ai --concurrency=3` clean, `bun test test/{project,session,sync,workspace,loop,config,server,cli,file,chatbot}` 1197 pass / 0 fail. The compiler found what the reads had been hiding — `Workspace.remove` and `Workspace.restore` were listing sessions of the ambient project while holding the workspace's own `info.projectID`, and the three tool-layer test failures were all call sites that had an instance one line above.

  **The promise `Map` is now a `ScopedCache`** (2026-08-26). Lookup is `fromDirectory` → context. `init` is not part of lookup: the first caller that passed one used to bake it into the creation promise, so a concurrent waiter that did not ask for bootstrap still failed when that init exploded, and the instance was evicted as if creation had failed. Those two failures are different. A failed lookup expires immediately (`timeToLive` zero) so the next caller retries creation; a failed `init` clears `bootstrapped` and leaves the entry — the same path the retroactive-init tests already pinned, now whether the instance is one millisecond old or one hour. Two lifecycle tests are inverted rather than deleted: first-acquisition init failure no longer evicts, and a bystander that did not pass `init` is not failed by someone else's bootstrap. ALS and `Instance.provide` stay; `util/context.ts` still has its production importer. The owning scope is process-lifetime — `dispose` / `disposeAll` invalidate entries, they do not close the cache, because closing it would mark it Closed and every later `provide` would interrupt.

  **R1 closed** (2026-08-26). The cache already owned lookup; the runtime now owns Effect execution. Each instance carries a `ManagedRuntime` whose layer provides `InstanceRef`. `InstanceScope.with` forks onto that runtime instead of the process-wide `AppRuntime`, so fibers see the instance without an ALS round-trip. Accessors throw after `dispose()` — the third post-teardown consequence, inverted rather than deleted. `Instance.provide` is the promise-side entry (the scope bridge, session re-entry, tests); CLI bootstrap, hot reload, the TUI worker and the sync stats resolver go through `withInstanceAsync`. `util/context.ts` keeps `instance.ts` (definition site) and `workspace-context.ts` (a different ALS). The 165 `withCurrentInstance` sites in modules that hold no context stay: that is the Promise→Effect boundary, not a remainder.

### Output codecs on structured built-ins (T3) — landed 2026-08-24

- **Buys** — Code Mode and any machine consumer get a validated `value` from tools that already return JSON in `output`.
- **Evidence** — T2 landed the wrapper; built-ins are not required to use it ([v2/tools.md](./v2/tools.md)). No built-in in `src/tool/*.ts` declares an `output` codec. `browser-control` and `todo` already `JSON.stringify` structured results into the model-facing string.
- **Depends on** — nothing. Later because T2 called this additive; do not add a CI rule that every tool must have a codec.
- **Done when** — Tools that already emit JSON declare a codec and return `value`. Model-facing `output` stays a string. A malformed `value` fails that call only. Tools that emit prose are unchanged.
- **Met 2026-08-24.** `todowrite`, `todoread` and `browser_control` declare codecs; every other tool is untouched and still has no `value`. Model-facing `output` is byte-identical in all three — the tests assert the exact string, not a shape. Code Mode's rendered signature goes from `Promise<unknown>` to the real type.

  **`todo` is the clean case**: the codec is `Todo.InfoSchema`, which this repo owns, so it cannot drift from a payload produced elsewhere.

  **`browser_control` is the case the roadmap's wording did not anticipate**, and the difference is worth recording rather than glossing. A codec is declared per _tool_, but this tool is twenty-one actions with heterogeneous results, so "tools that emit prose are unchanged" cannot hold branch-by-branch: once the codec exists, the wrapper parses `value` on **every** call, and the eight prose branches had to gain one too. Their `output` strings are untouched — which is the part the model sees — but a machine consumer that used to get `"Clicked #go"` now gets `{ action: "click", name, selector }`. The codec is a union discriminated on `action`, so a consumer switches on the result instead of parsing English.

  **Payloads that cross the daemon socket are validated loosely on purpose.** `SessionInfo` and `JSONFrame` are produced by `@nikcli-ai/browser-control`, which ships separately from the tool, so their schemas are `z.looseObject`: the fields the tool documents are required, everything else passes through. Validating an externally-produced payload strictly is how an output codec turns into an outage — a new field on the daemon side would fail calls that would otherwise have worked. A test feeds the tool a session carrying an unknown field and asserts it survives; making the schema strict turns that test red.

  **Two regressions ruled out with evidence rather than reasoning.** (1) The codec never reaches the provider: `session/tools.ts` builds the AI SDK tool from `description` + `inputSchema` only, so the tool-array bytes that form the prompt-cache prefix are unchanged. (2) The codec costs nothing in the model-facing Code Mode catalog: `CATALOG_BUDGET` is `0` and neither tool is pinned, so their signatures were never inline — measured at 0 chars added. At the library default budget the same codecs would have added ~76%, which is the number to remember if that budget is ever raised.

  **Verified by mutation.** Three mutations of `browser-control.ts` are each caught: dropping one branch's `value`, making the session payload strict instead of loose, and mislabelling a snapshot format. All 21 actions (23 return branches) are exercised against a mocked daemon.

### `normalizeMessages` on the LLM turn path (P3) — closed on the measurement 2026-08-24

- **Buys** — Provider turns allocate fewer copies of the message list. Not an HTTP win.
- **Evidence** — `provider/transform.ts` still has `// TODO: fix this stupid inefficient dogshit function` on `normalizeMessages` (multiple `msgs.map` passes, per-part allocations). June 2026 resource review flagged it; the function is still there. Independent of the HttpApi module.
- **Depends on** — nothing. Later because it is on the LLM turn, not the contract.
- **Done when** — One documented pass (or a measured reason to keep several). A bench or a comment with a counter replaces the TODO. Behavior of sanitization / tool-result shaping is unchanged.
- **Met by the second branch: a measured reason to keep several.** On a 601-message / 2.4MB history — about the largest a 200k-token context holds — `ProviderTransform.message` costs ~2.1ms. Of that, ~72% is `sanitizeSurrogates` scanning characters, which is per-byte work that no restructuring of the passes removes. One structural walk over every message and part costs **0.012ms**, so the passes the TODO complained about are together ~0.5ms of allocation, and their irreducible floor is under 1% of the function. `JSON.stringify` of the same payload — unavoidable, it is the request body — costs **0.8x the entire function**. The transform is linear at ~3.3µs/message and the provider branch barely registers (anthropic vs openai differ by ~6%).

  So a perfect rewrite saves under a millisecond, on a request that then waits seconds for a model, in exchange for merging eight provider-specific rules — two of which reorder or split messages and one of which returns early — into a single walk. That is a bad trade, and P3 is closed the same way P2.2 was: by answering the question rather than building the thing.

  **The characterization is the deliverable that outlasts the decision.** `test/provider/transform-normalize.test.ts` pins the passes that carried no coverage at all: surrogate sanitization across every role and both tool-result output shapes, the Anthropic and Bedrock empty-content filters (including blank reasoning kept alive by a signature), Claude and Mistral id scrubbing on both sides of a call, the Anthropic tool-call reorder, the Mistral tool→user repair, the DeepSeek reasoning injector, and the fact that the Mistral branch returns early so later passes never run. Four mutations of `transform.ts` were each caught. The TODO is replaced by the numbers above; `test/provider/hot-paths.benchmark.test.ts` records transform / scan / serialize together so the ratio that decided this stays visible.

  **One finding worth carrying forward.** The function mutates the caller's messages in place — parts included. `unsupportedParts` copies user messages first, but shallowly, reusing the same part objects, so sanitization is written through to the caller's array for every role. Returning a clean copy would arguably be more correct and would still be a behaviour change. Anyone reopening this must decide that deliberately; the test pins the aliasing precisely.

  **The only lever that would matter** is not re-sanitizing history that previous turns already sanitized — the scan is the cost, and it is repeated over the whole history every turn. That needs provenance on the message and is a correctness change, not a refactor. Not proposed here.

## Respect non-goals

Recorded so they are not re-proposed:

- **Nested `/project/:projectID/session/...` URLs.** Directory scoping is middleware plus storage keys. See [Preserve boundaries](./README.md#preserve-boundaries).
- **Automatic hard-crash session recovery.** S2 covers the graceful case on purpose. Anything more needs provider-dispatch ambiguity, tool idempotency, and retry budgets designed together.
- **Clustered session ownership.** Execution stays process-local until there is an explicit placement and fencing protocol.
- **A shared PubSub for the event feed.** Considered and rejected in E1's spec; the win it offers is queue-slot references, not frame copies.
- **Rebuilding TUI features opencode already has.** The jlongster TUI set is already present; "moving sessions" upstream is nikcli's existing warp.
- **Rewriting `SessionProcessor` or `toModelMessages` to consume entries.** [v2/session.md](./v2/session.md) leaves `MessageV2` as the LLM layer on purpose.
- **Pinning `SessionEntry.Entry` on the HTTP contract.** The variant set grows without a contract bump; that is why those three SessionV2 types stay `Unknown`. Re-checked 2026-08-30 against `Schema.TaggedUnion.matchOrElse` (H10): the matcher is consume-time on a closed union and does not un-force the payloads. A half-open `Union(known, catch-all)` accepts a new variant but also accepts a malformed known member as the fallback, which is worse than `Unknown`. No follow-up item.
- **Promoting raw streaming / prompt / SSE / websocket routes into encoded Effect handlers.** `POST /session/:id/message` and `prompt_async` are raw because they open a chunked 200 or return 204 before the loop finishes (`httpapi/prompt.ts`). SSE and upgrades stay ahead of the router. H7 does not promote mobile SSE/upload/upgrade.
- **Desktop as a second TUI renderer.** [tui-package.md](./tui-package.md) §6: `packages/desktop` is a Tauri webview; the TUI renders through `@opentui/solid`. The packaging check is `nikcli-tui`, and it already exists.
- **Deleting leftover `storage/*.json` trees.** They stay on disk for downgrade. Runtime does not read them.
- **Mandatory tool output codecs.** T2 is opt-in. T3 adds codecs only where the tool already returns structured JSON.
- **Raising SQLite `mmap_size`.** `mmap_size = 0` is a durability choice; WAL checkpoint already runs. Not a perf item without a measured crash/WAL story.
- **`idleTimeout` other than `0` without an SSE/websocket-aware policy.** `server.ts` sets `idleTimeout: 0` on both `Bun.serve` and `listenEffect`. Default Bun idle would kill EventFeed. EventFeed already evicts stalled readers.
- **Per-request HttpApi layer rebuild.** `sharedMemoMap` + `toWebHandler` already cache the handler.
- **Adopting opencode v2's package split** (`schema` → `core` → `protocol` → `server` → `client`). It is a second HttpApi rewrite for a boundary nikcli already enforces differently: one core package plus an extracted `packages/tui` that has no `nikcli-ai` dependency. Surveyed 2026-09-09 and rejected.
- **Porting `packages/core/src/session/inbox.ts`.** Its ideas that matter here already exist — `noReply: true` on `SessionPrompt.admit` is their `resume: false`, and `SessionPending.Delivery` is their steer-versus-queue. What is genuinely theirs is compaction and move as inbox control items forming a delivery barrier, and that needs an observed "a steer jumped a compaction" case in this repository before it is an item.
- **Their write-ahead execution claim and crash-resume.** Same reason automatic hard-crash recovery is already a non-goal above, plus upstream documents it as not exactly-once.
- **Electron desktop, `plugin-browser` CDP, and the always-on background service with a password.** `packages/desktop` is a Tauri webview here, and `serve` / `attach` already cover the daemon shape.
- **`effect/unstable/cli` replacing yargs, a VS Code extension, `packages/session-ui`, `packages/merman`, `packages/latex`.** ACP covers the editor case; `packages/tui-math` covers math; the rest wait for someone to ask.

- **Full `fromZod` rewrite of `config.ts`.** The `nikcli.json` document is zod; `fromZod` is the correct adapter. New HTTP/domain shapes are Effect-first; `zodObject` is for leftover zod callers.

### 2026-08-24 (later) — P2.1 (session list filters, ordering, and limit in SQL)

**`GET /session` stops reading the whole project to return twenty rows.** The route materialized every session of the project through `Array.fromAsync` — one `JSON.parse` of the `data` blob per stored row — then filtered directory / roots / start / search in JS, sorted, and sliced.

- **Two derived columns, because the JS predicates are not expressible in SQLite without changing their meaning.** `session_info.directory_key` stores `Filesystem.comparisonKey(directory)`: on Windows that is a JS `toLowerCase` of a resolved, forward-slashed path, so `WHERE directory = ?` would be a different predicate and `WHERE lower(directory) = ?` an ASCII-only approximation of it. `session_info.title_lower` stores `title.toLowerCase()`, because SQLite's `lower()` is ASCII-only and would silently drop non-ASCII search matches the JS filter accepts. `20260824000000_session_directory_key` adds both and backfills them with the same functions the write path uses, so runtime and backfill agree by construction. Neither column is read back into `Session.Info` or put on the wire.
- **Search uses `instr()`, not `LIKE`.** `LIKE` reads `%` and `_` in a user's search term as wildcards; `String.includes` does not. A route test pins that searching for `%` returns nothing.
- **`SessionRepo.query` + `Session.Service.query`.** The repository takes a comparison key; the service takes a directory path and converts it, so no caller can pass a raw path where a key is expected. `list()` stays — it is the "walk every session of this project" iterator other callers still want. Ordering is `updated_at DESC, created_at ASC`; the tiebreaker reproduces the old behavior, whose stable `Array.prototype.sort` over a created-ascending input kept created order on equal `updatedAt`.

### 2026-08-24 (last) — H8.1: authentication on the HttpApi contract

**Security is now declared where the endpoint is declared.** `ServerRouter` and the bridge authenticated imperatively, so OpenAPI could not name a scheme and a new encoded group was protected only by being reached through the right dispatcher.

- **`httpapi/security.ts`** declares `bearerAuth` / `auth_token` / `basicAuth` and implements all three with one delegate to `Auth.authenticate`, reading the raw `Request` rather than the decoded credential. It has to: the server accepts combinations no single scheme describes — a Tailscale identity header, or open mode with no credential at all. `Auth.authenticate` remains the only implementation of the acceptance order.
- **The 401 is returned as a `Response`, not raised as a declared error.** Failing with an error schema would have JSON-encoded the body and dropped the `WWW-Authenticate` challenge. Returning it verbatim keeps the wire identical _and_ keeps the middleware's error union empty — which is why `bun run generate:httpapi-clients` produced **zero drift**.
- **Classification, which is the actual work.** 328 operations secured, 10 open. The 10 are exactly the paths reachable without credentials, from two different sources: `Auth.isPublicPath` (health probe, browser sign-in, account creation) and `PublicRoutes.publicRequest`, which answers the share routes _ahead_ of authentication entirely. `global` and `users` mix public and protected, so those two mark the protected endpoint at its definition site — a group-level sweep would have made the liveness probe advertise a scheme it does not enforce.
- **Where the middleware has to be provided, and why it is not obvious.** `HttpApiBuilder.group` captures `Effect.context()` when the group layer is built, and `applyMiddleware` resolves the middleware service out of _that_ captured context. Providing it only to `ApiLive` compiles and then fails every protected request at runtime with `Service not found: nikcli/HttpApiAuth`. It therefore goes to the merged handler layers in `public.ts`, and separately to `mobile-handlers.ts`, `sync.ts`, `global.ts` and `contract-extra.ts`, which build their groups against their own `Api`.

**Two regressions found and closed before they shipped:**

- **The imperative checks had to stay.** Removing them looked right — the middleware covers the encoded routes — but the middleware can only guard paths the contract describes. An unmatched path has no endpoint, so a password-protected server would have started answering 404 to unauthenticated callers where it previously answered 401. Both checks are back, and they now `Auth.remember` so the middleware does not authenticate a second time.
- **`WorkspaceServer` would have started rejecting everything.** It serves a workspace sandbox on its own `Bun.serve`, performs no authentication, and passes `upstreamAuthVerified: true`. With the middleware in place and nothing remembered, it would have authenticated those requests and failed every one on a server with `NIKCLI_SERVER_PASSWORD` set. `Auth.markUpstreamVerified` records that the question was already settled — a different statement from `remember`, which records _who_ the caller is. `test/server/httpapi-bridge-401.test.ts` pins it, and that assertion was confirmed to fail without the marker.

**Verified.** `bun test` full suite 4018 pass / 2 fail. Neither failure is this change: `httpapi-file.test.ts`'s ripgrep search is the documented load flake and passes alone, and `test/mcp/streamable-http-transport.test.ts`'s SSE-reconnect case fails identically on pristine `3c4819927f` in a clean worktree — it is a pre-existing failure, unrelated to the server auth path. `bun run check:routes` ok — 338 contracts, 315 handlers, 23 raw. `bun run generate:httpapi-clients` regenerated with no diff. `bun run typecheck` clean on `packages/nikcli`.

**One cast worth not having.** The middleware layer was first written as `Layer.succeed(Middleware, { … } as never`). A cast to `never` silences every check, so it came out before the commit, and the typecheck confirms it was never needed: `Layer.succeed` types its value from the service key, which instantiates `authorize`'s generic at `HttpServerResponse` and collapses its two return branches. ### 2026-09-09 (final) — H11: the endpoint that could not await its own teardown

**The decision R3 deferred, made on evidence.** `POST /instance/dispose` answered 500 while its work had actually happened, and the standing `httpapi-top-level.test.ts` failure — red since before this work — was that same defect seen from the test side. ### 2026-09-10 (last) — D3: the suite is green, and both "known" failures were real bugs

**Two failures had been described rather than diagnosed.** One was "the standing `signature.test.ts` schema-rendering one that predates all of this", the other "the documented `missing OpenAPI component: Event` install artifact". Both descriptions were wrong, and both took minutes to settle once anyone asked what the code actually did.

**The first is E6 fallout with a real user-facing edge.** CodeMode shows the model a TypeScript signature per tool. `Schema.Number` cannot round-trip `NaN` or the infinities through JSON, so its JSON Schema carries them as string alternatives, and `tool-schema.ts` has always collapsed that back to `number` — otherwise every numeric parameter in every tool signature would read `number | "Infinity" | "-Infinity" | "NaN"`. Effect used to emit one alternative per sentinel; from `4.0.0-rc.112` it emits one alternative holding all three. The guard checked `enum.length === 1`. So the day the pin moved, the noise came back into every signature the model reads, and the test that noticed it was filed as "standing".

**The second was a rename nobody had looked up.** `BusEvent.schemas()` annotates the union `identifier: "Event"`; Effect names a component after the identifier and appends `Encoded` when the encoded side differs from the type side, so the component is `EventEncoded`. The generated SDK still exports `Event`, because the codegen builds that union itself. The test was asserting an Effect naming detail, not the thing the SDK needs.

**Neither test was loosened to match current output.** The first restored behaviour the repository had deliberately implemented and silently lost; the second widened an assertion that was always more specific than its own stated intent, with the reason written into the file.

**The suite is green end to end for the first time in this sequence.** `bun run test:ci` — 16 of 16 batches, 392 files, **4157 pass, 0 fail**.
