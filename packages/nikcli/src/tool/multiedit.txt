Apply multiple find-and-replace edits to a single file in one operation. Built on top of Edit. Prefer this over multiple Edit calls when edits target the same file.

Each edit has `oldString`, `newString`, optional `replaceAll` (default false).

Rules:
- Provide absolute file paths.
- Edits are applied in sequence; each operates on the previous result.
- Edits are atomic — if any edit fails, none are applied.
- `oldString` must match exactly (including whitespace and indentation).
- Plan to avoid conflicts between sequential edits.

To create a new file: empty `oldString` plus the file contents as `newString`. To rename a token across the file, use `replaceAll: true`.

No TODO/FIXME placeholders. No emojis unless the user asks. Don't touch git hooks unless asked.
