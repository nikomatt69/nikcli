Control the host computer: take screenshots and dispatch mouse and keyboard input. Use this to interact with GUI applications, navigate web browsers, fill forms, and perform any task that requires direct desktop control.

Coordinates are in the logical viewport declared by the host. Every `screenshot` response reports the exact `display_width_px × display_height_px` currently in effect. Always take a screenshot first to orient yourself, then reason about coordinates in that space. The host scales coordinates to the real display automatically.

Prefer small, verifiable steps. After any action that changes screen state (click, type, scroll), take another screenshot to confirm before continuing.

Supported actions:
- `screenshot` — capture the current display. Returns a PNG attachment and the declared viewport size.
- `cursor_position` — report current [x, y] mouse position.
- `mouse_move` — move cursor to `coordinate` without clicking.
- `left_click` / `right_click` / `middle_click` / `double_click` / `triple_click` — click at `coordinate`.
- `left_mouse_down` / `left_mouse_up` — press or release the left button without moving. Use for manual drag sequences.
- `left_click_drag` — press at `start_coordinate`, drag to `coordinate`, release.
- `type` — type the literal string in `text` as keystrokes.
- `key` — dispatch a key combination in `text` (xdotool-style: `"ctrl+a"`, `"Return"`, `"Escape"`, `"cmd+shift+t"`, `"Page_Down"`).
- `hold_key` — hold the key spec in `text` for `duration` seconds.
- `scroll` — scroll at `coordinate` in `scroll_direction` by `scroll_amount` clicks.
- `wait` — sleep `duration` seconds. Useful for animations, page loads.

Safety notes:
- Never type passwords or secrets unless explicitly instructed by the user.
- Coordinates outside the declared viewport will be rejected.
- Rate-limited to 20 actions per second.
- The host honours user-configured forbidden regions — actions inside them fail.
