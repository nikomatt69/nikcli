Render rich, visually impressive terminal visualizations using SolidJS components with OpenTUI.

This tool creates REAL interactive visualizations in the TUI dialog panel, not just ASCII placeholders. Use this tool when users want to see data visually.

# Core Philosophy

**Every visualization should be a work of art.** Just as a web developer would create beautiful CSS layouts, you must craft stunning terminal interfaces using SolidJS and OpenTUI's low-level renderers. The visualizations should feel alive, responsive, and delightful - not like crude ASCII art.

# Component Types

## 1. BAR_CHART - ASCII/Unicode Bar Charts

```typescript
{
  type: "bar_chart",
  title?: "Revenue by Quarter",           // Optional section title
  items: [
    { label: "Q1 2024", value: 125000, unit: "$" },
    { label: "Q2 2024", value: 89000, unit: "$" },
    { label: "Q3 2024", value: 156000, unit: "$" },
    { label: "Q4 2024", value: 203000, unit: "$" },
  ],
  barWidth: 40,      // Character width (10-60, default 40)
  maxValue?: 250000  // Override auto-calculated max
}
```

**Best Practices:**
- Use short labels (under 15 chars) for clean rendering
- Add units ($, %, ms, req/s) for clarity
- Sort by value descending for best visual impact
- Consider logarithmic scales for vastly different values

## 2. TABLE - Data Grids

```typescript
{
  type: "table",
  title?: "Server Performance",
  headers: ["Server", "CPU %", "Memory GB", "Status"],
  rows: [
    ["web-01", "45%", "8.2 GB", "Healthy"],
    ["web-02", "67%", "12.1 GB", "Warning"],
    ["web-03", "12%", "4.0 GB", "Healthy"],
    ["db-primary", "89%", "31.8 GB", "Critical"],
  ]
}
```

**Best Practices:**
- Keep headers short (under 20 chars)
- Align numeric columns right, text left
- Use status column with color coding
- Limit to 6-8 columns for readability
- Truncate long cell content with ellipsis

## 3. KEY_VALUE - Label-Value Pairs

```typescript
{
  type: "key_value",
  title?: "System Status",
  items: [
    { key: "CPU Usage", value: "45%", status: "success" },
    { key: "Memory", value: "12.4/16 GB", status: "warning" },
    { key: "Disk", value: "456/512 GB", status: "warning" },
    { key: "Network", value: "1.2 Gbps", status: "info" },
    { key: "Uptime", value: "14 days", status: "success" },
    { key: "Errors", value: "0", status: "success" },
  ]
}
```

**Status Colors:**
- `success` → green (✅ all good)
- `warning` → yellow (⚠️ attention needed)
- `error` → red (❌ critical issue)
- `info` → blue (ℹ️ informational)
- `default` → theme text color

## 4. PROGRESS_BARS - Fill Indicators

```typescript
{
  type: "progress_bars",
  title?: "Build Progress",
  barWidth: 35,
  items: [
    { label: "Compilation", value: 85, max: 100 },
    { label: "Tests", value: 42, max: 150, unit: "/150" },
    { label: "Linting", value: 100, max: 100 },
    { label: "Bundle", value: 67, max: 100 },
  ]
}
```

**Color Logic:**
- < 70% fill → success (green)
- 70-90% fill → warning (yellow)
- > 90% fill → error (red)

## 5. TEXT - Styled Text Blocks

```typescript
{
  type: "text",
  title?: "Deployment Summary",
  content: `Successfully deployed to production!
  
  Changes:
  - Fixed authentication bug
  - Added dark mode toggle
  - Improved performance by 23%
  
  Deployed by: deploy-bot
  Commit: abc1234`,
  style: "code" | "success" | "warning" | "error" | "info" | "muted"
}
```

**Style Guide:**
- `code` → Monospace block with syntax highlighting
- `success` → Green tinted text (for confirmations)
- `warning` → Yellow tinted text (cautions)
- `error` → Red tinted text (failures)
- `info` → Blue tinted text (information)
- `muted` → Dimmed text (secondary info)
- Default → Normal theme text

## 6. TIMELINE - Event Sequences

```typescript
{
  type: "timeline",
  title?: "Pipeline Execution",
  events: [
    { 
      time: "10:23:45",
      label: "Build Started", 
      status: "done" | "active" | "pending" | "error",
      detail: "Compiling TypeScript sources..."
    },
    { 
      time: "10:24:12",
      label: "Running Tests", 
      status: "active",
      detail: "42/150 tests passed"
    },
    { 
      time: "—",
      label: "Deploy", 
      status: "pending",
      detail: "Waiting for tests to complete"
    },
  ]
}
```

**Status Icons:**
- `done` → ✓ (completed successfully)
- `active` → ● (currently running)
- `pending` → ○ (waiting)
- `error` → ✗ (failed)

# Advanced Visualization Patterns

## Dashboard Layout (Multiple Components)

When combining 2-8 components, the dialog shows tabs for navigation:

```typescript
{
  title: "Analytics Dashboard",
  components: [
    { type: "bar_chart", title: "Traffic", items: [...] },
    { type: "table", title: "Top Pages", ... },
    { type: "key_value", title: "Summary", ... },
    { type: "progress_bars", title: "Resources", ... },
  ]
}
```

**Tips:**
- Group related visualizations under a cohesive theme
- Use short titles (under 20 chars) for tab labels
- Tab order should follow logical flow
- Maximum 8 components per dashboard

## Data Transformation

Transform raw data into visualization-ready formats:

```typescript
// Sort by value descending
items.sort((a, b) => b.value - a.value)

// Calculate percentages
const total = items.reduce((sum, item) => sum + item.value, 0)
const percentages = items.map(item => ({
  ...item,
  pct: (item.value / total * 100).toFixed(1) + "%"
}))

// Group and aggregate
const grouped = data.reduce((acc, item) => {
  const key = item.category
  acc[key] = acc[key] || { count: 0, total: 0 }
  acc[key].count++
  acc[key].total += item.value
  return acc
}, {})
```

## Color Theming

Leverage theme colors for consistency:

```typescript
const colors = {
  primary: theme.primary,      // Main accent
  success: theme.success,      // Positive states
  warning: theme.warning,       // Caution states  
  error: theme.error,          // Negative states
  info: theme.primary,          // Informational
  muted: theme.textMuted,       // Secondary text
  border: theme.borderSubtle,  // Subtle borders
  background: theme.backgroundPanel,
}
```

# When to Use Each Component

| Data Type | Best Component | Example |
|-----------|---------------|---------|
| Metrics, benchmarks | `bar_chart` | Response times, CPU usage |
| Rankings, comparisons | `table` | Top 10 products, leaderboard |
| Status, config | `key_value` | System info, settings |
| Progress, completion | `progress_bars` | Build steps, quotas |
| Code, logs | `text` | Stack traces, output |
| Processes, flows | `timeline` | Deploy steps, pipelines |

# Animation Guidelines

Use animation sparingly for emphasis:

- **Spinners** → Long-running operations (builds, deploys)
- **Live updates** → Real-time metrics (CPU, memory)
- **Transitions** → Tab changes, panel switches

Avoid animation for:
- Static data that doesn't change
- Quick, repeated updates
- Users who disabled animations

# Accessibility

- Ensure sufficient contrast between text and background
- Don't rely on color alone (add labels/icons)
- Consider terminal color schemes (light/dark)
- Test in narrow terminals (80 columns minimum)

# Error States

When data is unavailable or invalid:

```typescript
{
  type: "text",
  title: "Error Loading Data",
  content: "Unable to fetch metrics. Please check your connection.",
  style: "error"
}
```

Or for partial data:

```typescript
{
  type: "key_value",
  title: "Partial Data",
  items: [
    { key: "Status", value: "Limited data", status: "warning" },
    { key: "Records", value: "45/1000", status: "info" },
    { key: "Last Update", value: "2 hours ago", status: "muted" },
  ]
}
```

# Performance Tips

- Limit table rows to 50-100 for smooth scrolling
- Use pagination for large datasets
- Cache computed values with `createMemo()`
- Batch DOM updates with `batch()`

# Final Checklist

Before rendering a visualization, verify:
- [ ] Title is short and descriptive
- [ ] Labels are under 20 characters
- [ ] Data is sorted logically
- [ ] Status colors are appropriate
- [ ] Units are included where needed
- [ ] Multiple components have clear tabs
- [ ] Error states are handled
- [ ] Content fits in terminal width
