Read the contents of a file or directory. Supports text files, images, and PDFs. Images and PDFs are presented directly to the model.

Each text line is prefixed by its 1-based line number as `<line>: <content>`. The prefix is for reference and is NOT part of the file content — do not copy it into Edit `oldString`/`newString`. Directory entries are returned one per line.

Usage:
- The filePath parameter should be an absolute path
- By default, this tool returns up to 2000 lines from the start of the file
- The offset parameter is the line number to start from (1-based)
- To read later sections, call this tool again with a larger offset
- Use the grep tool to find specific content in large files or files with long lines
- Directory entries use the same offset/limit pagination and append `/` to directories
- If you are unsure of the correct file path, use the glob tool to look up filenames by glob pattern
- Any lines longer than 2000 characters will be truncated
- Call this tool in parallel when you know there are multiple files you want to read
- Prefer one larger read over many small slices; if you need more context, read a larger window
- If you read a file that exists but has empty contents you will receive a system reminder warning in place of file contents.
- Images and PDFs larger than 20 MiB are rejected before ingestion.

If the path does not exist, the tool errors with `File not found: <path>` and may suggest up to three similarly-named siblings from the parent directory.
