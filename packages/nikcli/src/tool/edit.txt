Exact string replacements in files.

Rules:
- Must use Read at least once in the conversation before editing — the tool errors otherwise.
- Preserve exact indentation. Never include line number prefixes in `oldString`/`newString`.
- Prefer editing existing files; only Write for genuinely new files.
- `oldString` not found → fails with "oldString not found in content".
- `oldString` matches multiple times → either include more surrounding context or set `replaceAll: true`.
- Use `replaceAll: true` for renames and broad substitutions.

No emojis unless the user asks. No skipping git hooks unless asked.
