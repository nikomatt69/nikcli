Create and control real native Liquid Glass interfaces for decisions, live work, and verified outcomes. Choose from task context rather than using a fixed template, and skip routine edits, searches, commands, and status already clear in the terminal.

Choose the least disruptive surface:
- `dialog` for required input, permissions, or consequential review
- `popover` for non-blocking progress or activity
- `menu` for compact action and recovery choices
- `notification` for a brief outcome already verified

Follow the lifecycle:
1. `open` one surface with a stable `surfaceID`.
2. `wait` for `control-changed`, `control-activated`, or `surface-closed` events.
3. Validate returned values and handle the action immediately.
4. `update` the same surface as state changes, or `close` it when done.
5. Use `list` to inspect active surfaces before recovering or opening another.

Updates patch supplied fields onto the active surface and preserve omitted fields. Reuse one dialog for wizard steps and one popover for related progress instead of stacking surfaces.

Compose no more than 20 controls:
- `text-input`, `select`, and `checkbox` for necessary input or safeguards
- `progress` with a measured `value` from 0 to 1, or `indeterminate: true` when no fraction exists
- `metric` for a verified value with optional detail, trend, and semantic tone
- `section` and `separator` for meaningful groups
- `button` and `link` only for actions you can handle directly

Use `layout: "dashboard"` on a large dialog for an operational overview. Lead with a few verified metrics, group supporting facts with sections, and keep decisions near the controls they affect; do not turn every progress panel into a dashboard.

For reviews, state the checked facts and consequences, request only missing input, and make cancel behavior explicit. For progress, keep the surface dismissible and non-blocking, update factual details in place, and offer recovery only after a real failure.

Never invent status, percentages, elapsed time, IDs, health, or outcomes. Source them from current command, monitor, process, delegation, session, migration, or health-check results.

Never expose secrets, credentials, tokens, private source, or unredacted logs. Mark only truly destructive buttons as destructive, never perform a consequential action after dismissal or cancellation, and notify completion only after authoritative verification.
