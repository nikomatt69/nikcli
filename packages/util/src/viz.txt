Render a rich terminal dashboard in the TUI dialog panel (structured UI, not prose ASCII).

Use for: status boards, KPIs, charts, timelines, trees, code review digests, fleet maps, incident summaries.
Do NOT draw ASCII box diagrams in chat — use components below.

Principles: pick the component that answers the question; group with `section`/`grid`; color by semantics (`success`/`warning`/`error`/`info`); short labels; never invent data.

Components:
- text, markdown, code, diff, alert
- table, key_value, tree
- stat, stat_grid
- bar_chart, line_chart, histogram, heatmap, gauge, progress_bars
- timeline, status_grid
- card, list, accordion, compare, sparkline_row
- section, grid (layout)

Hints:
- Health/deploy → status_grid / timeline / stat_grid
- Numbers that matter → stat / stat_grid with unit/delta/trend
- Hierarchy → tree; pipelines → timeline; matrices → heatmap/compare
- Prefer `grid` + `children` over deeply nested arrays
- Keep charts modest (≤6 series, ≤30 timeline events, ≤4 nest levels)

Pass a single dashboard JSON matching the tool schema. Prefer fewer cohesive components over many scattered ones.
