How to read this

Two documents own the plan. They do not mix.

PRODUCT_ROADMAP.md — Proposed

User outcomes and evidence gates. Discovery may audit and measure. It cannot admit code. Shipping without measuring the stated outcome does not complete an item.

ROADMAP.md — Current

Ordered engineering work. An item exists only if evidence is in the repository today: file, fact, runnable acceptance gate. Product priorities may promote an item; they do not weaken its gate.

specs/ + specs/v2/

Contracts, not a backlog. When a document and the code disagree, the code wins. Actionable work goes in ROADMAP, not in a contract file.

Horizons, not dates

Now = baseline + proven blocker. Next = discovery while Now is measured. Later = hypothesis, not a release promise.

Do not start a second HttpApi rewrite. Hono and NIKCLI_EXPERIMENTAL_HTTPAPI are gone. Deepen the module that every adapter already crosses.

What already shipped (do not re-plan)

  • One database. nikcli.db, journaled TypeScript migrations, WAL, foreign_keys=ON, mmap_size=0. JSON storage retired; leftover trees stay on disk for downgrade only.
  • One HTTP surface. Effect HttpApi on Bun.serve. Clients generated from the contract. Auth declared with HttpApiMiddleware (328 secured, 10 open).
  • One event log. sync_event for session and workspace. Public filter withholds six internal types; withheld means absent, not typed.
  • SessionV2 write path. Entries persist first; v1 is toV1*. Import / teleport / run write through SessionV2. Pending input is durable. Graceful restart continues turns. Hard crash is out of scope.
  • TUI extracted. packages/tui has no @/ import and no nikcli dependency. Second consumer: standalone attach host.
  • Instance runtime. Per-directory ScopedCache + ManagedRuntime. ALS remains for 22 named boundary reads. Unconditional bootstrap was measured and rejected (test-suite cost, not RSS).
  • Effect pin. Workspace on 4.0.0-rc.112. Working rule points at shipped docs, not an author-machine clone.
  • Release integrity (C1). Generated drift, format, lint, patched-deps, Railway credential, Docker versions — all blocking. Direct publish cannot skip validation.

Platform surfaces (product, not a second HTTP)

TUI

OpenTUI + Solid. Default nikcli. Worker talks to local server over RPC + SSE. Can attach remotely.

Headless server

HttpApi + SSE + WebSocket. OpenAPI. Generated SDK at @nikcli-ai/sdk/httpapi.

Desktop

Tauri webview — not a second TUI renderer. Packaging check is nikcli-tui.

Mobile

Expo app, QR pairing, nikcli:// deep links, bearer tokens from pair ceremony.

Identity

Cloudflare Worker at auth.nikcli.store. OAuth 2.1 + PKCE S256, device code, email-code. Account creation cannot be skipped.

Bots / ACP / MCP

Slack, Discord, Teams, Google Chat, GitHub, Linear. ACP for editors. MCP client+server.

Non-goals — do not re-propose

  • Nested /project/:id/session/... URLs. Directory scoping is middleware + storage keys.
  • Automatic hard-crash session recovery. S2 is graceful on purpose.
  • Clustered session ownership. Execution stays process-local until placement + fencing exist together.
  • Shared PubSub for the event feed. Rejected in E1.
  • Rebuilding TUI features OpenCode already has. Warp is nikcli’s “moving sessions”.
  • Rewriting SessionProcessor / toModelMessages to consume entries. MessageV2 stays the LLM layer.
  • Pinning SessionEntry.Entry on the HTTP contract. H10 re-checked; Unknown stays.
  • Promoting raw SSE / prompt / websocket into encoded Effect handlers.
  • Desktop as a second TUI renderer.
  • Deleting leftover storage/*.json trees.
  • Mandatory tool output codecs. T2 is opt-in.
  • Raising SQLite mmap_size.
  • idleTimeout other than 0 without an SSE-aware policy.
  • Per-request HttpApi layer rebuild (already memoized).
  • Full fromZod rewrite of config.ts.
  • Unconditional instance bootstrap (measured: test-suite cost, not RSS).
  • Threading the last 22 ALS reads (named boundaries; cascade is a rewrite).
  • Keying Brain’s process-wide single-flight (machine-global by design).
  • A second Effect HttpApi rewrite.
  • Running the ~350-file nikcli suite in CI. Memory kills the runner. bun run test:ci locally. Do not add it back, do not mark it non-blocking.
  • Weakening CI to get green: no skip, quarantine, or critical: false.
  • Billing / entitlements before a priced cohort exists.

How I would continue

The engineering plan’s own rule: the next item, if any, needs evidence that is in the repository today. I would not refill from a wish list. I would close the two open product windows, then promote only what those windows name.

Phase A
Close hosted release identity — still discovery, then one small ID C1 already gates validate and required deploy. The lie that remains: health returns semver, Railway --detach exits 0 on upload accept, two uploads of 1.330.0 look identical. Discovery in PRODUCT_ROADMAP already names the gap. I would not implement until an engineering ID exists. The smallest future item, if admitted: bake the validated git SHA at image build, expose it on the existing public GET /global/health (additive field, regenerate GlobalHealth, C1 drift), associate the detached upload with that SHA, fail the release decision on mismatch or timeout. No auto-rollback. No tokens in the body. Evidence gate: two consecutive approved uploads plus a failed-build case and an old-healthy-instance case.
Phase B
First-use without new telemetry Do not invent install_completed / first_turn_completed. They are not in source. Measure with what exists: TUI first-run (UserApi.hasUsers === false + unset kv.onboarding_complete), session.created, session.status busy→idle, session.error names (ProviderAuthError, APIError, …), DialogAccountLogin poll failures, empty catalog after model filter. Rank blockers by affected users and elapsed-time cost from support logs / manual review over one release boundary after hosted B1/C2. Promote only failures on installer, auth, provider catalog, or first-turn. Skip extras (image / TTS / remote) as architecture work. Production funnel events stay unadmitted until an ID exists — and if one is admitted, reuse the existing error taxonomy, payload limited to version, platform, elapsed, coarse code.
Phase C
Promote proposed contracts that already have tests, archive the rest Thirteen proposed v2 docs describe live code. I would pick the ones whose invariants are already pinned (permission coupling, loop single-flight/capacity, plugin autoload fail-closed, CI budgets, redaction) and mark them Accepted. For the rest (share lattice, workspace product-trust, CLI surface completeness, brain model chain), write the missing test or archive the hypothesis. This is documentation hygiene that stops the next pass from treating Proposed as a backlog.
Phase D
Continuity discovery on the existing seam User promise: a session started on one surface resumes on another without transcript loss, duplicate execution, or hidden queued input. Scenarios: TUI↔desktop, TUI↔mobile, reconnect after server restart, workspace switch. Measure state convergence and explicit recovery, not visual parity. Reuse generated HttpApi clients, EventFeed, session_pending, SessionV2. Surface presentation stays local. Protocol divergence needs an explicit contract decision. Output of this phase is a brief with a proposed engineering ID — or a written rejection. Not a new renderer, not a second transport, not “mobile/desktop feature parity.”
Phase E
Automation reliability on existing Loop / Mission / background-run / restart S4r is landed. Measure completion vs intervention separately: cancellation, graceful restart, result handoff, orphan lease recovery, capacity abort. Clustered ownership and hard-crash replay stay non-goals until placement, fencing, provider ambiguity, and tool idempotency are designed together. Smallest evidenced gap becomes the next engineering ID. Likely candidates if measurement agrees: orphaned-run operator UX, intervention-rate on permission-fullAccess sandboxed runs, mission resume attaching the same worktree. Do not add cron. Do not add a run queue on capacity.
Phase F
Share / distribute — only after trust is named ShareNext already stores remote or local envelopes. Later outcome needs trust, ownership, and revocation before changing collaboration or hosted surfaces. Tombstones, visibility lattice, cross-account sharing are product decisions with no leftover in the tree today. I would not start them.
Phase G
Paid value — after a priced cohort Retention and willingness-to-pay by the Now/Next outcome cohorts. Support cost. Provider-cost envelope. No billing architecture, no entitlement middleware, no second auth product until those exist.
Never
Things I would refuse even if asked as “quick wins” Re-adding the nikcli suite to CI. Quarantining tests. A second HttpApi. Nested project URLs. Desktop-as-TUI. Unconditional bootstrap. Threading ALS “to finish R1.” Pinning SessionV2 entries. Mandatory tool codecs. Raising mmap. Inventing funnel events. Auto-rollback of Railway. Effect 4.0.0-final wait (renames already happened at beta.104).

Working rules I would keep while doing that

  • HttpApi change → edit the group → bun run generate:httpapi-clients → commit generated output.
  • Typecheck once at the end of a change set (RAM).
  • Narrowest targeted test + typecheck before declaring done. Quote pass/fail counts and exit codes.
  • Verify encode/optional-key changes end-to-end through Server.fetch, never with a Schema probe (toJSON lies).
  • CI red is never someone else’s problem and is never fixed by skipping signal.
  • Git and DB operations wait for permission.
  • Effect: Effect.fail for declared errors; orDie only for unknown I/O; no throw inside Effect.gen.
  • Auth onboarding cannot skip account creation. Dialogs tear down polling on unmount.
