## 1. Close filesystem containment gap

**Goal.** Replace the lexical `containsPath` with a realpath-based containment that resists symlinks, `..` walks, and Windows cross-drive traversal.

**Critical files.**

- `src/file/index.ts:324-403` (current `containsPath` + the two TODO sites at `:391` and `:468`)
- `src/util/filesystem.ts` (add realpath seam here)
- `src/server/routes/file.ts:256-264` (the `PUT /file/content` write-path that bypasses the file service)

**Concrete changes.**

- Add `Filesystem.realpathInside(root, candidate): Promise<string | null>` to `src/util/filesystem.ts`. Returns canonical path when `candidate` resolves under `root`, `null` otherwise. Uses `fs.promises.realpath` for the existing parent, walks ancestors for non-existent write targets.
- Replace `containsPath` body in `src/file/index.ts:324-345` with a thin wrapper around `Filesystem.realpathInside`. Route the public methods (`read`, `list`, `status`, `search`) through the realpath variant.
- Delete the two TODO comments at `:396-397` and `:470-471` once replaced.
- In `routes/file.ts:256-264`, route `PUT /file/content` through `realpathInside` and switch to atomic `write-then-rename` (write to `<target>.tmp`, then `fs.rename`) to close the torn-write race.
- Export a typed `Filesystem.ContainmentError` (carry `candidate`, `root`, `reason: "symlink" | "cross-drive" | "escape"`) and replace the inline `AccessDeniedError` constructions at `file/index.ts:399` and `:473`.

**Verification.**

- New `test/file/containment.test.ts` — cases: nested symlink, `..` traversal inside a symlinked dir, write-target under non-existent dir, Windows cross-drive stub (skip on POSIX), nested worktree root.
- Extend `test/server/routes-file.test.ts` — `PUT /file/content` rejects traversal paths and atomically writes happy paths.
- New `test/util/filesystem.test.ts` — black-box realpath behaviour for the cases above.
- Manual: drop a symlink `<project>/escape -> /etc`, attempt `read {file:"escape/passwd"}`, expect `AccessDeniedError`.

**Effort:** M. **Risk:** Low — narrow seam, existing tests cover lexical containment.

## 2. Centralize log redaction and safe serialization

**Goal.** A single `Logger.redact` policy at the format boundary so secrets, OAuth state, query-embedded tokens, and full URLs never reach persistent logs.

**Critical files.**

- `src/util/log.ts:121-137` (`build` / `formatError` — the serialisation site)
- `src/util/user-error.ts` (call sites throw tagged errors; their `.cause` must be redacted)
- `src/cli/error.ts:133-140` (`FormatUnknownError` — also needs redaction)
- `src/cli/cmd/tui/{thread,worker}.ts` (TUI toast path uses `Log`)

**Concrete changes.**

- New `src/util/redact.ts` with `REDACT_KEYS = new Set(["token","secret","password","authorization","cookie","code","state","apiKey","apikey","session","bearer","x-api-key"])`, `redactValue(value): unknown`, `redactUrl(value): string` (strip `?token=…&code=…` keeping schema+host+path), `safeStringify(value, depth=4): string` using a `WeakSet` visited set to break cycles and a 4096-char per-leaf cap.
- In `src/util/log.ts:121-137`, route every value through `safeStringify` before `JSON.stringify`. For string values, run `redactUrl` first.
- Plumb `redactValue` through `formatError` (`:102-107`) so error causes are walked and redacted too.
- Tighten `Logger` signature: `extra?: Record<string, unknown>` instead of `Record<string, any>` (the smell the report flags).
- In `src/cli/error.ts:133-140`, replace bare `JSON.stringify(input, null, 2)` with `safeStringify(input)`; replace `input.stack` exposure with `Log.create({ service: "error-formatter" }).debug(...)` and return `input.message ?? input.name` to the user.

**Verification.**

- New `test/util/redact.test.ts` — cycle handling, depth cap, key matching, URL rewriting, OAuth-callback URL masking.
- New `test/util/log.test.ts` — feed tokens/prompts/config into `Log.create(...).info(...)`, assert file buffer contains `[REDACTED]` instead of raw value.
- Extend `test/cli/error.test.ts` — circular `Error.cause` chain renders as `"<circular>"`.
- Manual: run a session, confirm `~/.local/share/nikcli/log/*.log` contains no `sk-…`, OAuth `code=…`, or `Authorization: Bearer …`.

**Effort:** M. **Risk:** Medium — touches every log call. **Mitigation:** ship behind `Flag.NIKCLI_LOG_REDACT=0` for one release, then default on.

**Roll-out.**

- Add `safeStringify` alongside existing `JSON.stringify`; have `Log.build` prefer the safe variant via a feature flag defaulting to on in CI, off in dev.
- Add a contributor note in `AGENTS.md`: "log redactors: do not bypass `safeStringify`".
- Grep for `JSON.stringify` in `src/` and audit each call site; replace direct calls inside logging paths. Non-log serialisation stays unchanged.

## 5. Consolidate the error model

**Goal.** One typed-error channel; `UserFacingError` is the only path that emits text to users; `FormatError` is the single dispatcher; stack traces never leak.

**Critical files.**

- `src/cli/error.ts:1-157` (dispatcher — keep, harden)
- `src/util/user-error.ts` (`UserFacingError` base class)
- `src/util/log.ts` (couples with item 2 redaction)
- `src/util/error.ts` (legacy `NamedError` namespace; locate and audit callers)

**Concrete changes.**

- Audit `NamedError` usages. Add a single `ErrorModel` module re-exporting canonical tagged classes (`UserFacingError`, `File.AccessDeniedError`, `File.IOError`, `PermissionNext.{RejectedError,CorrectedError,DeniedError}`). Mark `NamedError` `@deprecated` with a `// @deprecated` comment.
- Add `formatStack(error)` returning `null` by default or redacted stack only when `process.env.NIKCLI_DEBUG === "1"`. Use it in `cli/error.ts:133-140`.
- Define `TransportError` (`Schema.TaggedErrorClass`) carrying `{ _tag, message, code, retryable, cause? }` that maps to Hono's `onError` and the Effect HttpApi encoder. Replace the ad-hoc `{error: string}` shape in `session.create` (`routes/session.ts:591`).
- Make `FormatError` exhaustive: default fallback returns `UserFacingError.format()` for unknown tags; only returns `undefined` for non-Error inputs.
- In `src/util/log.ts`, add a `cause`-aware variant of `formatError` (depth-limited) that respects item 2's redaction policy.

**Verification.**

- New `test/util/error-model.test.ts` — exhaustive tag dispatch, transport encoder round-trip, stack suppression default.
- Extend `test/cli/error.test.ts` — golden output for each registered `_tag`, no `at ` lines in default mode.
- New `test/server/error-translation.test.ts` — Hono `onError` returns the same JSON shape as Effect HttpApi encoder for the same error.
- Manual: trigger `ConfigJsonError`, `UserFacingError`, plain `Error` from CLI; confirm no stack traces in default mode.

**Effort:** M. **Risk:** Medium — changes touch every error site. **Mitigation:** keep `NamedError` as a thin alias during deprecation window.

**Roll-out.** Three steps: (a) add `ErrorModel` module + aliases; (b) switch new code paths; (c) sweep old paths in a final pass gated by `bun run lint --deny deprecated`.

## 8. Consolidate plugin registration security

**Goal.** Plugin/tool load is allowlist-gated, integrity-pinned, and emits typed errors.

**Critical files.**

- `src/tool/registry.ts:169-211` (the `Bun.Glob` + `import()` scan)
- `src/plugin/` (the plugin service)
- `src/config/config.ts` (new allowlist config block)

**Concrete changes.**

- New seam: `PluginLoader` namespace in `src/plugin/loader.ts` exporting `Interface { list(): Effect.Effect<{path, hash}[], PluginLoaderError>; load(path): Effect.Effect<ToolDefinition[], PluginLoaderError> }`. Two adapters: `BunGlobLoader` (current behaviour, marked deprecated, scoped to dev mode) and `AllowlistLoader` (default).
- In `ToolRegistry.layer` (`registry.ts:175,178-198`), replace `new Bun.Glob(...)` + `import(match)` with `yield* loader.list()` then `yield* loader.load(p)` per entry. Default `AllowlistLoader` reads `Config.tool.allow` (list of paths/hashes) and rejects anything else with `PluginLoaderError.NotAllowed`.
- Add `Config.tool.pin` (`Record<path, sha256>`); loader verifies SHA-256 of resolved file matches; mismatches throw `PluginLoaderError.HashMismatch`.
- Introduce `PluginLoaderError` (`Schema.TaggedErrorClass`) with tags `NotAllowed | HashMismatch | ScanFailed | ImportFailed | Disabled` — leans on item 5.
- Disable dynamic load in production: `Flag.NIKCLI_ALLOW_PLUGIN_AUTOLOAD=1` to enable, default off; loaded plugins stay in `ToolRegistry` `custom` list as today but cannot run arbitrary code unless the user opts in.

**Verification.**

- New `test/plugin/loader.test.ts` — happy path allowlist, hash mismatch, missing entry, symlink re-direction; glob-only behaviour preserved when `Flag.NIKCLI_ALLOW_PLUGIN_AUTOLOAD=1`.
- Extend `test/tool/registry.test.ts` — drop a `tool/escape.ts` containing `console.log("pwn")` into a temp config dir; expect no tool registered and `PluginLoaderError.NotAllowed` in the bus event.
- New `test/security/plugin-pinning.test.ts` — SHA mismatch halts load and emits typed error.

**Effort:** M. **Risk:** Medium — breaks workflows that depend on `~/.config/nikcli/tool/foo.ts` autoload. **Mitigation:** feature flag default off; document migration in `AGENTS.md`.
