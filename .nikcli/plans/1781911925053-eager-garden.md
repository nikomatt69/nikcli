# Exemplary ACP (Agent Client Protocol) integration in nikcli

## Goal

Bring nikcli's ACP server to the same architectural bar as
[`anomalyco/opencode@dev/packages/opencode/src/acp`](https://github.com/anomalyco/opencode/tree/dev/packages/opencode/src/acp):

- **Effect-everywhere service layer** with typed `RequestError` mapping
- **Directory snapshot** cached per-directory, exposes providers / modes / commands / default model
- **Config options** for model / effort(variant) / mode selection
- **Full session lifecycle** — `newSession`, `loadSession`, `resumeSession`, `listSessions`, `closeSession`, `forkSession`, `setSessionConfigOption`, `setSessionModel`, `setSessionMode`
- **Streaming sessions** via global event subscription + replay on `loadSession`
- **Tool calls** mapped to ACP `ToolKind` with locations, diff content, and shell-output snapshots
- **Permissions** queued per-session, with `writeTextFile` preview applying unified diffs
- **Usage updates** with cached context limits + USD cost
- **Profile instrumentation** behind `OPENCODE_ACP_PROFILE=1` → rename to `NIKCLI_ACP_PROFILE=1`
- **messageId** threaded through every `sessionUpdate`
- **Pluggable / extension-friendly**: keep wiring identical so an external plugin can also host the same `ACPService.make({ sdk, connection })`.

User-confirmed scope: **Full port to 12-file architecture, Effect everywhere, E2E + unit verification.**

## Reference Architecture (opencode, dev branch)

| File               | Responsibility                                                                                                                                                                                                                                                                                |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `service.ts`       | `make({ sdk, connection, ... })` returns the ACP service interface. All ACP methods are `Effect.fn` generators dispatched through a `ManagedRuntime`.                                                                                                                                         |
| `agent.ts`         | 96-line `Agent` class implementing `@agentclientprotocol/sdk`'s `ACPAgent` interface. Each method just calls `run(this.service.xxx(params))`, where `run` maps `ACPService.Error` → `RequestError`.                                                                                           |
| `session.ts`       | In-memory `Effect.Ref<Map<sessionId, Info>>` with `create / load / list / get / remove / setModel / setVariant / setMode / recordPartMetadata`.                                                                                                                                               |
| `directory.ts`     | `Loader` + `Service` Effect layers. `loaderLayer` aggregates providers, agents, commands, skills, default model in parallel; `Service` keeps a `SynchronizedRef<Map<dir, Effect>>` of cached snapshots with `Effect.cached` invalidation on error.                                            |
| `event.ts`         | `Subscription` class subscribes to `sdk.global.event()`, routes `permission.asked` to `ACPPermission.Handler`, `message.part.updated` / `message.part.delta` to local session-metadata records and `sessionUpdate` notifications. Also exposes `replayMessage` for `loadSession` rehydration. |
| `tool.ts`          | Pure helpers: `toToolKind`, `toLocations`, `pendingToolCall`, `runningToolUpdate`, `completedToolUpdate`, `errorToolUpdate`, `shellOutputSnapshot`, `imageContents`.                                                                                                                          |
| `permission.ts`    | `Handler` class with per-session promise queues; `requestPermission` + `writeTextFile` for "Allow once" / "Always" / "Reject"; applies unified diffs on edit approvals.                                                                                                                       |
| `content.ts`       | Pure helpers: `promptContentToParts` (ACP → nikcli), `partsToContentChunks` (nikcli → ACP), `audienceFlags` / `partAudience` for `synthetic` / `ignored` annotations.                                                                                                                         |
| `config-option.ts` | Pure helpers: `buildModelSelectOption`, `buildEffortSelectOption`, `buildModeSelectOption`, `buildConfigOptions`, `parseModelSelection`.                                                                                                                                                      |
| `usage.ts`         | Effect service: `buildUsage`, `latestAssistantMessage`, `totalSessionCost`, `contextLimit`, `sendUpdate`. Cached `contextLimit` per `(dir, provider, model)`.                                                                                                                                 |
| `error.ts`         | Tagged `Schema.TaggedErrorClass` errors + `toRequestError` mapper to `@agentclientprotocol/sdk`'s `RequestError`.                                                                                                                                                                             |
| `profile.ts`       | `mark` / `duration` / `measure` behind `process.env.OPENCODE_ACP_PROFILE === "1"`.                                                                                                                                                                                                            |

The CLI command (`opencode acp`) wires `Service.listen(opts)` → `createOpencodeClient(baseUrl)` → `AgentSideConnection((conn) => agent.create(conn, { sdk }), ndJsonStream(stdin, stdout))`.

## Nikcli Current State

`packages/nikcli/src/acp/` already exists with a working baseline:

- `agent.ts` (1,369 lines) — class `ACP.Agent implements ACPAgent` with `initialize / newSession / loadSession / prompt / cancel / setSessionModel / setSessionMode`. Subscribes to `sdk.global.event` for streaming, listens for `permission.asked`, translates `tool/text/reasoning/file` parts, handles `todowrite` → `plan`, replays message history on `loadSession`. Mature single-file implementation, but missing configOptions, fork/list/resume/close, usage_update, messageId threading, profile instrumentation, and Effect layer decomposition.
- `session.ts` — `ACPSessionManager` in-memory map; methods: `create / load / get / tryGet / getModel / setModel / setMode`.
- `types.ts` — `ACPSessionState` + `ACPConfig`.
- `README.md` — references a `client.ts` and `server.ts` that **do not exist** in the directory listing.

`packages/nikcli/src/cli/cmd/acp.ts` (70 lines) already implements the stdio + `Server.listen` + `createNikcliClient` + `AgentSideConnection` wiring using `ndJsonStream`.

`@agentclientprotocol/sdk@0.5.1` is already a dependency. `@nikcli-ai/sdk/v2` is already generated and exports `createNikcliClient`. `Agent.Service` from `src/agent/agent.ts` (Effect-based, line 1024 exports `defaultLayer`) is available for `defaultAgent()` / `list()` / `generate()`.

The wire protocol surface available in the SDK: `Provider`, `Command`, `Skill`, `MCP`, `Permission`, `Session`, `App`, `Config`, `Global`. Confirmed endpoints relevant: `sdk.session.create / get / list / messages / message / prompt / command / summarize / abort`, `sdk.config.providers / get`, `sdk.app.agents / skills`, `sdk.command.list`, `sdk.permission.reply`, `sdk.mcp.add`, `sdk.global.event`.

## Implementation Plan

### Phase 1 — Foundation: error, profile, types

Create the cross-cutting helpers and types before any service code.

**Files:**

- `packages/nikcli/src/acp/error.ts` (new)
- `packages/nikcli/src/acp/profile.ts` (new)

**`error.ts`** — mirror opencode:

```ts
export class SessionNotFoundError extends Schema.TaggedErrorClass<...>()("ACPSessionNotFoundError", { sessionId: Schema.String }) {}
export class InvalidConfigOptionError ...
export class InvalidModelError ...
export class InvalidEffortError ...
export class InvalidModeError ...
export class AuthRequiredError ...
export class UnknownAuthMethodError ...
export class UnsupportedOperationError ...
export class ServiceFailureError ...
export type Error = SessionNotFoundError | InvalidConfigOptionError | ... | ServiceFailureError
export function toRequestError(error: Error): RequestError
export function fromUnknownDefect(defect: unknown, safeMessage?: string): ServiceFailureError
```

Use the existing `@/util/effect-zod` `zodObject` or `Schema.TaggedErrorClass` directly with `Schema.String` for fields. Throw `LoadAPIKeyError` → `RequestError.authRequired()` in `Agent.authenticate`.

## Adaptation Notes (opencode → nikcli differences)

- **Provider/model IDs**: nikcli uses unbranded `string`s; opencode uses `ProviderV2.ID` / `ModelV2.ID` branded types. Drop the branded types where they appear in ported code.
- **Variant key**: nikcli doesn't have an `effort` concept in `Provider.Model.variants` today — `buildEffortSelectOption` returns `undefined` when `variants` is empty, so the option is simply omitted. No code change beyond the gate.
- **Tool set**: nikcli has `apply_patch`, `todowrite`, `monitor`, `delegation`, `task`, `external_directory`, `docs_*` not present in opencode. Add cases in `toToolKind` and `toLocations`.
- **`sdk.session.fork`**: if not present in nikcli SDK v2, the `forkSession` method throws `UnsupportedOperationError`. Verify during implementation.
- **`@nikcli-ai/sdk/v2` types**: import `SessionMessageResponse` (replay), `Event`, `EventMessagePartDelta`, `EventMessagePartUpdated`, `ToolPart`, `Message`, `Part` from `@nikcli-ai/sdk/v2` (opencode imports `@opencode-ai/sdk/v2`).
- **No `@opencode-ai/core/*` packages**: nikcli doesn't have these. Use plain `string` for IDs; the `Provider.parseModel` helper already exists at `packages/nikcli/src/provider/provider.ts`.
- **`Installation.VERSION`**: nikcli exports this from `@/installation` (already imported by `agent.ts`).
- **Plugin hook**: `Agent.init({ sdk })` returns a factory that takes a `connection` + optional config — keep this signature so a `packages/plugin` extension can call it the same way. The internal `ACPService.make({ sdk, connection })` shape is the public contract.
- **Logging**: use nikcli's `Log.create({ service: "acp-..." })` everywhere (opencode uses `Effect.logError` for some paths; nikcli uses `log.error(...)` — keep nikcli's style for `Log` calls, `Effect.logError` only inside Effect generators where the runtime is preferred).

## Verification

End-to-end + unit verification, executed in this order, must all pass before the goal is met:

1. **Typecheck** — `cd packages/nikcli && bun run typecheck` exits 0.
2. **Lint** — `cd packages/nikcli && bun run lint` exits 0.
3. **Existing tests** — `cd packages/nikcli && bun test` exits 0. No regressions in `test/server/`, `test/agent/`, `test/cli/`.
4. **Unit tests** — new `packages/nikcli/test/acp.test.ts` covers:
   - `Service.initialize` returns `protocolVersion: 1`, all four `sessionCapabilities`, `agentCapabilities.promptCapabilities.embeddedContext`, `authMethods[0].id === "nikcli-login"`.
   - `Service.newSession` returns `configOptions` containing `model`, and (when modes exist) `mode`. `currentModelId` matches the resolved default model.
   - `Service.loadSession` calls `replayMessages` and emits `sessionUpdate`s with `messageId` populated.
   - `Service.prompt` with a non-slash prompt invokes `sdk.session.prompt`; with `/compact` invokes `sdk.session.summarize`; with `/<known-command>` invokes `sdk.session.command`.
   - `Service.setSessionModel` parses `provider/model/variant` strings into `Provider.parseModel`-shaped output.
   - `Service.setSessionMode` rejects unknown modes via `ACPInvalidModeError` → `RequestError.invalidParams`.
   - `Service.closeSession` removes the session from the in-memory store and calls `sdk.session.abort`.
   - `Service.listSessions` returns server-side sessions + live sessions, sorted by `updatedAt desc`.
   - `Handler.handle(permission.asked)` calls `connection.requestPermission`, then `sdk.permission.reply` with the chosen optionId; on edit + allow it calls `connection.writeTextFile` after `applyPatch`.
   - `Tool.toToolKind("bash") === "execute"`, `toToolKind("edit") === "edit"`, `toToolKind("grep") === "search"`, etc.
   - `Content.promptContentToParts([{ type: "image", data: "...", mimeType: "image/png" }])` produces a `{ type: "file", url: "data:image/png;base64,...", ... }` part.

     Mock `NikcliClient` and `AgentSideConnection` with stubs; assert call counts and argument shapes.

## Out of Scope

- VS Code / JetBrains native ACP adapters (we ship the protocol server; clients are external).
- Replacing the SDK with anything else.
- Adding a new `Provider.Model.variants` field — `effort` config option simply hides itself when no variants exist.
- Auth implementation beyond the `AuthMethod` advertisement — `authenticate()` throws `AuthRequiredError` until credentials are present, same as opencode.
- Moving the ACP server into a separate process / plugin package. The factory signature is plugin-friendly so a follow-up can extract it.
