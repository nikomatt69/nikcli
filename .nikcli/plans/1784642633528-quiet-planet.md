# Port 5 opencode PRs into nikcli (compaction, MCP permissions, shell, command overrides)

## Goal

Port the five highest-impact open pull requests from `anomalyco/opencode` into the nikcli monorepo, landing each one as its own focused commit and PR against `live-main` so they can be reviewed and reverted independently. All five ports use only patterns already documented in `packages/nikcli/AGENTS.md` (Zod, Effect, `Tool.define`, `Log.create`, `Storage` namespace) and stay within the nikcli TypeScript + Bun toolchain.

## Plan review (interpretation committed for this turn)

The previous delegation cycles confirmed nikcli is structurally a port of opencode and verified the exact insertion points for each port by direct `grep`. This plan turns that ranking into a sequenced, verifiable execution plan.

Interpretation committed:

1. **One PR per port.** Five separate branches and five separate PRs against `live-main`. This keeps review surface small and lets us revert any one without un-doing the rest.
2. **Lowest risk first.** Order is A → B → C → D → E. A is a single switch case, B is a permission refactor, C is a new tracker with reset semantics, D is a dep bump + 2-line replacement, E is the only one that touches the public config schema and therefore requires SDK regeneration.
3. **No opportunistic refactors.** Each PR is the minimal change plus its targeted unit test. No "while I'm here" cleanup.

## Recommended architecture (shared by all five ports)

Each port follows the existing nikcli patterns captured in `packages/nikcli/AGENTS.md`:

- **Errors**: classify in `packages/nikcli/src/session/message-v2.ts` `fromError`. Do not throw from tool `execute()`. Use `Log.create({ service: "<area>" })` for any new logger.
- **Storage**: nikcli's `Storage` namespace with hierarchical keys. The compaction failure counter (port C) lives in a module-level `Map<string, number>` with reset on success — same as opencode. No DB migration.
- **Tool definitions**: `Tool.define("name", { description, parameters: z.object(...), execute })`. No mock / placeholder code.
- **Config**: extend via the zod schema in `packages/nikcli/src/config/config.ts`. When the public schema changes (only port E), regenerate `packages/sdk/openapi.json` and `packages/sdk/js/src/v2/gen/`** with `packages/sdk/js/script/build.ts`.
- **Tests**: `bun test` against new `<area>.test.ts` files next to the existing `packages/nikcli/test/...` tree. Existing test files already cover the touched modules (`test/session/message-v2.test.ts`, `test/session/retry.test.ts`, `test/session/processor-retry.test.ts`, `test/session/compaction.test.ts` if it exists, `test/command/effect-service.test.ts`, `test/tool/bash-output.test.ts`). Each port extends the closest existing test rather than creating a new one when possible.

### Port B — Exclude wholly-denied MCP tools from provider requests

Files to modify:

- `packages/nikcli/src/permission/ruleset.ts` — introduce a new exported `Permission.visibleTools(tools, ruleset)` helper that filters out tools wholly-denied by `pattern === "*"` rules but preserves resource-scoped denies. Mirrors opencode's contract.
- `packages/nikcli/src/session/tools.ts` — when enumerating MCP tools for the model, route them through `Permission.visibleTools(mcpTools, ruleset)`.
- `packages/nikcli/test/permission/ruleset.test.ts` (create if missing) — unit tests for the new helper, including the pattern `postman*` whole-deny and a resource-scoped deny case.
- `packages/nikcli/test/session/tools.test.ts` (create or extend) — integration test that an MCP tool wholly denied by `tools: { "postman*": false }` is **not** present in the model-facing tool list, while a different MCP tool with only a resource-scoped deny **is** still listed.

Behaviour to add (verbatim from upstream #38060, adapted):

```ts
// permission/ruleset.ts
export function visibleTools<T extends { name: string }>(tools: T[], ruleset: Rule[]): T[] {
  const wholeDenies = new Set(ruleset.filter((r) => r.action === "deny" && r.pattern === "*").map((r) => r.tool))
  return tools.filter((t) => !wholeDenies.has(t.name))
}

// session/tools.ts — at the MCP enumeration site
for (const [key, entry] of Object.entries(Permission.visibleTools(yield * mcp.tools(), ruleset))) {
  // … existing conversion logic unchanged
}
```

### Port C — Compaction circuit breaker

Files to modify:

- `packages/nikcli/src/session/compaction.ts` — add module-level `MAX_CONSECUTIVE_COMPACTION_FAILURES = 3`, `compactionFailures: Map<string, number>`, and exported helpers `recordCompactionFailure(sessionID)`, `resetCompactionFailures(sessionID)`, `isCompactionCircuitOpen(sessionID)`. In the `compact` branch, build the error message using the attempt counter; in the `continue` branch, call `resetCompactionFailures`.
- `packages/nikcli/test/session/compaction.test.ts` (create if missing; the existing `summary-effect-service.test.ts` is adjacent and may already cover some of this) — unit tests for the three exports (increment, reset, threshold-trip), plus a processor-level test that asserts the error message contains `"circuit breaker open"` after 3 consecutive failures and that the counter resets after a `continue`.

Behaviour to add (verbatim from upstream #38102, adapted to nikcli's compaction pipeline shape):

```ts
// session/compaction.ts
const MAX_CONSECUTIVE_COMPACTION_FAILURES = 3
const compactionFailures = new Map<string, number>()

export function recordCompactionFailure(sessionID: string): number {
  const count = (compactionFailures.get(sessionID) ?? 0) + 1
  compactionFailures.set(sessionID, count)
  return count
}
export function resetCompactionFailures(sessionID: string): void {
  compactionFailures.delete(sessionID)
}
export function isCompactionCircuitOpen(sessionID: string): boolean {
  return (compactionFailures.get(sessionID) ?? 0) >= MAX_CONSECUTIVE_COMPACTION_FAILURES
}
```

The two existing call sites (the `compact` and `continue` branches inside the compaction generator) get two extra lines each: one to call `recordCompactionFailure(input.sessionID)` and update the error message with the attempt count, one to call `resetCompactionFailures(input.sessionID)`.

### Port E — Partial command override without `template`

Files to modify:

- `packages/nikcli/src/config/config.ts` line 759 — change `template: z.string()` to `template: z.string().optional()`.
- `packages/nikcli/src/command/index.ts` lines 150-162 — branch on `command.template !== undefined`:
  - If defined → keep the existing full-overwrite behaviour.
  - If undefined → look up `existing = result[name]` (or `commands[name]` if there's a separate built-in table) and merge `command.agent ?? existing.agent`, `command.model ?? existing.model`, `command.description ?? existing.description`, `command.subtask ?? existing.subtask`. Drop the entry if no built-in exists with that name.
- `packages/nikcli/src/command/index.ts` line 235 — the `if (result[name]) continue` for skill commands still applies; partial-overrides continue to take precedence over skill commands with the same name.
- `packages/sdk/openapi.json` + `packages/sdk/js/src/v2/gen/**` — regenerate with `./packages/sdk/js/script/build.ts` because the config contract changed.
- `docs/commands.mdx` (if it exists) — add a paragraph explaining partial override.

Behaviour to add (verbatim from upstream #38071, adapted to nikcli's command shape):

```ts
for (const [name, command] of Object.entries(cfg.command ?? {})) {
  if (command.template !== undefined) {
    // existing full-overwrite path
    result[name] = {
      /* … unchanged … */
    }
    continue
  }
  const existing = result[name]
  if (existing === undefined || typeof existing.template !== "string") continue
  result[name] = {
    name,
    agent: command.agent ?? existing.agent,
    model: command.model ?? existing.model,
    description: command.description ?? existing.description,
    get template() {
      return existing.template
    },
    subtask: command.subtask ?? existing.subtask,
    hints: existing.hints,
  }
}
```

Tests to add in `packages/nikcli/test/command/effect-service.test.ts` (or new `command.test.ts` next to it):

- `command.review = { agent: "my-reviewer" }` inherits the built-in `/review` template and overrides only `agent`.
- `command.foo = { description: "x" }` with no built-in named `foo` is dropped (no orphan command).
- `command.review = { template: "..." }` still works as a full override (backwards compatibility).
- An old config without `template` parses cleanly (`template` is now optional, not required).

### Sequencing, branches, and review

Each port lands as its own commit and its own PR against `live-main`:

1. Branch `feat/port-38041-retry-json-parse-error` → port A → push → open PR.
2. Branch `fix/port-38060-exclude-denied-mcp-tools` → port B → push → open PR.
3. Branch `feat/port-38102-compaction-circuit-breaker` → port C → push → open PR.
4. Branch `fix/port-38045-shell-quote` → port D → `bun install` → push → open PR.
5. Branch `feat/port-38071-partial-command-override` → port E → regen SDK → push → open PR.

Ports A and B can be developed in parallel; C depends on A's retry patterns being consistent; D is independent; E depends on the SDK regen script being up to date.
