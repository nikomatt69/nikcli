# Perfect Migration to Effect — Plan

**Goal:** complete, regression-free migration of `packages/nikcli` to Effect 4, starting with the easiest/foundational phases, preserving all current behavior, with no error-propagation regressions and no public SDK/output regressions.

## Scope decisions (from the user)

1. **Start with the easiest phases and progress.** The plan lands the foundation (Phase A and B) first, then progresses through the remaining phases. The deliverable for this round is a plan + Phase A + B executed cleanly; the remaining phases are sized as separate follow-up rounds but the structure is laid out here end-to-end.
2. **Keep Hono as a long-lived fallback.** Hono is not deleted; the new Effect `HttpApi` backend runs behind `NIKCLI_EXPERIMENTAL_HTTPAPI=1` and the default backend stays Hono until the SDK diff (Phase E) is closed.
3. **ALS removal (`util/context.ts`, `project/instance.ts`) is the most logical next carve-out after the foundation lands.** It is documented as a focused follow-up round (Phase C below) rather than mixed into the error-typing work, because `INST-1..6` touches many call sites (`tool/repo_overview.ts`, `control-plane/adapters/worktree.ts`, `cli/bootstrap.ts`, `file/watcher.ts`, `storage/db.ts`, `session/llm.ts`) and that surface deserves its own PR cadence.
4. **Process guard helper lives in `src/effect/process-guards.ts`** (new file, alongside the existing `src/effect/` foundation). Exposes `installProcessGuards()` that pipes `process.on("unhandledRejection")` and `"uncaughtException"` into `Cause.pretty(cause) → UI.error → process.exitCode`.

## Current state (audit summary)

`packages/nikcli` is mid-migration to Effect 4.0.0-beta.65 (see `packages/nikcli/package.json`):

- **Foundation in place:** `packages/nikcli/src/effect/{runtime,instance-ref,instance-scope,instance-state,with-instance,index}.ts` define `InstanceRef`/`WorkspaceRef`, `InstanceState.make` (per-directory `ScopedCache`), `InstanceScope.with(...)`, and a shared `AppRuntime = ManagedRuntime.make(Layer.empty, { memoMap })`.
- **28+ services already on the Effect shape** (`Context.Service` + `Layer.effect` + `defaultLayer`): `Account`, `Agent`, `AppFileSystem`, `Auth`, `Bus`, `Command`, `Config`, `ConfigPaths`, `ConnectorAuth`, `File`, `FileWatcher`, `Format`, `Installation`, `LSP`, `MCP`, `McpAuth`, `PermissionNext`, `Plugin`, `Project`, `ProviderAuth`, `Pty`, `Question`, `SessionStatus`, `Skill`, `Snapshot`, `ToolRegistry`, `Truncate`, `Vcs`, `Worktree`, `Session` (plus sub-services `SessionProcessor`, `SessionPrompt`, `SessionCompaction`, `SessionSummary`, `SessionRevert`, `SystemPrompt`, `Todo`), `ShareNext`, `Provider`, `Storage`.
- **50 `Context.Service` definitions, 53 `Schema.TaggedErrorClass`es, 787 `Effect.gen` blocks, 113 `Effect.fn` sites.**
- **HTTP/HttpApi**: `packages/nikcli/src/server/httpapi/{public,bridge,top-level,config,experimental,file,mcp,project,provider,question,permission,session,workspace}.ts` implement a parallel `effect/unstable/httpapi` stack mounted through `HttpApiBridge` behind the `NIKCLI_EXPERIMENTAL_HTTPAPI=1` feature flag. ~80 routes are bridged. The legacy Hono server is the default.
- **Two context systems coexist**: `packages/nikcli/src/util/context.ts` (AsyncLocalStorage `Context.create<T>` for `Instance.provide`, `WorkspaceContext.provide`) and Effect `Context.Service`. The `Instance.provide` legacy path is the deletion target.
- **Error handling is ~70% typed.** 53 `Schema.TaggedErrorClass`es coexist with 62 `class X extends Error` legacy classes and 200+ `Effect<…, unknown>` service methods.
- **No `NamedError` class exists** in this repo (it was never introduced; the pattern is `Schema.TaggedErrorClass` directly).
- **Schema layer is hybrid**: 372 hand-written zod definitions, 91 derived from `Schema.Struct` via `packages/nikcli/src/util/effect-zod.ts` (the walker that converts `Schema.Struct → z.ZodType`).
- **Tests use `bun:test` + `Effect.runPromise(InstanceScope.with(...))` directly** or `makeTestRuntime(label, layer)` from `packages/nikcli/test/helpers/{test-effect,effect-test}.ts`. There is no `testEffect(...)` aligned with the upstream house style.

## Plan

### Phase A — Error typing foundation (deliverable for this round)

**Objective:** every expected service failure is a `Schema.TaggedErrorClass` on the Effect error channel. No `Effect<…, unknown>` for service-method-level effects. No `throw` inside `Effect.gen`/`Effect.fn` for expected failures. No `class X extends Error` for expected domain failures.

**Sub-steps (each a small, testable PR):**

#### A.1 — Define the tagged-error taxonomy

- Inventory every `throw new XError(...)` and `Effect.fail(new Error(...))` inside service files (not infrastructure or transport).
- For each, define a `Schema.TaggedErrorClass<XError>()("XError", { fields })` in the owning service file.
- Replace `throw new XError(...)` with `yield* new XError({ ... })` (or `Effect.fail(new XError({...}))` for non-generator sites).
- Replace `Effect.tryPromise({ try, catch: e => new Error(String(e)) })` with `Effect.tryPromise({ try, catch: e => mapToDomainError(e) })` where `mapToDomainError` is a local function that returns the specific tagged class.
- **Services to touch (P1 of `error-boundaries-plan.md` + `migration.md`):**
  - `packages/nikcli/src/provider/provider.ts` — `ProviderInitError`, plus narrow the `Effect<…, unknown>` methods.
  - `packages/nikcli/src/mcp/index.ts` — `MCPFailed`.
  - `packages/nikcli/src/skill/skill.ts` — `SkillInvalidError`, `SkillNameMismatchError`.
  - `packages/nikcli/src/lsp/client.ts` — `LSPInitializeError`.
  - `packages/nikcli/src/ide/index.ts` — install errors.
  - `packages/nikcli/src/config/{error,config,markdown}.ts` — config errors (preserve CLI diagnostics).
  - `packages/nikcli/src/session/{prompt,processor}.ts` — `agentRequired` becomes `yield* new AgentNotFoundError({ name, available })` (was a plain `throw new Error`).
  - `packages/nikcli/src/worktree/index.ts` — `err.name.startsWith("Worktree")` family becomes named tagged classes.
  - `packages/nikcli/src/util/process.ts` — `Process.RunFailedError` tagged.
  - `packages/nikcli/src/util/user-error.ts` — `UserFacingError` becomes a `Schema.TaggedErrorClass` with `title`, `what`, `trySuggestion`, `docs` fields. The `FormatError` chain in `packages/nikcli/src/cli/error.ts` switches from `instanceof` to `Effect.catchTag("UserFacingError", ...)` (or equivalent JS-side matcher using `_tag`).

#### A.2 — Tighten service method error channels

- For every service in the `migration.md` checklist that returns `Effect<…, unknown>`, narrow the method signature to `Effect<…, Namespace.Error>` where `Namespace.Error` is the union of all `Schema.TaggedErrorClass`es the service can fail with.
- For Hono-boundary services, the `Interface` type stays the same; the implementation uses the typed channel.
- Add `namespace Error` exports where the union needs to be referenced (e.g. `export type Error = Storage.NotFoundError | Storage.IOError`).

#### A.3 — Test migration to typed exits

- For each `Effect.runPromise(...)` test that expects a failure, switch to `Effect.runPromiseExit(...)` and assert `Exit.isFailure` + the specific `_tag`.
- For tests that currently catch a thrown error with `try/catch`, wrap in `Effect.tryPromise(...)` and assert the same way.

**Verification (after each sub-step):**

- `cd packages/nikcli && bun run typecheck` (tsgo).
- `cd packages/nikcli && bun test test/{service-folder}/effect-service.test.ts` (per-service tests).
- `cd packages/nikcli && bun test test/server/httpapi-bridge.test.ts test/server/httpapi-session.test.ts test/server/httpapi-config.test.ts` (regression check for the Hono and Effect HTTP path).
- `rg -n "Effect\.Effect<[^,]+, unknown>" packages/nikcli/src/{account,agent,auth,bus,config,connector,file,filesystem,format,installation,lsp,mcp,permission,plugin,project,provider,pty,question,session,share,skill,snapshot,storage,tool,util,vcs,worktree}/` returns no matches.
- `rg -n "throw new [A-Z][A-Za-z]+Error\(" packages/nikcli/src/{account,agent,auth,bus,config,connector,file,filesystem,format,installation,lsp,mcp,permission,plugin,project,provider,pty,question,session,share,skill,snapshot,storage,tool,util,vcs,worktree}/` returns no matches in service files (only in the test files that intentionally throw, if any).

### Phase B — HTTP boundary mappers (deliverable for this round)

**Objective:** the Hono `onError` `instanceof` chain in `packages/nikcli/src/server/server.ts:182-210` shrinks to a final unknown-defect fallback. Each route (or route group) maps its expected service errors to a declared `HttpApiError`/public body at the handler boundary.

**Sub-steps:**

#### B.1 — Add HTTP error helpers

- Create `packages/nikcli/src/server/httpapi/errors.ts` with `notFound(message)`, `badRequest(message)`, `unknown()` (per `error-boundaries-plan.md` § "Helper Modules We Probably Want").
- These return `Effect.fail(new HttpApiError.BadRequest({ message }))` / `.NotFound(...)` and are reused by handlers (no giant `unknown → status` mapper).

#### B.2 — Replace `server.ts:182-210` chain

- For each entry in the chain (`Session.BusyError → 409`, `Storage.NotFoundError → 404`, `Provider.ModelNotFoundError → 400`, `Vcs.PatchApplyError → 400`, `Worktree* → 400`, `HTTPException → passthrough`, fallback `500`):
  - Find the matching Hono route handler in `packages/nikcli/src/server/routes/*.ts`.
  - Wrap the service call with `Effect.catchTag("XError", () => badRequest(...))` (or the appropriate helper).
  - Preserve the legacy `{ name, data }` body shape where the SDK depends on it.
- After all chain entries are routed, the `onError` middleware is reduced to:
  - `if (err instanceof HTTPException) return err.getResponse()`
  - `log.error("unhandled", { cause: Cause.pretty(cause) })`
  - `return c.json({ name: "Unknown", data: { message: "Internal error" } }, 500)`

**Verification (after each route file):**

- `cd packages/nikcli && bun test test/server/httpapi-*.test.ts`
- `cd packages/nikcli && bun test test/server/routes/...` (per-route Hono tests).

## Why this order minimizes regression risk

- **Phase A is purely additive in type safety.** Each tagged class narrows the error channel; no behavior changes; the wire format stays the same; the SDK output stays the same. The Hono `onError` chain keeps working because `instanceof` continues to work on `Schema.TaggedErrorClass` instances (they extend `Error`-shaped values).
- **Phase B's per-route `Effect.catchTag` swaps are scoped per route file.** Each route file's Hono tests + the `httpapi-bridge` tests act as a regression net. A bad catch produces a wrong status code, which tests catch.
- **Phase C (`util/context.ts` removal) is the most invasive** because it changes fiber-local access patterns. Doing it after the typed-error foundation means there is a clean fallback for any "where did the `Instance.directory` come from?" debugging — the typed error tells you which service threw.
- **Phase D's route bridging is incremental** (one route group per PR), with the regex allowlist as a switch.
- **Phase E (SDK flip) is the highest-regression-risk step** and benefits from the fact that the Hono backend still exists for the fallback flag.
- **Phase F (CLI) is the user-facing finish line** but the process-guard helper is the safety net for any "I forgot to `yield*` a fiber" bug introduced earlier in the migration.
- **Phase G (tool/bus/storage/log) is mechanical** once Phase A's typed errors are in place.
- **Phase H (test infra) is a refactor of the test code only**; behavior is unchanged.
