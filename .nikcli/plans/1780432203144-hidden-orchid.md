# Perfect Migration to Effect — Analysis and Plan

## Status Snapshot (read-only audit)

`packages/nikcli` is **deep into** an Effect 4 migration. The current state is:

- **Effect 4.0.0-beta.65** + `@effect/platform-bun` 4.0.0-beta.65 are direct deps (`packages/nikcli/package.json`).
- **Foundation is in place**: `src/effect/{runtime,instance-ref,instance-scope,instance-state,with-instance,index}.ts` define `InstanceRef`/`WorkspaceRef`, `InstanceState.make` (per-directory `ScopedCache`), `InstanceScope.with(...)`, and a shared `AppRuntime = ManagedRuntime.make(Layer.empty, { memoMap })`.
- **Service-shape migration is ~85% complete** (per `specs/effect/migration.md` and `facades.md`):
  - 28+ services already have `Context.Service<…>()("@nikcli/Name")` + `Layer.effect(Service, Effect.gen(...))` + `defaultLayer`: `Account`, `Agent`, `AppFileSystem`, `Auth`, `Bus`, `Command`, `Config`, `ConfigPaths`, `ConnectorAuth`, `File`, `FileWatcher`, `Format`, `Installation`, `LSP`, `MCP`, `McpAuth`, `PermissionNext`, `Plugin`, `Project`, `ProviderAuth`, `Pty`, `Question`, `SessionStatus`, `Skill`, `Snapshot`, `ToolRegistry`, `Truncate`, `Vcs`, `Worktree`, `Session` (and its sub-services `SessionProcessor`, `SessionPrompt`, `SessionCompaction`, `SessionSummary`, `SessionRevert`, `SystemPrompt`, `Todo`), `ShareNext`, `Provider`, `Storage`.
  - 50 `Context.Service` definitions, 53 `Schema.TaggedErrorClass`es, 787 `Effect.gen` blocks, 113 `Effect.fn` sites.
- **HTTP/HttpApi migration is mid-progress** (per `specs/effect/http-api.md`):
  - The legacy Hono server is still the default backend; `src/server/httpapi/{public,bridge,top-level,config,experimental,file,mcp,project,provider,question,permission,session,workspace}.ts` already implement a parallel `effect/unstable/httpapi` stack mounted through `HttpApiBridge` behind the `NIKCLI_EXPERIMENTAL_HTTPAPI=1` feature flag.
  - 80+ method+path routes are bridged, but ~80+ Hono routes still serve the default path. SSE (`/event`), websocket (`/pty`), TUI bridge, and session streaming routes are not yet ported.
- **Schema layer is hybrid**: 372 hand-written zod definitions, 91 derived from `Schema.Struct` via `util/effect-zod.ts`, plus the dual `export const Info = zodObject(InfoSchema) + export type Info = DeepMutable<Schema.Type<typeof InfoSchema>>` pattern.
- **Two context systems still coexist**: `util/context.ts` (AsyncLocalStorage `Context.create<T>` for `Instance.provide`, `WorkspaceContext.provide`) and Effect `Context.Service`. Removing the legacy ALS layer is the `INST` track in `specs/effect/todo.md` and is still open.
- **Error handling is ~70% typed**: 53 `Schema.TaggedErrorClass`es, but 62 `class X extends Error` remain (62 `throw new` sites), and several service methods still type their error channel as `unknown` instead of the specific `Schema.TaggedErrorClass` union.
- **No `NamedError` class exists in this repo** (the original upstream `opencode` `NamedError` was never introduced). The pattern is `Schema.TaggedErrorClass` directly.

## What is _missing_ for a complete, regression-free, perfect migration

The team's own specs (`todo.md`, `error-boundaries-plan.md`, `routes.md`, `http-api.md`, `loose-ends.md`, `tools.md`, `facades.md`) already enumerate the remaining work. The gaps fall into nine categories. Below is the consolidated gap inventory grouped by _risk to a "no-regression, no-error-propagation" finish line_:

### Gap 1 — Service error channel typing (high risk for propagation)

Today: ~200 service methods return `Effect.Effect<T, unknown>`. The "unknown" defeats `Effect.catchTag` and forces `instanceof` chains at boundaries (especially `server.ts:182-210`).

Required finish:

- For every service in `migration.md`'s checklist, tighten the method's error type from `unknown` to a domain `Error` union (e.g. `Effect.Effect<SessionInfo, Storage.Error | SessionBusyError>`).
- Replace `Effect.tryPromise` error channels with `Schema.TaggedErrorClass` constructors via `Effect.mapError`/`Effect.catchAll`.
- Audit every `Effect<…, unknown>` and either:
  - narrow to the specific tagged class (preferred), or
  - keep `unknown` only at true I/O boundaries and translate to a tagged error at the next `Effect.fn` boundary.

Files affected: every service file in `src/{account,agent,auth,bus,config,connector*,file,filesystem,format,installation,lsp,mcp,permission,plugin,project,provider,pty,question,session,share,skill,snapshot,storage,tool,util,vcs,worktree}/*` (50+ files).

### Gap 2 — Remaining `class X extends Error` → `Schema.TaggedErrorClass` (high risk for propagation)

The `error-boundaries-plan.md` checklist still lists:

- [ ] `provider/provider.ts` — `ProviderInitError`
- [ ] `mcp/index.ts` — `MCPFailed`
- [ ] `skill/index.ts` — `SkillInvalidError`, `SkillNameMismatchError`
- [ ] `lsp/client.ts` — `LSPInitializeError`
- [ ] `ide/index.ts` — install errors
- [ ] `config/error.ts` / `config/config.ts` / `config/markdown.ts` — config errors
- [ ] `session/prompt.ts` — `agentRequired` `throw new Error("Agent not found: …")` (line 131)
- [ ] `session/processor.ts` — same `agentRequired` throw
- [ ] `worktree/index.ts` — `err.name.startsWith("Worktree")` family in `server.ts:200`
- [ ] `util/user-error.ts` — `UserFacingError` (matched by `cli/error.ts` `FormatError` and TUI toast pipeline)
- [ ] `util/process.ts` — `Process.RunFailedError`

These need to be `Schema.TaggedErrorClass` so `Effect.catchTag` is the single tool, and so the Hono `onError` `instanceof` chain in `server.ts:182-210` shrinks.

### Gap 3 — Hono `onError` chain → boundary mappers (regression risk for HTTP wire shape)

`src/server/server.ts:182-210` uses a single `instanceof` chain (`Session.BusyError`, `Storage.NotFoundError`, `Provider.ModelNotFoundError`, `Vcs.PatchApplyError`, `err.name.startsWith("Worktree")`, `HTTPException`). After Gap 1+2 land:

- Per `error-boundaries-plan.md` § "Remove Domain Knowledge From HTTP Middleware", the route group (or route) is the right place for the `domain → HttpApiError.BadRequest` translation; the middleware becomes a final unknown-defect fallback that logs `Cause.pretty(cause)` and returns a safe `500`.
- The Hono-specific `{ name, data }` legacy wire shape must be preserved where the SDK depends on it (`packages/sdk/openapi.json`); see Gap 9 for the SDK diff risk.

### Gap 4 — Hono routes still default (functional risk for end users)

Per `http-api.md`, the following route groups are **not yet bridged** and run only on Hono today:

- [ ] `POST /provider/:providerID/oauth/authorize`, `POST /provider/:providerID/oauth/callback`
- [ ] `POST /session/:sessionID/init`, `POST /session/:sessionID/share`, `DELETE /session/:sessionID/share`, `POST /session/:sessionID/summarize`
- [ ] `POST /session/:sessionID/message` (streaming prompt), `POST /session/:sessionID/prompt_async`, `POST /session/:sessionID/command`, `POST /session/:sessionID/shell`, `POST /session/:sessionID/permissions/:permissionID`
- [ ] `GET /event` (SSE), `/pty/*` (websocket), `/tui/*` (UI bridge)
- [ ] `POST /sync/start`, `POST /sync/replay`, `POST /sync/history`
- [ ] Remaining Hono `mcp.ts`, `file.ts`, `experimental.ts`, `global.ts`, `mobile.ts`, `session.ts`, `server/server.ts` top-level handlers still need direct `Instance.*` and service-boundary audit per `routes.md`.

The SSE, websocket, and TUI bridge routes need **raw Effect HTTP** rather than `HttpApi` per `http-api.md` Phase 7.

### Gap 5 — OpenAPI/SDK source flip (regression risk for SDK consumers)

`http-api.md` Phase 4 documents the open issues blocking the SDK default flip from Hono → Effect:

- Branded-type `pattern` constraints not propagated (~169 missing).
- Per-property `description` annotations not propagated (~107 missing).
- `Event.*` / `SyncEvent.*` component names differ (Hono dotted vs Effect PascalCase, ~50 differences).
- Component deduper emits numbered duplicates (`Session9`).
- Cosmetic-only diffs (`additionalProperties: false`, `const` vs `enum`, MAX_SAFE_INTEGER `maximum`, `propertyNames`).

Until those are closed, deleting the Hono route implementations will silently change the generated `@nikcli-ai/sdk` types.

### Gap 6 — `util/context.ts` ALS removal (`INST` track in `todo.md`)

The AsyncLocalStorage `Context.create<T>` in `util/context.ts` is the legacy alternative to `InstanceRef` / `WorkspaceRef`. The `todo.md` `INST` track lists:

- [ ] `INST-1` Remove direct `Instance.*` value readers (`tool/repo_overview.ts`, `control-plane/adapters/worktree.ts`, `cli/bootstrap.ts`).
- [ ] `INST-2` Move `InstanceContext` type-only imports.
- [ ] `INST-3` Audit `InstanceState.bind(...)` callbacks (`file/watcher.ts`, `storage/db.ts`, `session/llm.ts`).
- [ ] `INST-4` Classify `AppRuntime.runPromise(...)` re-entry sites (`project/with-instance.ts`, `project/instance-runtime.ts`, `control-plane/adapters/worktree.ts`, `cli/effect-cmd.ts`, ACP, CLI upgrade).
- [ ] `INST-5` Remove `Instance.current` fallback from `InstanceState.context` and `run-service.attach()`.
- [ ] `INST-6` Move `restore`/`bind` to remaining boundary, then delete `project/instance.ts`.

`project/instance.ts` is the deletion target; `effect/bridge.ts` is not (it remains a sanctioned Promise/callback bridge).

### Gap 7 — CLI entry points still on `async/catch` (regression risk for `cli/index.ts`)

`src/cli/index.ts:49-59` still installs `process.on("unhandledRejection")` and `process.on("uncaughtException")` loggers and wraps the top-level yargs command in `try { await cli.parse() } catch (e) { FormatError(e); ... } finally { process.exit() }`. The `unhandledRejection` path is the last line of defense for any fiber that escapes without being joined.

Risk: as more code is migrated to typed errors, a forgotten `Effect.fail` whose fiber is never joined (or a `Promise.all` over a list of effects where one fails) is the new "silent crash" mode. Required finish:

- Pipe every CLI command through a single `AppRuntime.runPromiseExit(Effect.gen(...))` body and inspect `Exit`; convert the success/failure to a CLI exit code.
- Move `unhandledRejection` from a console log to a one-shot `Cause.pretty(cause) → userMessage → UI.error` (use `Effect.runFork` and `Cause.pretty` via a small `installProcessGuards()` helper in `src/effect/process-guards.ts`).
- Migrate `cli/ui.ts`, `cli/network.ts`, `cli/upgrade.ts` to use the `cli/effect/prompt.ts` pattern (already in place for `@clack/prompts`).
- Migrate `cli/cmd/*` handlers so each command body is one `AppRuntime.runPromise(Effect.gen(...))` block (per `routes.md` "Caller templates" § "Plain async CLI or script entrypoints").

### Gap 8 — Bus + storage + log primitive migration (medium risk for thread safety)

- `bus/index.ts:117` still uses `Effect.promise(() => Promise.all(pending).then(() => undefined))` and `GlobalBus.emit` is a Node `EventEmitter`. Switch to `Effect.PubSub` for the in-process `Bus.Service` and acknowledge that `GlobalBus` (cross-instance) cannot be fully Effect-native (it has to escape the runtime).
- `storage/storage.ts` keeps a `withErrorHandling` adapter that wraps `Bun.file().json()` failures as `Storage.NotFoundError` only for `ENOENT`. After Gap 1+2, the typed `Storage.Error` union (`Storage.Error = NotFoundError | ...`) should be the single error channel; the `withErrorHandling` helper should disappear.
- `util/log.ts` already has `Schema.Literals` for the level but is plain TypeScript. Adopt `Effect.logDebug/info/warn/error` + `Logger.replace` so logs flow through the Effect logger pipeline and the same level filter / structured annotations work.
- `util/user-error.ts` should become `Schema.TaggedErrorClass` and the `FormatError` chain should switch to `Effect.catchTag`.

### Gap 9 — SDK regeneration + diff guard (regression risk for SDK consumers)

`packages/sdk/js` is generated by `@hey-api/openapi-ts` from `packages/sdk/openapi.json`. The SDK is **not** Effect-based. The migration must:

- Run `./packages/sdk/js/script/build.ts` after every OpenAPI-touching PR.
- Verify the SDK diff is expected (per `http-api.md` Phase 4) before flipping the source backend.
- Keep `NIKCLI_SDK_OPENAPI=httpapi` opt-in until the Hono vs Effect diffs are closed.

### Gap 10 — Tests still on the old `Effect.runPromise + InstanceScope.with` shape

The skill describes `testEffect` from `packages/opencode/test/lib/effect.ts`; this repo does not have that exact helper. The local helpers are:

- `test/helpers/test-effect.ts` — `makeTestRuntime(label, layer)`
- `test/helpers/effect-test.ts` — `runExit`

Per `specs/effect/todo.md` P1 (`TEST`) and `test/EFFECT_TEST_MIGRATION.md`:

- Use `testEffect(...)` with explicit layers.
- Prefer `it.instance(...)` for service tests.
- Prefer `it.live(...)` for real timers/filesystem/child processes.
- Avoid sleeps; wait on real events.
- Convert touched tests to the ideal pattern; do not mutate `process.env` or globals.

Required finish: align the local helper names with the house style (`testEffect` is the desired entry point) and migrate the ~50+ service tests that still use `Effect.runPromise(InstanceScope.with(...))` directly to use `testEffect(...)` and `provideInstance(...)`.

## What the "perfect" finish line looks like

A complete, regression-free migration would satisfy all of the following simultaneously:

1. **No `Effect<…, unknown>`** for any service-method-level effect (only at true I/O seams, translated immediately).
2. **No `class X extends Error`** for expected domain failures — every expected failure is a `Schema.TaggedErrorClass` exported from a `Namespace.Error` union.
3. **No `throw` inside `Effect.gen`/`Effect.fn`** for expected failures (use `Effect.fail`/`yield* new XError(...)`); `throw` is reserved for defects (`Effect.die`).
4. **No `instanceof` chain in `server.ts:182-210`** — replaced by per-route `Effect.catchTag(...)` + a generic `HttpApiError` (or `Schema.ErrorClass` with `httpApiStatus`) declared in the route group, plus a final `Cause.pretty(cause)` 500 fallback.
5. **No `util/context.ts` ALS** — `Instance.provide` and `WorkspaceContext.provide` are gone; every caller uses `InstanceRef`/`WorkspaceRef` or `InstanceState.context`.
6. **No Hono default backend** — `NIKCLI_EXPERIMENTAL_HTTPAPI` default flips, the regex bridge stays as a short-lived fallback, then the bridge is deleted.
7. **No SDK diff** between Hono-sourced and Effect-sourced OpenAPI for the same routes.
8. **No `try { await runXxx } catch (e) { FormatError(e) }`** in CLI commands — each command body is one `AppRuntime.runPromiseExit(Effect.gen(...))` and renders failures with `FormatError` (or a typed per-error render helper).
9. **No manual `Effect.tryPromise(...)` wrappers around service methods** — the façade pattern is gone; the test layer is `Service.defaultLayer` directly with `Effect.provide` (per `facades.md` "Pitfalls" #2).
10. **No `unhandledRejection` swallowed errors** — fiber failures are joined or interrupt; the `Effect.cause` is rendered and the process exits with a meaningful code.
11. **All tests are `testEffect`/`it.live`/`it.instance`** with explicit layers; no `process.env` mutation; no raw `fs`/`Bun.write` in tests (use `AppFileSystem.Service` + `tmpdirScoped()`).
12. **No plain `Schema.Unknown` / `z.any` in route response bodies** — every route response schema is `Schema.Struct(...)` with a named identifier.
13. **No Promise-style `await` inside tool bodies** — every tool body is `Effect.gen(...)` and uses `yield* AppFileSystem.Service`/`HttpClient.HttpClient`/`ChildProcessSpawner.ChildProcessSpawner` instead of raw `fs`/`fetch`/`spawn` (per `tools.md` "Follow-up cleanup").

## Migration plan (vertical slices, no regressions)

The migration is large enough to need vertical slices. The order below minimizes the risk of regressing the public surface at each step. Every step has its own verification gate.

### Phase A — Error typing (foundation; no behavior change)

For each service in `migration.md`'s checklist that still returns `Effect<…, unknown>`:

1. Add a `Schema.TaggedErrorClass` for each `throw new XError(...)` and `Effect.fail(new Error(...))` inside the service.
2. Export the union as `Namespace.Error`.
3. Narrow the method signatures: `Effect.Effect<…, Namespace.Error>`.
4. Map external failures via `Effect.mapError` / `Effect.catchAll` to the typed class.
5. Update tests to assert on `Exit.Failure` and `Effect.flip(...)` with the typed tag.

Verification: `bun run typecheck` from `packages/nikcli`, plus per-service `test/{service}/effect-service.test.ts`.

### Phase B — Domain → HTTP boundary mappers (no behavior change)

For each of the 53 `Schema.TaggedErrorClass`es (and the new ones from Phase A):

1. Add a tiny shared helper in `src/server/routes/instance/httpapi/errors.ts` (per `error-boundaries-plan.md`): `notFound(msg)`, `badRequest(msg)`, `unknown()`.
2. Replace the Hono `onError` `instanceof` chain entries one-by-one with per-route `Effect.catchTag` handlers that produce the public HTTP error body (preserving the legacy `{ name, data }` shape where the SDK depends on it).
3. End-state: the Hono `onError` is a thin final fallback that logs `Cause.pretty(cause)` and returns 500; no domain knowledge.

Verification: `bun test test/server/httpapi-*.test.ts` + `bun test test/server/httpapi-bridge.test.ts` (the bridge already exercises both the Hono path and the Effect path).

### Phase C — `util/context.ts` retirement (no behavior change)

Follow `todo.md` `INST-1` through `INST-6`:

- `INST-1` remove direct `Instance.*` value readers (yield from `InstanceRef`).
- `INST-2` move `InstanceContext` to `project/instance-context.ts`.
- `INST-3` audit each `InstanceState.bind(...)` callback and replace ALS capture with explicit provision.
- `INST-4` classify `AppRuntime.runPromise(...)` re-entry sites.
- `INST-5` remove `Instance.current` fallback from `InstanceState.context` and `run-service.attach()`.
- `INST-6` move remaining `restore`/`bind` to the boundary that needs it, then delete `project/instance.ts`.

Verification: full `bun run typecheck` + `bun test test/effect/instance-scope.test.ts` + the full session/bus/service suites.

### Phase D — Finish Hono route bridging (per `http-api.md`)

1. Add the missing route slices to `src/server/httpapi/`:
   - `provider.ts` OAuth start/callback
   - `session.ts` init/share/summarize/prompt/command/shell
   - `experimental.ts` console + global session list
   - `sync.ts` (depends on `Sync.Service` — see `todo.md` "Sync")
2. Add tests in `test/server/httpapi-*.test.ts`.
3. Update `src/server/httpapi/bridge.ts` allowlist to route these through `HttpApiBuilder.toWebHandler`.
4. Keep SSE/websocket/TUI bridge routes on Hono for now (raw Effect HTTP plan in `http-api.md` Phase 7).

Verification: per-slice tests + bridge tests + the existing `test/server/httpapi-bridge.test.ts` keeps passing.

### Phase E — SDK/OpenAPI source flip (regression-sensitive)

Per `http-api.md` Phase 4:

1. Close the `pattern`/`description` propagation gap in the Effect OpenAPI output (the `Schema.annotate` flow is the lever).
2. Close the `Event.*` / `SyncEvent.*` naming gap (introduce a component-name strategy in `httpapi/public.ts`).
3. Fix the dedup collision in `httpapi/public.ts`.
4. Re-run `bun run --conditions=browser ./src/index.ts generate --httpapi` to produce an alternative OpenAPI.
5. Diff against `packages/sdk/openapi.json` produced by the Hono path; commit a per-route-group diff log.
6. Flip `packages/sdk/js/script/build.ts` default to `httpapi` once per-route diffs are zero.

Verification: `bun run test:ci` and the SDK build script.

### Phase F — Backend default flip + Hono deletion (per `http-api.md` Phases 5-6)

1. Add `server/backend.ts` selecting `hono` | `effect-httpapi` at startup.
2. Keep `NIKCLI_EXPERIMENTAL_HTTPAPI` as a short-lived fallback flag.
3. Run all tests against both backends.
4. Delete the Hono route implementations per the Hono Deletion Checklist (`http-api.md` §70).
5. Special routes (`event`/`pty`/`tui`) get raw Effect HTTP implementations (Phase 7) or stay deleted with Hono.

Verification: full test suite against both backends; SDK output unchanged.

### Phase G — CLI entry effectification (no behavior change)

1. Migrate `cli/index.ts` to use `AppRuntime.runPromiseExit(Effect.gen(...))` for the top-level yargs command.
2. Add `src/effect/process-guards.ts` with `installProcessGuards()` that pipes `process.on("unhandledRejection")` and `uncaughtException` into `Effect.cause` → `Cause.pretty(cause)` → `UI.error` + `process.exitCode = 1`.
3. Migrate `cli/ui.ts`, `cli/network.ts`, `cli/upgrade.ts` to use the `cli/effect/prompt.ts` pattern.
4. For each `cli/cmd/*` handler, wrap the body in one `AppRuntime.runPromise(Effect.gen(...))` (per `facades.md` "Plain async CLI or script entrypoints").

Verification: `bun test test/cli/...` and a smoke test of `bun run dev` end-to-end.

### Phase H — Tool bodies, bus, storage, log, user-error (no behavior change)

Per `tools.md`, `loose-ends.md`, and Gap 8:

1. Convert each tool body to `Effect.gen(...)`; yield `AppFileSystem.Service` / `HttpClient.HttpClient` / `ChildProcessSpawner.ChildProcessSpawner` instead of raw `fs`/`fetch`/`spawn`.
2. Switch `bus/index.ts` in-process subscribers to `Effect.PubSub`; keep `GlobalBus` as the cross-instance escape hatch.
3. Remove the `withErrorHandling` helper from `storage/storage.ts`; use the typed `Storage.Error` channel directly.
4. Convert `util/log.ts` to `Effect.logDebug/info/warn/error` + `Logger.replace`.
5. Convert `util/user-error.ts` to `Schema.TaggedErrorClass`; update `FormatError` and TUI toast pipeline to `Effect.catchTag`.

Verification: per-tool tests + `test/bus/effect-service.test.ts` + `test/storage/effect-service.test.ts`.

### Phase I — Test infrastructure alignment

1. Rename `test/helpers/test-effect.ts` (`makeTestRuntime`) and `test/helpers/effect-test.ts` (`runExit`) to a single `testEffect(...)` helper that matches the house style in the skill.
2. Migrate the ~50 tests that still use `Effect.runPromise(InstanceScope.with(...))` directly to use `testEffect(...)` and `provideInstance(...)` per `EFFECT_TEST_MIGRATION.md`.

Verification: `bun run test:ci` with no test regressions.

### Phase J — Final consolidation (no behavior change, but cuts the last legacy seams)

1. Remove all `Effect<…, unknown>` in service methods (only `never` or specific tagged errors remain).
2. Remove all `class X extends Error` for expected failures.
3. Remove all `makeRuntime(...)` service-local facades (already done per `facades.md`).
4. Remove `util/context.ts` and `project/instance.ts` (after `INST-6`).
5. Remove `util/effect-zod.ts`'s legacy bridges once all schemas are `Schema.Struct` (optional, only when the SDK is fully on the Effect OpenAPI source).
6. Remove the `cli/effect/prompt.ts` shim once all CLI commands are on the unified `AppRuntime.runPromise(...)` body.

6. `bun test test/effect/instance-scope.test.ts test/bus/effect-service.test.ts test/storage/effect-service.test.ts test/session/effect-service.test.ts` for the core effects.
