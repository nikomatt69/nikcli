## What I would integrate, in this order

### 1. S2 — continue sessions after a graceful restart

**Landed 2026-08-14.** Private nullable `session_info.time_suspended` with a partial index; `serve` suspends running sessions before abort, and the next server claims each row once with `UPDATE … RETURNING`. See [specs/v2/session-restart-continuation.md](../../specs/v2/session-restart-continuation.md). Hard crashes remain out of scope.

### 2. S1 — durable pending input

**Spec:** `specs/v2/session.md` §"Admission Precedes Execution" — needs its own decision record before code.
**Why second:** this is the product unlock, and it is the precondition for S4 and any serious recovery.

Today `SessionPrompt.admit` writes the user message straight into visible history. There is no `session_pending` row, no promotion transaction, no `steer` / `queue` delivery mode. A second caller joins the active loop via `PromptState` callbacks and receives the owner's result. Compaction cannot actually block input.

What this buys the user:

- steer a running turn at the next safe step
- queue a follow-up that waits for idle
- a compaction barrier that is real

Do not start S4 (v2 write path) before this. Without it the new engine reimplements the old limits.

### 3. T2 — tool output schemas

**Landed 2026-08-14.** A tool may declare an `output` zod codec; `Tool.define` parses `result.value` after execute; Code Mode receives `Tool.encoded(result, codec)`. Truncation still bounds only the model-facing string. Built-ins were not converted. See [specs/v2/tools.md](../../specs/v2/tools.md).

### 4. D2 remainder — leftover JSON consumers (steps 4–5)

**Spec:** `specs/storage/remove-json-storage.md` — steps 1–3 landed 2026-08-14. Do **not** start this from Horizon 1.

The four domain managers are SQL (`MissionRepo` / `MonitorRepo` / `ShareRepo` / `ArtifactRepo`, migration `20260814020000_domain_sql`). What remains is the derived-cache / ephemeral / project-workspace group. Each remaining module needs a move-or-delete decision before code; prefer deleting a cache that a query could replace. Do not delete `storage/storage.ts` until those decisions exist and the last production import is gone.

### 5. P1 — provider policy

**Landed 2026-08-14.** `Policy` in `src/policy/policy.ts` is the evaluator. Legacy `enabled_providers` / `disabled_providers` translate with denylist last. HTTP, CLI auth, and session auth list through `Policy.filter`. TUI disconnect appends a `deny` statement. See [specs/v2/provider-policy.md](../../specs/v2/provider-policy.md).
