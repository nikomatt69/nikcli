# Piano di aggiornamento completo delle dipendenze

## Obiettivo e perimetro

Aggiornare tutte le dipendenze del repository alle release correnti compatibili al momento dell'esecuzione, inclusi major version, runtime/toolchain Bun e TypeScript, pacchetti npm di ogni manifest, Expo/React Native, Tauri/Cargo, Nix, immagini Docker e GitHub Actions. Le prerelease restano ammesse solo dove il progetto le usa gia intenzionalmente; se esiste una release stabile supportata, il piano migra a quella. Ogni gruppo deve essere aggiornato, migrato e verificato separatamente prima di procedere, cosi da evitare un aggiornamento big-bang e rendere ogni regressione attribuibile e reversibile.

## Gate anti-regressione

Ogni coorte deve superare, in quest'ordine:

1. **Risoluzione:** install pulito e `bun install --frozen-lockfile` al root e nei package con lock indipendente; nessun peer warning non spiegato, patch applicata alla versione esatta, lock deterministico su seconda esecuzione.
2. **Statico:** `bun run typecheck`, `bun turbo typecheck`, lint e format check; `cargo check --locked` per i due crate.
3. **Unit/integration:** `bun turbo test`, `bun run test` e `bun run test:integration` in `packages/nikcli`, test LLM replay, app/UI, inference e package coinvolte. I test marcati non-critical in `script/ci-validate.ts` vanno comunque eseguiti separatamente come gate obbligatori.
4. **Build/codegen:** `bun turbo build`, build CLI, app/web/console/dashboard/desktop/mobile, SDK generation con diff revisionato, Docker e Nix.
5. **Behavioral:** strict route coverage, CLI `--help`/`--version`, server health, provider/tool streaming replay, app Playwright, browser/terminal/computer-use smoke, Expo simulator e Tauri native smoke.
6. **Cross-platform:** workflow Linux e Windows completa, windows-compat, desktop six-target e Nix matrix. Una coorte nativa non e conclusa con il solo risultato macOS locale.
7. **Sicurezza:** audit delle dipendenze e review di lifecycle scripts, trusted dependencies, nuovi binari, nuove licenze e cambi di permessi/binding.

Al primo gate fallito: fermare la coorte, identificare la prima versione/call site che rompe, aggiungere o rafforzare un test riproduttore, correggere la migrazione e rieseguire l'intera sequenza della coorte. Non saltare, indebolire o silenziare test; se serve rollback, ripristinare solo i file della coorte senza toccare modifiche preesistenti dell'utente.

## Verifica finale e definition of done

- `bun outdated --recursive` e gli audit eseguiti nei package non-workspace non mostrano aggiornamenti residui, salvo pin temporanei esplicitamente documentati con evidenza e test.
- `cargo outdated` non mostra release stabili residue e `cargo update --dry-run` non propone update compatibili sui due manifest; manifest/lock sono coerenti e i check cross-target passano.
- Tutti i manifest, catalog/override, patch, lock Bun/Cargo/Nix, Docker tag e Action refs dell'inventario iniziale hanno un esito registrato; nessuna dipendenza e stata omessa perche transitive, annidata o fuori dal workspace principale.
- Il CI validation runner termina verde, ma la chiusura richiede anche i test che esso classifica non-critical, la matrix completa di `.github/workflows/test.yml`, `.github/workflows/windows-compat.yml`, `.github/workflows/desktop-release.yml` e i build Nix/container.
- SDK/codegen e tipi generated sono riproducibili; una seconda generazione non produce diff.
- Confronto baseline/finale: stesso o maggior numero di test eseguiti, nessuna route persa, nessun nuovo warning peer, nessuna regressione nei flussi CLI/server/app/mobile/desktop e nessun file utente estraneo incluso.
