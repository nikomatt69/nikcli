**Obiettivo:** Correggere bug e incoerenze emersi dall’audit di `src/cli`, con ogni modifica allineata a pattern esistenti, coperta da verifica (`bun run typecheck`, test mirati, smoke CLI).

## Principi anti-regressione

| Regola                                                                                                         | Motivo                                                                                     |
| -------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| Ogni handler che usa `Instance.*` → `bootstrap(cwd, …)` o `withInstanceAsync({ directory: process.cwd() }, …)` | `Instance.project` chiama `context.use()` (`instance.ts` L84–86)                           |

| TUI server boot: **non** argv-only; estrarre helper da `ResolvedNetworkConfig`                                 | `network.test.ts` garantisce config→hostname; argv-only rompe `server.mdns` / hostname LAN |
| Nessun `xfail`, nessuna assertion indebolita                                                                   | Obiettivo è fix, non mascherare                                                            |

## Fase 1 — Critical (PR 1, batch piccolo)

### 1.1 `nikcli sync connect` — instance + lifecycle

**File:** `src/cli/cmd/sync.ts`

**Problema:** `Instance.project.id` senza instance (L47); `await new Promise(() => {})` rende `handle.stop()` irraggiungibile (L52–53).

**Edit (pattern verificato — allineato a `pr.ts` + `remote.ts` keepMobileHostAlive):**

```ts
await withInstanceAsync({ directory: process.cwd(), init: InstanceBootstrap }, async () => {
  const remote = await readRemote()
  if (!remote) {
    /* messaggio + return */ return
  }
  const handle = await RemoteSync.start({
    url: remote.url,
    token: remote.token,
    projectID: Instance.project.id,
  })
  console.log(`connected to ${remote.url} (project ${Instance.project.id})`)
  console.log("press Ctrl-C to disconnect")
  await new Promise<void>((resolve) => {
    let closing = false
    const close = () => {
      if (closing) return
      closing = true
      process.off("SIGINT", close)
      process.off("SIGTERM", close)
      void handle.stop().finally(resolve)
    }
    process.once("SIGINT", close)
    process.once("SIGTERM", close)
  })
})
```

- Import: `withInstanceAsync` da `@/effect`; `InstanceBootstrap` da `@/project/bootstrap` (come `pr.ts`).
- **`init: InstanceBootstrap`** allinea DB/plugin e può avviare `initRemoteSyncFromEnv` se autostart è on — `RemoteSync.start` è **idempotente** per `(url, projectID)` (`cli-init.ts` L8–9); nessuna doppia connessione attesa.
- `connect` resta **esplicito** anche con `sync.autostart: false` (a differenza del solo bootstrap).
- **Nota prodotto:** TUI `POST /sync/connect` usa `startForAllProjects`; CLI usa `Instance.project.id` — possibile divergenza vs `sdk.directory` in stats TUI (documentare, non fix in Fase 1).

**Verifica:**

- `bun run typecheck`
- Smoke manuale (solo se hub configurato): `nikcli sync connect` non deve throw su `context.use`; Ctrl+C deve uscire senza hang zombie (opzionale: log `remote sync` stop).
- Unit: aggiungere `test/cli/sync-connect.test.ts` con mock di `RemoteSync.start` + spy `bootstrap` **oppure** test integrazione leggero che verifica il handler è wrappato (grep strutturale) — minimo: test che esporta helper `runSyncConnect` se si estrae per testabilità.

**Rischio regressione:** Basso se si copia lifecycle da `remote.ts` `keepMobileHostAlive` (L455–468).
