# Fix: String.prototype.repeat RangeError in dialog-analytics.tsx

## Root Cause

In the `HBar` component (line 289), when `props.max` is `0` (e.g. a fresh session with zero tokens), `filled()` computes `Math.max(1, Math.floor((0 / 0) * 25))` → `Math.max(1, NaN)` → `NaN`. However, the more common trigger is when `props.value > 0` and `props.max === 0`, which yields `Infinity` → `Math.floor(Infinity)` → `Infinity` → `Math.max(1, Infinity)` → `Infinity`.

`String.prototype.repeat(Infinity)` throws: `RangeError: String.prototype.repeat argument must be greater than or equal to 0 and not be Infinity`.

Additionally, `props.width - filled()` on line 303 would become `NaN` or negative `Infinity`, causing a second `.repeat()` failure for the empty portion of the bar.

## Fix

**File**: `src/cli/cmd/tui/component/dialog-analytics.tsx`

### Change 1: `HBar` component — clamp `filled()` (line 291)

```tsx
// Before:
const filled = createMemo(() => Math.max(1, Math.floor((props.value / props.max) * props.width)))

// After:
const filled = createMemo(() => {
  if (props.max <= 0 || !Number.isFinite(props.max)) return 0
  return Math.min(props.width, Math.max(0, Math.floor((props.value / props.max) * props.width)))
})
```

This:

- Returns `0` when `max` is zero/negative/NaN (no bar drawn)
- Clamps to `[0, props.width]` so `filled()` is always safe for `.repeat()`
- `props.width - filled()` on line 303 is also always ≥ 0

### Change 2: `StackedBarChart` — guard last segment (line 251)

```tsx
// Before:
const w = i === props.segments.length - 1 ? remaining : Math.max(1, Math.floor((s.value / t) * props.width))

// After:
const w =
  i === props.segments.length - 1 ? Math.max(0, remaining) : Math.max(1, Math.floor((s.value / t) * props.width))
```

This prevents a negative `remaining` from producing a negative width for the last segment.
