# Critical Bugs Fix Plan

## Summary

This plan addresses **CRITICAL**, **HIGH**, and **MEDIUM** priority bugs in the nikcli codebase. The fixes involve missing awaits, security issues, resource leaks, and code quality improvements.

---

## CRITICAL Bugs (Fix Immediately)

### 1. Missing await - share() + update() not awaited

**File:** `src/session/index.ts:305-314`

```typescript
// BUGGY (lines 305-314):
if (!result.parentID && (Flag.NIKCLI_AUTO_SHARE || cfg.share === "auto"))
  share(result.id)
    .then((share) => {
      return update(result.id, (draft) => {
        draft.share = share
      })
    })
    .catch(() => {
      // Silently ignore sharing errors during session creation
    })
```

**Problem:** Fire-and-forget pattern - session is returned before `share()` and `update()` complete, causing potential race conditions.

**Fix:**

```typescript
if (!result.parentID && (Flag.NIKCLI_AUTO_SHARE || cfg.share === "auto"))
  void share(result.id)
    .then((share) => {
      return update(result.id, (draft) => {
        draft.share = share
      })
    })
    .catch((error) => {
      log.debug("sharing failed during session creation", { error: String(error) })
    })
```

```typescript

  // This check is after accessing .info
```

**Problem:** The code accesses `userMessage.info.id` in the callback (line 103) before checking if `info` exists. If any message has undefined `info`, the callback throws.

Also fix the type assertion:


### 5. Resource leak - file.stat().catch(()=>{}) hides errors

**File:** `src/tool/edit.ts:71`

```typescript
// BUGGY (line 71):
const stats = await file.stat().catch(() => {})
if (!stats) throw new Error(`File ${filePath} not found`)
```

**Problem:** All errors are swallowed including permission errors, not just "file not found".

**Fix:**

```typescript
const stats = await file.stat().catch((error) => {
  if (error?.code === "ENOENT" || error?.code === "ENOTDIR") {
    return null
  }
  throw error
})
```

**File:** `src/tool/grep.ts:54-73`

```typescript
// BUGGY (lines 54-73):
const proc = Bun.spawn([rgPath, ...args], {

const output = await new Response(proc.stdout).text()

if (exitCode === 1 || (exitCode === 2 && !output.trim())) {
```

**Problem:** Process not explicitly killed on early return paths.

**Fix:**

```typescript
const proc = Bun.spawn([rgPath, ...args], {
  stdout: "pipe",
  stderr: "pipe",

try {
  const output = await new Response(proc.stdout).text()
  const errorOutput = await new Response(proc.stderr).text()
  const exitCode = await proc.exited

  if (exitCode === 1 || (exitCode === 2 && !output.trim())) {
    return { ... }
  }
  // ... rest of code
} finally {
  proc.kill()
}
```

### 8. OOM risk - reads entire file for binary check

**File:** `src/tool/read.ts:186-202`

```typescript
// BUGGY (lines 186-202):
const bufferSize = Math.min(4096, fileSize)
const buffer = await file.arrayBuffer() // Loads entire file!
if (buffer.byteLength === 0) return false
const bytes = new Uint8Array(buffer.slice(0, bufferSize))
```

**Problem:** `file.arrayBuffer()` reads the entire file into memory. For large files, this causes OOM.

**Fix:**

```typescript
// Use Bun's slice capability to read only what's needed
const buffer = await file.slice(0, bufferSize).arrayBuffer()
```

### 10. Path traversal possible

**File:** `src/server/routes/file.ts:140-143`

```typescript
// BUGGY (lines 140-143):
;async (c) => {
  const path = c.req.valid("query").path
  const content = await File.list(path)
  return c.json(content)
}
```

**Problem:** User-provided `path` is not validated against traversal attacks.

**Fix:** Add path validation:

```typescript
import * as path from "path"

;async (c) => {
  const requestedPath = c.req.valid("query").path
  const normalized = path.normalize(requestedPath)
  const resolved = path.isAbsolute(normalized) ? path.resolve(normalized) : path.resolve(Instance.directory, normalized)

  // Ensure resolved path is within Instance.directory
  if (!resolved.startsWith(Instance.directory)) {
    return c.json({ error: "Path traversal denied" }, 403)
  }

  const content = await File.list(resolved)
  return c.json(content)
}
```

## MEDIUM Bugs (Good Practice)

### 14. Empty catch blocks

**Files:** 129 locations with `} catch {` pattern

**Strategy:** Replace empty catch blocks with logging. Since there are many files, prioritize security-sensitive and error-prone areas:

**Priority files to fix:**

1. `src/server/server.ts` (lines 271, 826) - Server error handling
2. `src/session/message-v2.ts` (lines 757, 874) - Session handling
3. `src/plugin/copilot.ts` (lines 77, 137) - Plugin errors
4. `src/pty/index.ts` (lines 79, 184, 223) - PTY errors
5. `src/mobile/expo.ts` (multiple) - Mobile errors
6. `src/storage/storage.ts` (line 223) - Storage errors

**Fix pattern:**

```typescript
// Before:
} catch {}

// After:
} catch (error) {
  log.debug("operation failed", { error: String(error) })
}
```

Note: For truly ignorable errors (like cleanup that doesn't affect functionality), use `void` or explicit no-op with logging at debug level. For errors that should be visible, use `log.warn()`.
