# Piano: rifinitura docs (`packages/web/src/pages/docs`)

## Contesto

- **26 pagine** Astro in `packages/web/src/pages/docs/*.astro` (file-based routing → `/docs/...`).
- **Shell condivisa**: `packages/web/src/layouts/DocsLayout.astro`, `packages/web/src/styles/docs.css`, sidebar `packages/web/src/data/docsSidebar.ts`, componenti `packages/web/src/components/docs/*`.
- **Pattern attuale**: frontmatter con `toc`, `DocsLayout` (title/subtitle/description SEO), sezioni `<section id="..." class="mb-16 scroll-mt-24">`, mix di `DocCard`, `DocCallout`, `DocCode`, tabelle `doc-table`.
- **Nessun i18n** sul sito docs; copy in inglese.
- **Nota repo**: sotto `packages/web/src/pages/docs` non devono comparire copie del monorepo `nikcli` (il glob ha trovato path anomali tipo `.../docs/src/...` — da verificare in implementazione: se sono symlink/artefatti, ripulire o escludere dal deploy; le pagine da rifinire sono solo i `.astro` in quella cartella).

## Obiettivo (interpretazione «rifinisci tutto»)

Rendere le docs **coerenti visivamente**, **accurate rispetto al runtime** (`packages/nikcli`), **più navigabili** e **più facili da mantenere**, senza riscrivere da zero contenuti lunghi già solidi (architecture, cli, mobile, tui, source-map).

**Assunzione** (se vuoi solo UI o solo contenuti, restringiamo in fase build): scope **completo** = UI + contenuti + struttura leggera.

## Problemi rilevati

| Area                 | Problema                                                                                                                                                                  |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Coerenza layout**  | `index.astro` usa `sm:mb-20 sm:scroll-mt-28` sulle sezioni; quasi tutte le altre solo `scroll-mt-24`. `docs.css` già imposta `scroll-margin` su `h2` — ridondanza/deriva. |
| **Pagine «sottili»** | `cli-debug.astro`: solo tabelle, niente intro, callout, link a LSP/debug nel codice.                                                                                      |
| **Agenti**           | Manca `support` (definito in `packages/nikcli/src/agent/agent.ts`, hidden, read-only docs assistant).                                                                     |
| **Tools**            | `tools.astro` ha indice manuale `toolIndex[]` — rischio drift vs `registry.ts` / nuovi tool (`goal`, `exec_code`, ecc. già elencati; va verifica sistematica).            |
| **Cross-link**       | Poche «Next / Related» in fondo pagina; hub `index.astro` buono ma non tutte le pagine rimandano a Configuration / CLI / Architecture.                                    |
| **Manutenibilità**   | Liste lunghe duplicate (source-map directories, tool index, tabelle CLI) senza modulo condiviso.                                                                          |
| **Qualità copy**     | Mix «Nikcli» / «nikcli» nei `description` meta; alcune pagine senza `DocCallout` dove servirebbe (warn/info operativi).                                                   |
| **Build**            | `packages/web` non ha script `typecheck`/`lint` in `package.json` — verifica via `bun run build` in `packages/web`.                                                       |

## Strategia in 4 fasi

### Fase 1 — Design system docs (basso rischio, alto impatto)

1. **Classe sezione unica** in `docs.css`, es. `.doc-section` = `mb-16 scroll-mt-24` (+ eventuale variante responsive come index).
2. **Sostituire** classi ripetute su tutte le 26 pagine (meccanico, search-replace controllato).
3. **Griglie**: standardizzare su `grid grid-cols-1 gap-6 md:grid-cols-2 md:gap-8 my-8` (come `index.astro`) dove oggi c’è solo `gap-6 my-8`.
4. **Componente opzionale** `DocSection.astro` (`id`, `title` slot) — solo se riduce duplicazione senza appesantire; altrimenti restare su classe CSS.

**File**: `packages/web/src/styles/docs.css`, tutti `packages/web/src/pages/docs/*.astro`, eventualmente `packages/web/src/components/docs/DocSection.astro`.

### Fase 2 — Contenuti e accuratezza (campione + pagine critiche)

1. **Agents** (`agents.astro`): aggiungere card/callout per agente `support` (hidden, invocato da dialog `/support`, read-only, doc index).
2. **Tools** (`tools.astro`):
   - Confrontare `toolIndex` con export/registrazione in `packages/nikcli/src/tool/registry.ts` e file in `packages/nikcli/src/tool/`.
   - Aggiornare descrizioni, rimuovere tool obsoleti, segnare tool dietro flag (`lsp`, `batch`, `scout` env).
   - _(Opzionale ma consigliato)_ script di build/check in `packages/web/script/` che legge registry e fallisce se l’indice docs è stale — evita drift futuro.
3. **CLI debug** (`cli-debug.astro`): intro breve, link a `/docs/cli` e `/docs/lsp`, 1–2 `DocCallout` (quando usare `debug doctor` vs `debug config`), esempi `DocCode` per comandi frequenti.
4. **Pass mirato** su pagine «entry» per utenti nuovi: `configuration.astro`, `web-app.astro`, `routines.astro` — verificare path comandi e endpoint citati contro `packages/nikcli/src/cli/cmd/` e `packages/nikcli/src/server/`.

Non riscrivere per intero `architecture.astro`, `mobile.astro`, `tui.astro` salvo errori puntuali trovati in verifica.

### Fase 3 — Navigazione e SEO

1. **Componente** `DocRelated.astro` (2–4 link fissi per «famiglia» di pagina) o blocco markup ripetuto in fondo — collegare Core ↔ Systems ↔ Reference.
2. **Allineare** `title`/`description` su pattern: «{Topic} - Nikcli Docs» lato layout già ok; uniformare `description` prop (frase unica, keyword coerenti, branding `nikcli` minuscolo nel body).
3. **Sidebar** (`docsSidebar.ts`): ordine e label già ok; eventuale raggruppamento «Automation» (Routines/Loops/Missions) solo se migliora scansione — evitare churn inutile.

### Fase 4 — Pulizia repo e verifica

1. Verificare assenza di tree `packages/web/src/pages/docs/src` (o simili) nel workspace; se presente, rimuovere/spostare fuori da `pages/docs` (non deve finire in routing Astro).
2. `bun run build` in `packages/web`.
3. Smoke manuale: `bun run dev` in `packages/web`, aprire `/docs`, `/docs/cli-debug`, `/docs/tools`, `/docs/agents`; mobile sidebar + TOC attivo; theme light/dark.
4. Se esiste `replace_classes.js` o script one-off per classi docs, integrare in script ufficiale o eliminare se obsoleto.
