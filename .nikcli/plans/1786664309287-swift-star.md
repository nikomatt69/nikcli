# Specs Roadmap

## Assessment

The specs are intentionally a decision record plus an ordered roadmap, not a feature backlog. As of 2026-08-14, the largest foundations have landed: one central SQLite/Drizzle runtime and migration journal, SQL-backed core and domain state, one Effect HttpApi surface, one durable sync/event log, graceful restart continuation, scoped instance reload, stable tool advertisement, and bounded SSE fan-out. The remaining work is concentrated in a small number of contracts and two larger structural migrations.

## Recommended Order

### 1. Close the JSON-storage tail

- Reconcile every remaining Storage consumer listed in specs/storage/remove-json-storage.md into either a SQL-backed durable record, a query replacing a derived cache, or explicitly process-local ephemeral state.
- Decide the fate of session/stats.ts, analytics/\*, cli/cmd/{stats,usage}.ts, tool/memory_search.ts, PTY/background/routine state, and project/workspace JSON before coding.
- Prefer deletion for recomputable caches; do not introduce read-through fallbacks after a domain moves.
- Finish by deleting src/storage/storage.ts and src/storage/effect.ts once no production imports remain.
- Verify migration idempotence/backfill, journal assertions, no production Storage imports, and database/type/unit suites.

### 2. Define and implement durable pending input (S1)

- Add a focused decision record for admission, steer, queue, compaction barriers, promotion, interruption, retries, and duplicate message identity.
- Add session_pending plus an atomic promotion transaction at safe step boundaries.
- Preserve current single-flight process ownership while making pending input durable; keep hard-crash recovery out of scope until execution ambiguity is designed.
- Verify steering/queue ordering, coalesced promotion, step-budget reset once per batch, interrupted-turn preservation, concurrent callers, and restart behavior.

### 3. Unify provider policy (P1)

- Add ordered allow/deny statements with wildcard and last-match-wins evaluation.
- Translate legacy enabled_providers/disabled_providers at config load, preserving current precedence and default behavior.
- Move provider catalog and all listed HTTP/auth/session/TUI consumers to the catalog/policy instead of duplicating checks; make the TUI write policy statements.
- Add compatibility fixtures for legacy configs, mixed allow/deny cases, wildcard matching, and config reload.

### 4. Add typed tool output (T2)

- Extend the tool definition with an optional output codec/value while preserving the existing model-facing string and metadata behavior.
- Encode validated machine values into Code Mode and reject malformed successes at the registry/runtime boundary.
- Keep tools without an output codec backward compatible and preserve truncation, attachments, cancellation, permissions, and per-call failure isolation.
- Verify built-in/plugin tools, malformed output, Code Mode typing, and serialized tool advertisement stability.

### 5. Persist instruction deltas (S3)

- Land instruction_blob and instruction_state, then emit one hash delta at each safe step boundary.
- Switch request assembly to stored values with epoch handling across compaction, movement, revert, and fork; only afterward optimize hash-first file reads.
- Treat initial unavailable sources as blocking, later unavailable sources as retaining the last value; never persist rendered prose.
- Add security tests for source scoping, URL failures/timeouts, content-addressed blobs, redaction/leakage, event ordering, and compaction/fork semantics.
- This follows S1 because both rely on safe-boundary machinery.

### 6. Swap SessionV2 writes to the v2 engine (S4)

- Move create/prompt writes from v1 services to direct entry writes only after pending-input semantics are stable.
- Keep MessageV2 authoritative for the LLM layer and make the v1 projection derived.
- Verify retries, aborts, compaction, tools, permissions, snapshots, restart continuation, API compatibility, and no duplicate durable events.

### 7. Extract the TUI package (U1)

- Extract shared infrastructure first, close the tool-rendering seam, and replace genuine backend imports with SDK/API boundaries.
- Create packages/tui with no imports resolving into packages/nikcli; keep CLI startup, auth, instance binding, and server bootstrap in the host.
- Add the second consumer only after standalone packaging works.
- Verify package-isolated typecheck, installer-binary startup, warm-start performance, SDK behavior, plugin compatibility, and no duplicated implementation.

### 8. Optimize and standardize themes (U3 -> U2)

- First lazy-load only the selected theme plus one built-in; resolve or remove the six unreferenced theme documents.
- Then introduce derived semantic foreground/background, status, border, and surface tokens behind a compatibility proxy.
- Migrate surfaces incrementally and remove the proxy only after flat reads disappear.
- Verify all themes, contrast/readability, plugin themes, dialogs/popovers, syntax rendering, and startup performance.

## Cross-Cutting Gates

- Update the relevant spec and specs/ROADMAP.md at each contract or phase boundary; keep statuses accurate.
- For every SQL move, require an idempotent backfill and preserve downgrade JSON files without runtime dual reads.
- Run bun run typecheck and targeted tests after each section, then the full unit suite before phase boundaries.
- For HTTP contract changes, update the Effect contract, regenerate clients, run bun run check:routes, and verify generated SDK types.
- Measure runtime-sensitive work rather than relying on typecheck: SSE lag/overflow, session restart, prompt-cache stability, TUI startup, and theme load time.

## Explicit Non-Goals

Do not reintroduce nested project URLs, automatic hard-crash recovery, clustered ownership, shared PubSub for SSE, or a TUI rewrite. These are explicitly rejected in specs/ROADMAP.md.
