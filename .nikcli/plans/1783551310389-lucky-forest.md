## P1 (must fix before flag-on)

### Fix 1 — `abortableIterable` listener leak (`packages/nikcli/src/session/llm/native-runtime.ts:75-88`)

Each `Promise.race` iteration registers `abort.addEventListener("abort", onAbort, { once: true })`. If `iterator.next()` wins the race, the listener stays attached until the abort signal actually fires. For chatty streams this accumulates listeners and prevents GC of the iterator closure.

**Fix:** capture the listener in a local ref, call `abort.removeEventListener("abort", onAbort)` after `Promise.race` resolves, regardless of which side won.

```ts
async function* abortableIterable<T>(it: AsyncIterable<T>, signal: AbortSignal) {
  if (signal.aborted) throw new DOMException("Aborted", "AbortError")
  const iter = it[Symbol.asyncIterator]()
  try {
    while (true) {
      let onAbort: (() => void) | undefined
      const abortPromise = new Promise<never>((_, reject) => {
        onAbort = () => reject(new DOMException("Aborted", "AbortError"))
        signal.addEventListener("abort", onAbort, { once: true })
      })
      try {
        const next = await Promise.race([iter.next(), abortPromise])
        yield next.value as T
        if (next.done) return
      } finally {
        if (onAbort) signal.removeEventListener("abort", onAbort)
      }
    }
  } finally {
    await iter.return?.()
  }
}
```

**Test:** add a case to `test/session/native-runtime.test.ts` that iterates a long async iterable with an abort signal that **never fires**, then asserts the signal has 0 listeners (`signal.eventNames()` length or `AbortSignal.prototype` inspection).

### Fix 2 — `stickyScroll` vs virtualization sticky-bottom conflict (`packages/nikcli/src/cli/cmd/tui/routes/session/index.tsx:1372-1389, 197-227`)

The scrollbox already has `stickyScroll={true}` + `stickyStart="bottom"`. The new `windowed()` sticky-bottom branch clamps `scrollTop` to `total - vp` when within 2 messages of the tail. Two sticky-bottom mechanisms will fight each other → jumpy viewport when `experimental.tui.messageVirtualization: true`.

**Fix:** remove the sticky-bottom clamp from `windowed()` (let `stickyScroll` handle it). The virtualization only computes a windowed slice — sticky-bottom is the scrollbox's job. Replace:

```ts
// before (lines 207-210):
if (scrollTop + vp >= total - MESSAGE_HEIGHT_ESTIMATE * 2) {
  scrollTop = Math.max(0, total - vp)
}
```

with:

```ts
// after: no clamp — stickyScroll handles it.
const range = visibleRange({ heights, scrollTop, viewportHeight: vp, overscan: OVERSCAN })
```

**Test:** manual soak with `experimental.tui.messageVirtualization: true` during a long streaming response. Update `test/tui/util/message-window.test.ts` if the math changed (no — only removed a branch).

### Fix 3 — Uniform `MESSAGE_HEIGHT_ESTIMATE = 6` produces wrong spacer math (`index.tsx:177, 197-227`)

Multi-line assistant messages with tool calls, code blocks, or thinking blocks render far taller than 6 rows. Sticky-bottom math (`total - vp`) and spacer heights will drift.

**Fix (incremental, doesn't block flag-on but blocks default-on):**

- Accept the imprecision for the flag-off path (current behavior is bit-identical).
- For the flag-on path, add an `if (process.env.NIKCLI_TUI_VIRT_MEASURED) { /* measured path */ }` branch that reads from a measured-heights cache. Skip this in this PR — file as a follow-up under "deferred to before default-on".

No code change needed now beyond documenting the limitation in `specs/opencode-parity/04-message-list-virtualization.md` (add note: "P0 path uses uniform estimate; per-row measurement is required before default-on").

## P2 (should fix)

### Fix 4 — `RevertBanner` unmounts inside virtualized `<For>` (`index.tsx:1393-1433`)

`<RevertBanner>` is rendered as one of the `<Switch>` arms inside `<For each={windowed().items}>`. If virtualization scrolls the revert banner out of the slice, it unmounts and click handlers stop firing.

**Fix:** hoist the revert banner out of the `<For>` and render it before the scrollbox (sticky-bottom anchored). The banner is currently a single-element header; place it inside the scrollbox as a fixed-position sibling:

```tsx
<scrollbox ref={(r) => (scroll = r)} ...>
  <Show when={revert()}>
    <RevertBanner count={revert()!.reverted.length} diffFiles={revert()!.diffFiles} />
  </Show>
  <Show when={windowed().top > 0}>
    <box height={windowed().top} flexShrink={0} />
  </Show>
  <For each={windowed().items}>...</For>
  ...
</scrollbox>
```

This places the banner at the top of the scrollbox (above the windowed slice), so it's never unmounted by virtualization.

**Test:** manual — open session, revert some messages, scroll the session, click the banner. It must still respond.
