# Plan: Integrate OpenCode TUI Features into nikcli

## Context

After analyzing both nikcli and opencode TUI systems, identifying what's already present and what needs enhancement.

## Key Finding: nikcli Already Has Many Features!

| Feature                   | opencode | nikcli  | Status                                          |
| ------------------------- | -------- | ------- | ----------------------------------------------- |
| **KVProvider**            | ✅       | ✅      | Already exists (simpler implementation)         |
| **LocalProvider**         | ✅       | ✅      | Already exists (model/agent/session management) |
| **SyncProvider**          | ✅       | ✅      | More comprehensive in nikcli                    |
| **EditorContext**         | ✅       | Partial | Basic support exists                            |
| **CommandPalette**        | ✅       | ❌      | Missing                                         |
| **SyncV2 (fine-grained)** | ✅       | ❌      | Bulk sync + event patching                      |

## Phase 1: Already Done ✅

### 1.1 KVProvider

**Status**: Already exists at `src/cli/cmd/tui/context/kv.tsx`

- File-backed JSON storage (simpler than opencode's file locking)
- Debounced writes with `setTimeout`
- `signal()` helper for reactive getters

**Potential Enhancement**: Add file locking for cross-process safety (like opencode)

### 1.2 LocalProvider

**Status**: Already exists at `src/cli/cmd/tui/context/local.tsx`

- Model management with recent/favorite lists
- Agent state with color mapping
- MCP toggle support
- Connector toggle support
- Per-agent model preferences

**Already implemented**:

- `model.cycle()` - cycling through recent models
- `model.cycleFavorite()` - cycling through favorites
- `agent.move()` - cycling through agents
- `model.variant` support

### 1.3 SyncProvider

**Status**: Already exists at `src/cli/cmd/tui/context/sync.tsx`

- Comprehensive state management (providers, agents, sessions, messages, parts, todos, monitors, background jobs, etc.)
- Event-driven updates for permission/question/delegation
- Session sync with binary search for efficient updates

## Key Insights from Agent Exploration

### 1. Nikcli Already Has Most Features!

- **KVProvider**: Exists at `context/kv.tsx` (simple JSON file)
- **LocalProvider**: Exists at `context/local.tsx` (model/agent/connectors)
- **SyncProvider**: Comprehensive state management
- **CommandPalette**: Partial at `component/dialog-command.tsx`

### 2. Architecture Gap Analysis

| Feature          | Nikcli Status               | OpenCode Pattern            |
| ---------------- | --------------------------- | --------------------------- |
| **State Model**  | Monolithic store            | Atomic/derived state        |
| **Persistence**  | Flat JSON files             | IndexedDB + localStorage    |
| **Event System** | SSE batched (16ms debounce) | WebSocket + atomic          |
| **Plugin State** | Limited shared state        | VSCode-like extension API   |
| **Middleware**   | None                        | logger, persist, sync, undo |

### 3. What's Really Missing

1. **SyncV2 (Fine-Grained Events)** - Real-time streaming with atomic updates
2. **Command Palette UI** - Unified discoverable command interface
3. **Session Pinning** - Quick-switch with keyboard shortcuts
4. **Enhanced Keymap** - Leader key, mode stacks

## Detailed Implementation Guide

### 2.1 Command Palette (Priority 1)

Create `src/cli/cmd/tui/component/command-palette.tsx`:

```typescript
import { DialogSelect } from "@tui/ui/dialog-select"
// Similar to opencode's command-palette.tsx
// - Ctrl+P opens palette
// - Slash commands for quick access
// - Keybinding display in footer
```

**Integration**: Add to `app.tsx` binding commands, integrate with existing `CommandProvider`

### 2.2 Session Pinning (Priority 2)

Enhance existing `DialogSessionList` with:

- Pin/unpin button
- Pinned sessions section at top
- Quick-switch keys (1-9)

### 2.3 SyncV2 (Priority 3)

Create `src/cli/cmd/tui/context/sync-v2.tsx` alongside existing `sync.tsx`:

- Subscribe to 30+ session events
- Handle text deltas, tool progress, reasoning
- Real-time UI updates with atomic mutations

### 2.4 Enhanced Keymap (Priority 4)

Enhance `src/cli/cmd/tui/keymap.tsx`:

- Leader key binding
- Mode stack for custom modes
- Key aliases
