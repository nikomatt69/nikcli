# Fix workspace/worktree creation, switching, and chat context

## Root cause

- Worktree workspace creation calls `makeWorktreeInfo(..., detached: true)` when no branch is supplied, so the new workspace has no branch to display or route to. The generated `nikcli/<slug>` branch is also not returned by the adaptor and therefore is not persisted in the workspace row/event stream.
- `Workspace.sessionWarp` updates only `session.workspaceID`. It leaves `session.directory` pointing at the previous checkout, creating split state between workspace routing, persisted session metadata, Git/file operations, and the TUI's synthetic directory-change reminder.
- The main TUI prompt and slash-command submissions use the global SDK client without `workspace`/target `directory`, unlike the review prompt path. After opening or warping a worktree session, chat can therefore execute in the primary checkout even though the route shows the worktree.
- Projection/discovery currently cannot reliably distinguish “branch explicitly cleared” from “branch omitted”, so restart/replay can restore stale branch metadata.

## Implementation

1. **Finish and harden branch-aware worktree creation**
   - Preserve the existing in-progress edits in `packages/nikcli/src/workspace/adaptors/types.ts`, `packages/nikcli/src/workspace/adaptors/worktree.ts`, and `packages/nikcli/src/workspace/index.ts` rather than replacing unrelated user work.
   - Create a normal generated `nikcli/<slug>` branch when the caller does not request a branch; retain detached creation only for callers that explicitly use the low-level detached Worktree API.
   - Return the actual branch from the adaptor and persist that value in both `Workspace.Info` and `workspace.created` projection data.
   - Canonicalize/deduplicate discovered worktree directories before matching tracked workspaces, then emit `workspace.configUpdated` only when live branch metadata truly drifted.

2. **Make warp update one coherent session location**
   - In `packages/nikcli/src/workspace/index.ts`, resolve the target local worktree directory before mutating the session.
   - Update `draft.workspaceID` and `draft.directory` together in the same `Session.Service.update` call.
   - On detach, restore the canonical primary project directory (`current project.worktree`), not the session's possibly stale previous directory; use that same resolved directory when copying a patch to local.
   - Keep remote workspace semantics explicit: retain the stable local project directory in session metadata while the remote workspace ID controls proxy routing.
   - Perform restore/patch preparation before the metadata update so failures leave the session at its original location; if the post-update remote steal fails, restore the original workspace ID/directory before surfacing the error.

3. **Scope chat and commands to the active worktree**
   - In `packages/nikcli/src/cli/cmd/tui/component/prompt/index.tsx`, derive the active workspace ID from the session route/session cache and the active directory from the refreshed session.
   - Include `workspace` and `directory` on both `sdk.client.session.prompt(...)` and `sdk.client.session.command(...)`, matching the already-correct review prompt in `packages/nikcli/src/cli/cmd/tui/routes/changes/index.tsx`.
   - In `packages/nikcli/src/cli/cmd/tui/component/dialog-session-warp.tsx`, send the synthetic move reminder using the resolved target context and refreshed directory, ensuring the reminder itself cannot run in the old checkout.
   - Refresh the session cache before route navigation so subsequent file/Git/chat actions all observe the same directory.

4. **Make branch clearing replay-safe**
   - Keep the existing explicit-null handling in `packages/nikcli/src/sync/projector.ts`: `undefined` means unchanged, while `null` clears the branch.
   - Apply the same explicit-presence rule to `workspace.created`/session workspace projection fields where needed so cold replay does not resurrect a detached branch or a pre-detach workspace ID.

5. **Add focused regression coverage**
   - Extend `packages/nikcli/test/worktree/list.test.ts` (or workspace route coverage where the adaptor is exercised) to assert default workspace creation creates a real branch, checks `git branch --show-current`, and persists the exact generated branch.
   - Extend `packages/nikcli/test/workspace/projection.test.ts` to prove `workspace.configUpdated` with `branch: null` clears a prior branch and remains cleared after repeated projection.
   - Extend `packages/nikcli/test/server/workspace-warp-route.test.ts` to assert warp updates both `workspaceID` and `directory`, a deterministic command/tool context observes the worktree path/branch, and detach restores both fields to the primary project directory.
   - Add a small TUI source/unit regression assertion if needed to ensure both prompt and command payloads include active `workspace` and `directory`; prefer an executable route-level context test over brittle source matching.
