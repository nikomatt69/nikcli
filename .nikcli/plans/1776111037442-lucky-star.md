## Objective

Integrate two capabilities into `nikcli` without replacing its core runtime:

1. a sandbox abstraction layer inside `packages/nikcli`
2. durable background agents inspired by open-agents

The design must keep `packages/nikcli` as the center of gravity and reuse existing concepts: sessions, task/delegation, workspace adaptors, remote/container execution, storage, bus/SSE, and monitor/background patterns.

## Recommended Approach

### 1. Sandbox abstraction layer

Add a package-local sandbox contract that separates execution environment concerns from session orchestration.

Keep the current session pipeline unchanged:

`CLI/TUI -> server/session route -> SessionPrompt -> SessionProcessor -> storage/bus`

Only extract the execution-environment boundary used by workspace/local/remote/container-backed operations.

Recommended new package-local layer:

- `packages/nikcli/src/sandbox/interface.ts`
  - define a `Sandbox` interface inspired by open-agents, but tailored to nikcli
  - include filesystem, shell, lifecycle, optional preview URL, optional snapshot/resume state
- `packages/nikcli/src/sandbox/types.ts`
  - `SandboxKind`, `SandboxState`, `SandboxCapabilities`, `SandboxRef`
- `packages/nikcli/src/sandbox/registry.ts`
  - resolve the correct backend from workspace config / execution context
- backend implementations:
  - `packages/nikcli/src/sandbox/local.ts`
  - `packages/nikcli/src/sandbox/remote-workspace.ts`
  - `packages/nikcli/src/sandbox/container.ts`

The purpose is not to rewrite all tools immediately. The first integration should create a clean boundary that current workspace and background execution code can depend on.

### 2. Durable background agents

Replace the current partially in-memory background/delegation lifecycle with a durable supervisor model.

Recommended architecture:

- a new durable service in `packages/nikcli/src/background/`
  - `run.ts` or `record.ts` for durable background-run records
  - `supervisor.ts` for lifecycle orchestration
  - `resume.ts` for boot-time rehydration / watcher reattachment
- keep `task(background=true)` as the public entrypoint
- keep `delegation` as the main read/list/cancel interface initially
- store background-run state in `Storage`, not only in memory
- use child sessions as execution truth, but background-run records as lifecycle truth
- model the sandbox as an attached execution resource, not as the agent itself

This mirrors the most useful open-agents idea: `agent != sandbox`. The agent remains a nikcli session/subagent. The sandbox becomes a durable execution resource the run can reattach to or recreate.

## Implementation Phases

### Phase 1: Define the sandbox contract

Goal: introduce a stable execution boundary without changing user-facing behavior.

Likely files to modify:

- `packages/nikcli/src/workspace/adaptors/types.ts`
- `packages/nikcli/src/workspace/adaptors/index.ts`
- `packages/nikcli/src/workspace/index.ts`
- new `packages/nikcli/src/sandbox/*`

Work:

- define `Sandbox` methods needed by nikcli:
  - file reads/writes/stat/list
  - command execution
  - detached command execution
  - lifecycle hooks: `stop`, optional `snapshot`, optional `resume`, optional `extendTimeout`
  - metadata: working directory, env, host, expiration, capability flags
- define `SandboxRef` / `SandboxState` so a workspace or background run can persist how to reconnect
- adapt current workspace target resolution so `worktree`, `container`, and remote workspace targets can all produce a sandbox-backed execution context

### Phase 2: Wire current workspace execution to sandbox backends

Goal: make workspace/container/remote execution resolve through the new abstraction.

Likely files to modify:

- `packages/nikcli/src/workspace/index.ts`
- `packages/nikcli/src/workspace/session-proxy-middleware.ts`
- `packages/nikcli/src/server/proxy.ts`
- `packages/nikcli/src/workspace/workspace-context.ts`
- `packages/nikcli/src/workspace/workspace-server/server.ts`
- `packages/nikcli/src/workspace/adaptors/index.ts`

Work:

- keep existing proxying behavior working
- add a formal execution-context lookup that returns:
  - local sandbox
  - remote workspace sandbox
  - container sandbox
- ensure workspace records can persist enough state to reconnect after process restart

### Phase 3: Introduce durable background-run records

Goal: make background subagents survive process restarts and support resume/list/read/cancel reliably.

Likely files to modify:

- `packages/nikcli/src/delegation/manager.ts`
- `packages/nikcli/src/tool/task.ts`
- `packages/nikcli/src/session/index.ts`
- `packages/nikcli/src/storage/storage.ts`
- new `packages/nikcli/src/background/*`

Work:

- define a durable `BackgroundRun` record stored via `Storage`
- keep delegation IDs stable, but back them with persisted records instead of only maps
- separate:
  - run identity
  - child session identity
  - current status
  - last known progress summary
  - artifact/result path
  - sandbox reference/state
  - timeout / retry / wake-parent flags
- make `task(background=true)` create a durable run first, then launch the child session

### Phase 4: Add supervisor and resume semantics

Goal: background runs can be resumed/reconciled after restart, not just while memory is alive.

Likely files to modify:

- `packages/nikcli/src/background/supervisor.ts`
- `packages/nikcli/src/background/resume.ts`
- `packages/nikcli/src/project/bootstrap.ts`
- `packages/nikcli/src/session/status.ts`
- `packages/nikcli/src/bus/*`

Work:

- boot-time scan for running background runs
- reattach watchers to child sessions using stored session IDs
- if a run has an attached sandbox ref, reconnect or recreate according to backend capabilities
- use bus/session-status events to detect completion, error, timeout, cancel, and wake-parent conditions
- stop relying on polling-style plugin semantics for core durability

### Phase 5: Bridge public tools and APIs onto the durable core

Goal: preserve current user workflows while moving implementation behind the new durable engine.

Likely files to modify:

- `packages/nikcli/src/tool/task.ts`
- `packages/nikcli/src/tool/delegation.ts`
- `packages/nikcli/src/tool/monitor.ts`
- optional: `packages/plugin/plugins/background-agents/index.ts`

Work:

- keep `task(background=true)` contract stable
- keep `delegation` list/read/cancel stable, but back it with durable storage
- optionally deprecate or reimplement `packages/plugin/plugins/background-agents/index.ts` on top of the core durable service
- keep `monitor` and long-lived shell jobs aligned with sandbox lifecycle when a background run owns a sandbox

### Phase 6: Add optional sandbox snapshots for durable runs

Goal: enable stronger resume semantics where the backend supports it, without forcing it everywhere.

Likely files to modify:

- `packages/nikcli/src/sandbox/interface.ts`
- `packages/nikcli/src/sandbox/container.ts`
- `packages/nikcli/src/background/supervisor.ts`
- `packages/nikcli/src/background/record.ts`

Work:

- add optional snapshot hooks to sandbox backends
- persist snapshot metadata in `BackgroundRun`
- use snapshots only as a backend capability, not as a hard dependency

## Required Data Model Additions

### BackgroundRun

Persist a new record, for example under a storage namespace like `background_run`.

Fields:

- `id`
- `parentSessionID`
- `childSessionID`
- `agent`
- `title`
- `prompt`
- `status` = `pending | running | complete | error | timeout | cancelled | orphaned`
- `createdAt`
- `updatedAt`
- `completedAt?`
- `resultArtifactPath`
- `lastSummary?`
- `error?`
- `wakeParent`
- `timeoutMs`
- `sandboxRef?`
- `sandboxState?`
- `workspaceID?`
- `resumePolicy`

### SandboxRef / SandboxState

Persist backend-specific reconnect information behind a discriminated union:

- `local`
- `remote-workspace`
- `container`
- future cloud sandbox types

This lets durable runs restore the execution environment without teaching the session engine about backend details.

## API And Tooling Changes

### Keep stable initially

- `task(background=true)`
- `delegation list/read/cancel`

### Add internally first

- background-run supervisor APIs inside `packages/nikcli`
- sandbox resolver APIs inside `packages/nikcli`

### Optional later externalization

- add explicit server endpoints for background run inspection if web/mobile/TUI need richer resume UX
- expose sandbox capability metadata only after the internal contract is stable

## Verification Plan

### Core checks

- run `bun dev`
- verify normal foreground session flow still behaves identically
- verify existing workspace/container flows still work

### Sandbox checks

- local workspace resolves to local sandbox backend
- container workspace resolves to container backend and preserves current proxy behavior
- remote workspace resolves to remote backend and still mirrors SSE/event state correctly
- file/shell operations executed through the new abstraction preserve current semantics

### Durable background-agent checks

- launch a background subagent with `task(background=true)`
- confirm it appears in `delegation list`
- restart the runtime/server
- confirm the run can still be listed, read, and cancelled/resumed correctly
- verify final artifact and status survive restart
- verify parent-session wakeup or completion notification still happens

### Failure-path checks

- child session abort mid-tool
- server restart during running child session
- timeout while detached work is active
- remote/container sandbox unavailable on resume
- stale background-run record with missing child session or missing artifact

### Package validation

- run `bun run --cwd packages/nikcli typecheck`
- run `bun run --cwd packages/nikcli test`
- if server contract changes, regenerate/check SDK with `./packages/sdk/js/script/build.ts`

## Risks And Rollout Strategy

### Main risks

- over-coupling sandbox abstraction to one backend too early
- mixing durable run truth with session truth and creating inconsistent states
- breaking current delegation/task behavior while introducing persistence
- leaking local-only assumptions into remote/container resume flows

### Rollout

1. land sandbox interface and backends with no user-visible behavior change
2. land durable `BackgroundRun` persistence under the existing task/delegation API
3. add supervisor boot rehydration and session watcher resume
4. add optional sandbox snapshot support only after the first durable cycle works
5. only then consider UI/API expansion and plugin cleanup

## Final Recommendation

Do this as an incremental refactor of `nikcli`, not a platform rewrite.

- Use open-agents mainly for two ideas:
  - `agent != sandbox`
  - durable lifecycle around agent runs
- Do not import the open-agents runtime wholesale
- First create a clean `sandbox` boundary in `packages/nikcli`
- Then move `task/delegation` onto a durable supervisor backed by `Storage`
- Keep sessions as the execution engine and background runs as the orchestration layer above them
