# Mobile App Optimization Plan

## Scope

Optimize the React Native/Expo mobile app across:

- `packages/mobile/app`
- `packages/mobile/components`
- Supporting shared code in `packages/mobile/lib`, `packages/mobile/hooks`, and `packages/mobile/assets`

The goal is not a visual-only pass. This is a structured stabilization and refactor plan that reduces runtime bugs, removes duplicated UI infrastructure, improves large-list/large-file performance, and makes route files maintainable.

## Subagent Analysis Summary

This plan is based on parallel analysis from focused subagents:

- **App architecture**: inspected route files, session/editor/explorer/terminal/settings structure, and route-level state management.
- **Component patterns**: inspected modal/sheet duplication, button/chrome duplication, animation patterns, list rendering, and shared loading/error states.
- **Shared libs/assets**: inspected `client.ts`, auth/header handling, stream setup, terminal WebView protocol, animation helpers, haptics, theme tokens, stores, and type drift.
- **Planning synthesis**: consolidated findings into phased execution to avoid one risky mega-refactor.

## Guiding Principles

- Fix runtime correctness first, then extract shared primitives, then decompose large screens.
- Keep route behavior stable while moving code into hooks/components.
- Prefer small, verifiable phases with `bun run typecheck` after each phase.
- Avoid visual regressions: extracted UI primitives must preserve current glass/chrome look.
- Use `monitor` during implementation for long-running checks or simulator smoke runs where useful.

## Phase 1 — Network, Auth, Endpoint, and Error Hardening

### Why

The app currently has duplicated request logic and has already hit endpoint drift issues such as `Unexpected character: <` when a JSON client receives HTML. `ServerConfig` includes username/password fields, but request headers mostly use bearer token only.

### Files

- `packages/mobile/lib/client.ts`
- `packages/mobile/lib/server-provider.tsx`
- `packages/mobile/hooks/use-session-stream.ts`
- `packages/mobile/lib/types.ts`

### Work

- Centralize request behavior in `MobileClient`:
  - URL construction
  - auth headers
  - directory header
  - JSON vs text response parsing
  - friendly error messages for HTML/non-JSON responses
  - `204` handling
- Add Basic auth header fallback when `ServerConfig.username/password` are present and token is absent.
- Ensure mobile git endpoints consistently use `/mobile/git/...`.
- Reuse shared request/header helpers in `server-provider.tsx` user/auth calls.
- Reuse shared stream URL/header behavior in `use-session-stream.ts`.
- Update confirmed type drift in `lib/types.ts`, especially bootstrap fields returned by the server.

### Verification

- Run `bun run typecheck` in `packages/mobile`.
- Manually verify:
  - connect/login flow
  - bootstrap refresh
  - session list load
  - session stream reconnect/error behavior
  - git status/diff/branches calls no longer log JSON parse warnings
  - Basic auth server connection if available

## Phase 2 — Runtime Lifecycle Fixes

### Why

Several runtime risks are independent of larger refactors: terminal lifecycle, sheet close races, animation loop cleanup, haptic blocking, and brittle route chrome hiding.

### Files

- `packages/mobile/assets/terminal.html`
- `packages/mobile/app/(app)/terminal/index.tsx`
- `packages/mobile/components/git/GitStatusBar.tsx`
- `packages/mobile/components/session/PluginManagerSheet.tsx`
- `packages/mobile/components/session/ComposerToolDrawer.tsx`
- `packages/mobile/lib/haptics.ts`
- `packages/mobile/app/(app)/_layout.tsx`
- `packages/mobile/lib/animation.ts`

### Work

- Terminal WebView:
  - declare lifecycle flags such as `stopped`
  - listen to both `window.message` and `document.message`
  - validate WebView message shape before acting
  - clear timeouts/reconnect timers on close/unload
  - close socket on connection timeout
  - keep PTY WebSocket for shell input/output only
  - route resize through RN/REST, not through shell WebSocket
- Terminal screen:
  - cache `terminal.html` once instead of reading per tab
  - guard missing `asset.localUri`
  - debounce resize updates
- Animation cleanup:
  - stop `Animated.loop` instances on unmount in `GitStatusBar`
  - remove double-close patterns from sheet components
  - document native-driver-safe helpers in `animation.ts`
  - keep color/layout animation helpers separate from transform/opacity helpers
- Haptics:
  - make calls fire-and-forget
  - throttle rapid `selection` haptics
  - never block submit/press flows
- Layout chrome:
  - replace `segments.length > 2` with explicit route matching or route metadata for full-screen routes.

### Verification

- Run `bun run typecheck`.
- Use simulator/device and verify:
  - terminal resize JSON never appears in shell prompt
  - terminal reconnect/timeout states behave correctly
  - terminal tabs do not reload HTML unnecessarily
  - plugin/tool sheets do not double-close or leave stuck overlays
  - git status animation loops stop cleanly after navigation
  - full-screen route chrome appears/hides only where intended

## Phase 3 — Explorer Reliability and Stale Request Protection

### Why

`sessions/explorer.tsx` silently swallows directory expand errors and has debounced search without robust stale-result protection.

### Files

- `packages/mobile/app/(app)/sessions/explorer.tsx`
- `packages/mobile/components/ui/EmptyState.tsx`
- `packages/mobile/components/ui/ErrorBanner.tsx`
- `packages/mobile/components/Skeleton.tsx`

### Work

- Add per-directory loading state for expand/collapse.
- Add per-directory error state with retry affordance.
- Add stale search protection using request IDs or abort-like guards.
- Prevent older search responses from replacing newer results.
- Flatten expanded directory rows with memoized projection.
- Standardize loading/empty/error UI with existing shared primitives.

### Verification

- Run `bun run typecheck`.
- Manually verify:
  - expanding nested directories
  - expanding inaccessible/erroring directories
  - retrying failed directory load
  - rapid search query changes do not show stale results
  - empty directory and empty search states are clear

`app/(app)/settings/index.tsx` is very large and duplicates dedicated settings screens. The index should become a dashboard/composition route, not the owner of every workflow.

- `packages/mobile/app/(app)/settings/index.tsx`
- `packages/mobile/app/(app)/settings/providers.tsx`
- `packages/mobile/app/(app)/settings/github.tsx`
- `packages/mobile/app/(app)/settings/mcp.tsx`
- `packages/mobile/app/(app)/settings/agents.tsx`

- `packages/mobile/app/(app)/settings/skills.tsx`
- `packages/mobile/app/(app)/settings/tokens.tsx`
- `packages/mobile/components/settings/*`

### Work

- Extract reusable settings sections under `components/settings/`:
  - provider summary/detail components
  - GitHub auth/status components
  - MCP status/action components
  - preferences/account/status cards
- Extract repeated settings mutations into hooks:

### Verification

- Manually verify:

### Files

- `packages/mobile/app/(app)/sessions/[sessionId].tsx`

- New or updated hooks under `packages/mobile/hooks/`
- `packages/mobile/components/session/*`
- `packages/mobile/lib/session-utils.ts` (new if needed)

### Work

- Extract pure helpers to `lib/session-utils.ts`:
  - message normalization
  - title fallback
  - status helpers
  - attachment/message predicates
- Extract route logic into hooks:
  - `useSessionDetail`
  - `useSessionEvents`
  - `useSessionActions`
  - `useSessionLiveActivity`
  - `useSessionAttachments`
  - `useSessionGitActions`
- Extract focused components:
  - session header/status area
  - message list container
  - composer wiring container
  - command/publish/git coordinator
  - route loading/error/empty states
- Keep `[sessionId].tsx` as route composition only.
- Remove placeholder logic such as no-op tool toggle logs or convert to real behavior.

### Verification

  - send slash command

## Phase 7 — Performance Guards for Editor, Lists, Git Tree, and Terminal

### Why

Several screens render potentially large data with `ScrollView + map`, per-row animations, or all WebViews mounted at once.

### Files

- `packages/mobile/app/(app)/sessions/editor.tsx`
- `packages/mobile/components/editor/FileSearchSheet.tsx`
- `packages/mobile/components/git/GitFileTree.tsx`
- `packages/mobile/components/SessionListItem.tsx`
- `packages/mobile/components/session/PluginManagerSheet.tsx`
- `packages/mobile/components/session/ComposerToolDrawer.tsx`
- `packages/mobile/components/session/CommandPaletteSheet.tsx`
- `packages/mobile/components/session/AttachmentPickerSheet.tsx`
- `packages/mobile/app/(app)/terminal/index.tsx`

### Work

- Editor:
  - add file-size and line-count thresholds
  - skip syntax highlighting for very large files
  - add large-file warning/readonly fallback
  - virtualize read-only line rendering with `FlatList`
  - keep whole-file `TextInput` editing only below safe threshold
- Git file tree:
  - pre-index paths to avoid O(paths \* files)
  - flatten tree nodes
  - render with `FlatList`
- List-heavy sheets:
  - replace `ScrollView + map` with `FlatList` where item count can grow
  - memoize row components and stable callbacks
  - reduce or remove per-row `Animated.Value` allocations for large lists
- Session list:
  - avoid replaying entrance animations on every refresh/remount
  - memoize row props/callbacks
- Terminal:
  - mount active WebView plus a small keep-alive set
  - preserve tab metadata for inactive tabs
  - avoid memory growth from many hidden WebViews

### Verification

- Run `bun run typecheck`.
- Manually stress test:
  - large files
  - large search results
  - large git file trees
  - many sessions
  - many plugins/tools/commands
  - multiple terminal tabs
- Confirm scrolling remains responsive and memory usage improves.

  - add explicit color/layout animation helper using `useNativeDriver: false`
- Standardize shared UI states:
  - full-screen loading

  - empty state

## Phase 9 — Final Regression and Monitored Smoke Testing

### Commands

- `bun run typecheck` from `packages/mobile`
- Use `monitor` during implementation for long-running simulator/dev-server runs where useful.
- Manual simulator/device run via existing project workflow.

### End-to-End Checklist

- Connect/login/bootstrap
- Session list load/search
- Session detail load
- Stream assistant response
- Send text and slash command
- Attach file/image
- Open editor for small and large files
- Use editor find, copy, save, back-with-unsaved-changes
- Open explorer, expand nested folders, search files
- Open terminal, create tabs, resize, close tabs
- Git status, git diff, git review, stage/unstage/discard where applicable
- Settings dashboard and dedicated settings routes
- Provider/GitHub/MCP workflows
- All migrated sheets: open/close/action/keyboard/backdrop

## Execution Order Recommendation

1. Phase 1
2. Phase 2
3. Phase 3
4. Phase 4
5. Phase 7 editor/list/terminal guards that are independent
6. Phase 5 settings decomposition
7. Phase 6 session decomposition
8. Phase 8 normalization
9. Phase 9 regression

This order keeps user-visible runtime stability ahead of large structural refactors.

## Main Risks

- Terminal WebView lifecycle must be tested on real devices, not only simulator.
- Session detail decomposition is high-risk because streaming, actions, and live activities interact.
- Sheet primitive migration can cause subtle keyboard/backdrop regressions if done too broadly at once.
- Editor virtualization must preserve line-number alignment, find navigation, syntax colors, and save behavior.
