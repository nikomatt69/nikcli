# Routines Feature — Implementation Plan

## Overview

Implement a **Routines** system in nikcli that allows users to save named, reusable AI workflows with configurable triggers (manual, schedule, API webhook). Routines run as background sessions.

## 1. Backend — `src/mobile/routine.ts`

### Data Model

```ts
export namespace Routine {
  export type TriggerSchedule = { type: "schedule"; cron: string; enabled: boolean }
  export type TriggerApi      = { type: "api"; token: string; enabled: boolean }
  export type Trigger         = TriggerSchedule | TriggerApi

  export interface Record {
    id: string
    name: string
    prompt: string
    triggers: Trigger[]
    paused: boolean
    projectID: string        // Instance.project.id at creation time
    directory: string        // project directory
    createdAt: number
    updatedAt: number
    lastRunAt?: number
    lastSessionID?: string
  }

  // Zod schemas with .meta({ ref: "..." }) for OpenAPI
  export const TriggerScheduleSchema = z.object({ type: z.literal("schedule"), cron: z.string(), enabled: z.boolean() }).meta({ ref: "RoutineTriggerSchedule" })
  export const TriggerApiSchema      = z.object({ type: z.literal("api"), token: z.string(), enabled: z.boolean() }).meta({ ref: "RoutineTriggerApi" })
  export const TriggerSchema         = z.discriminatedUnion("type", [TriggerScheduleSchema, TriggerApiSchema]).meta({ ref: "RoutineTrigger" })
  export const RecordSchema          = z.object({ id, name, prompt, triggers, paused, projectID, directory, createdAt, updatedAt, lastRunAt?, lastSessionID? }).meta({ ref: "Routine" })
  export const CreateInputSchema     = z.object({ name, prompt, triggers? }).meta({ ref: "RoutineCreateInput" })
  export const UpdateInputSchema     = CreateInputSchema.partial().extend({ paused? }).meta({ ref: "RoutineUpdateInput" })
}
```

### Scheduling

Use the existing `Scheduler` namespace (`src/scheduler/index.ts`):

```ts
import { Scheduler } from "@/scheduler"

function registerScheduler(routine: Record) {
  const scheduleTrigger = routine.triggers.find((t) => t.type === "schedule" && t.enabled)
  if (!scheduleTrigger || routine.paused) return

  // Parse cron interval → ms (implement a simple parser for "*/N min/hour" patterns)
  // For MVP: support "@hourly", "@daily", "*/N" minute/hour patterns
  const intervalMs = parseCronInterval(scheduleTrigger.cron)
  if (!intervalMs) return

  Scheduler.register({
    id: `routine-${routine.id}`,
    interval: intervalMs,
    scope: "instance",
    run: async () => {
      await Instance.provide({
        directory: routine.directory,
        fn: () => Routine.run(routine.id),
      })
    },
  })
}
```

### `Routine.run(id)`

```ts
async function run(id: string): Promise<Session.Info> {
  const routine = await get(id)
  const session = await Session.create({ title: `Routine: ${routine.name}` })
  await SessionPrompt.prompt({
    sessionID: session.id,
    parts: [{ type: "text", text: routine.prompt }],
  })
  await Storage.update<Record>(key(id), (draft) => {
    draft.lastRunAt = Date.now()
    draft.lastSessionID = session.id
    draft.updatedAt = Date.now()
  })
  return session
}
```

## 2. Backend — REST Endpoints in `mobile.ts`

Add **after line 2837** (end of git routes, before utility functions), following the exact existing pattern:

| Method | Path                       | operationId              | Description                                                     |
| ------ | -------------------------- | ------------------------ | --------------------------------------------------------------- |
| GET    | `/routines`                | `mobile.routine.list`    | List all routines for current project                           |
| POST   | `/routines`                | `mobile.routine.create`  | Create a new routine                                            |
| GET    | `/routines/:id`            | `mobile.routine.get`     | Get a single routine                                            |
| PATCH  | `/routines/:id`            | `mobile.routine.update`  | Update name/prompt/triggers/paused                              |
| DELETE | `/routines/:id`            | `mobile.routine.delete`  | Delete a routine                                                |
| POST   | `/routines/:id/run`        | `mobile.routine.run`     | Trigger an immediate run                                        |
| POST   | `/routines/:id/pause`      | `mobile.routine.pause`   | Pause a routine                                                 |
| POST   | `/routines/:id/resume`     | `mobile.routine.resume`  | Resume a paused routine                                         |
| POST   | `/routines/trigger/:token` | `mobile.routine.trigger` | Public API webhook trigger (no auth header, uses token in path) |

Every handler wraps with `Instance.provide({ directory: Instance.directory, fn: () => ... })`.

## Cron Support (MVP)

A minimal `parseCronInterval(cron: string): number | null` function in `routine.ts`:

| Pattern               | Milliseconds    |
| --------------------- | --------------- |
| `@hourly`             | 3_600_000       |
| `@daily`              | 86_400_000      |
| `*/N` (minutes)       | `N * 60_000`    |
| `0 */N * * *` (hours) | `N * 3_600_000` |

Returns `null` for unrecognized patterns (routine won't be auto-scheduled).
