## schema.md Deep Analysis

### Core Migration Strategy

The schema migration document provides **practical guidance** for migrating Zod schemas to Effect Schema. Key insights:

#### 1. Three Preferred Shapes

**A. Schema.Class (for self-contained data)**

```ts
export class Info extends Schema.Class<Info>("Foo.Info")({
  id: FooID,
  name: Schema.String,
  enabled: Schema.Boolean,
}) {
  static readonly zod = zod(Info)
}
```

**B. Schema.Struct + withStatics (for self-referencing)**

```ts
export const Info = Schema.Struct({
  id: FooID,
  name: Schema.String,
}).pipe(withStatics((s) => ({ zod: zod(s) })))
```

**C. Schema.TaggedErrorClass (for domain errors)**

```ts
export class NotFoundError extends Schema.TaggedErrorClass<NotFoundError>()("FooNotFoundError", {
  id: FooID,
}) {}
```

#### 2. Named Refinements Pattern

```ts
const PositiveInt = Schema.Number.check(Schema.isInt()).check(Schema.isGreaterThan(0))

const NonNegativeInt = Schema.Number.check(Schema.isInt()).check(Schema.isGreaterThanOrEqualTo(0))

const HexColor = Schema.String.check(Schema.isPattern(/^#[0-9a-fA-F]{6}$/))
```

The walker translates these to equivalent zod refinements.

#### 3. Escape Hatches

**ZodOverride** - replaces entire derivation:

```ts
Schema.String.annotations({
  [ZodOverrideId]: () => z.string().regex(/^[A-Z]+$/),
})
```

**DeepMutable** - strips readonly for mutable consumers (temporary workaround for effect bug `x228my`)

### Current State (917 lines, Zod-first)

**Structure:**

```

├── Errors (NamedError.create)
├── Output formats (text, json_schema)
├── Part types (12 variants)
│   ├── PartBase

├── Message types (User, Assistant)
├── Event definitions
└── Utility functions (toModelMessages, cursor, etc.)
```

### Migration Order (from schema.md)

1. **Extract leaf schemas first:**
   - Output format payloads
   - Part base types
   - Time/range helpers
   - File/source helpers
   - Token/cost/model helpers

2. **Build part variants from leaves:**
   - Each part type becomes a Schema.Struct

3. **Higher-level unions:**
   - FilePartSource union
   - Part discriminated union
   - Message union

4. **Errors and events last:**
   - Can stay as NamedError.create temporarily
   - SyncEvent/BusEvent payloads use derived .zod

### Complexity Analysis

**Size:** 917 lines of Zod schemas
**Dependencies:**

- LSP.Range (from lsp/index.ts)
- Snapshot.FileDiff (from snapshot/index.ts)
- Identifier for ID generation
- Storage for persistence

**SDK Impact:** HIGH - Message types flow through SSE API and SDK output. Byte-identical output required.

## Core Migration Pattern: Effect Schema First

**The fundamental rule:** Effect Schema is the source of truth, `.zod` is compatibility only.

### Migration Pattern

```ts
// 1. Define Effect Schema as source of truth
const InfoSchema = Schema.Struct({
  id: Schema.String.pipe(Schema.startsWith("prefix")),
  name: Schema.String,
  status: Schema.Literal("active", "inactive"),
  tags: Schema.Array(Schema.String),
  metadata: Schema.optional(Schema.Record({ key: Schema.String, value: Schema.Unknown })),
}).annotations({ identifier: "MyType" })

// 2. Export derived Zod for compatibility
export const Info = zodObject(InfoSchema)
export type Info = Schema.Schema.Type<typeof InfoSchema>
```

### Zod → Effect Schema Translation Reference

| Zod                                         | Effect Schema                                |
| ------------------------------------------- | -------------------------------------------- |
| `z.string()`                                | `Schema.String`                              |
| `z.string().min(1)`                         | `Schema.String.pipe(Schema.minLength(1))`    |
| `z.literal("a")`                            | `Schema.Literal("a")`                        |
| `z.union([z.literal("a"), z.literal("b")])` | `Schema.Literal("a", "b")`                   |
| `z.object({})`                              | `Schema.Struct({})`                          |
| `z.array(z.string())`                       | `Schema.Array(Schema.String)`                |
| `z.record(k, v)`                            | `Schema.Record({ key: K, value: V })`        |
| `z.string().optional()`                     | `Schema.optional(Schema.String)`             |
| `z.string().startsWith("x")`                | `Schema.String.pipe(Schema.startsWith("x"))` |
| `z.custom()`                                | `Schema.String.pipe(Schema.pattern(/.../))`  |
| `z.number().int()`                          | `Schema.Number.pipe(Schema.int())`           |
| `z.enum(["a","b"])`                         | `Schema.Literal("a", "b")`                   |
| `z.coerce.number()`                         | `Schema.NumberFromString`                    |

Every migrated service follows this pattern:

```ts

  // 1. Schema definitions (Effect-first)
  const InfoSchema = Schema.Struct({ ... })

  // 2. Error classes

  // 5. Layer with Effect.fn tracing

    Service,

      const state = yield* InstanceState.make<State>(() => Effect.succeed({ ... }))

      })
      return Service.of({ method })
    }),
  )

  export const defaultLayer = layer
}
```

```ts
// instance-ref.ts
const currentInstanceRef = FiberRef.unsafeMake<Option.Option<InstanceContext>>(Option.none())
const currentWorkspaceRef = FiberRef.unsafeMake<Option.Option<WorkspaceContext>>(Option.none())

export const currentInstance = FiberRef.get(currentInstanceRef)

export function locallyInstance<A, E, R>(ctx: InstanceContext, effect: Effect.Effect<A, E, R>) {
```

### 3. InstanceState Pattern (Scoped Cache)

```ts
// instance-state.ts
export function make<S>(
  init: (ctx: InstanceContext) => Effect.Effect<S, never, Scope.Scope>,
): Effect.Effect<ScopedCache.ScopedCache<string, S>, never, Scope.Scope> {
  return ScopedCache.make({
    capacity: Number.MAX_SAFE_INTEGER,
    timeToLive: Duration.infinity,
    lookup: (key) =>
      context.pipe(
        Effect.flatMap((ctx) => init(ctx)),
        Effect.annotateLogs({ instance: key }),
      ),
  })
}
```
