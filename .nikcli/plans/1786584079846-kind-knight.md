# Plan: Diagnose and fix TUI bottom-left title flicker

## Goal (as interpreted)

The user reports that titles in the bottom-left of the nikcli TUI flicker (sfarfallano) during live streaming, as visible in the recording `/Users/nikoemme-os/Desktop/Registrazione schermo 2026-08-13 alle 02.42.06.mov`. Investigate why this happens and confirm the root cause.

## Investigation findings (Phase 1 complete)

The bug is **three compounding causes**, all already diagnosed and **fixed in staged changes** that are not yet committed. The working tree on branch `live-main` has 7 staged files targeting exactly this issue.

### Root cause 1 — Trailing `.trim()` on every token flips heading block type

**File:** `packages/nikcli/src/cli/cmd/tui/routes/session/diagram.ts`

`TextPart` and `ReasoningPart` used to call `.trim()` on the streaming text on every token. When a heading line was committed (`## Live projector\n` → has a trailing newline, classified as heading), the _next_ token arrived without a terminator, `.trim()` removed the newline, and the same line was re-classified as a paragraph. On the next token the newline came back, and it flipped again. The bottom-left heading (the last visible title in the transcript) flickered in/out at the token rate.

**Fix (staged):** New `liveMarkdown(text, streaming)` helper — only trims leading whitespace while streaming (no block-type change), full trim once settled.

### Root cause 2 — `reasoningSummary` regex dropped the title on the single `\n` before `\n\n`

**File:** `packages/nikcli/src/cli/cmd/tui/context/thinking.ts`

Regex required `\n\n` to keep a `**Title**` summary. The single trailing newline after `**Title**` made the title flicker off, then back on when the blank line landed. This is the "yellow Thinking: ..." header that shares the same band as the headings.

**Fix (staged):** Regex alternative added: `\s*$` keeps the title once `**Title**` is closed.

### Root cause 3 — Markdown coalesced re-highlight on every token

**File:** `packages/nikcli/src/cli/cmd/tui/feature-plugins/math/markdown.tsx`

Default `internalBlockMode` ("coalesced") rebuilds the whole message into one `CodeRenderable` per token, re-syntax-highlighting headings already on screen, which flashes them against the wallpaper.

**Fix (staged):** `internalBlockMode="top-level"` — headings/lists become independent renderables; once a heading leaves the trailing-unstable window it stays painted.

### Root cause 4 — Footer `Date.now()` memo at 60 Hz

**File:** `packages/nikcli/src/cli/cmd/tui/routes/session/index.tsx` (AssistantMessage)

The duration stats memo read `Date.now()` inline, so it re-evaluated on every token (60 Hz). The agent/mode/model titles on the same row shared that line and rewrote against the wallpaper at 60 Hz.

**Fix (staged):** Throttled to 1 Hz via a `now()` signal updated by `setInterval(..., 1000)`; tok/s stays gated until the turn is sealed.
