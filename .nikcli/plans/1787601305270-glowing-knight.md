# Prioritized integration plan — nikcli specs

## Scope of analysis

Read every doc under `specs/` (26 files: `specs/v2/*`, `specs/storage/*`, top-level `ROADMAP.md` and `PRODUCT_ROADMAP.md`) and cross-referenced with code state from the previous analysis session. The spec set has three buckets:

1. **Implemented** (do not re-do) — 9 docs marked _Implemented_ or _Accepted and implemented_: `session.md`, `session-v2-write-path.md`, `durable-pending-input.md`, `instruction-sync-proposal.md`, `session-restart-continuation.md`, `event-stream-architecture.md`, `public-event-filter.md`, `tui-theme-migration.md`, `provider-policy.md`, `catalog-config-plugin-lifecycle.md`, `tools.md`, plus `nikcli-sql-drizzle-adoption.md` and `remove-json-storage.md` (storage retirement, landed 2026-08-14).
2. **Officially queued by ROADMAP** — H8.1 (auth on contract) is the only "Now" item after E5 closed 2026-08-24. P2.2 is "queued, not pre-committed" pending P2.1 measurement (which already landed).
3. **Proposed contracts** — 13 specs in `specs/v2/` marked _Proposed_ (no test pin, no acceptance gate yet): `brain-consolidation-pass`, `cli-command-surface`, `ci-pipeline-runtime-budgets`, `logging-redaction-contract`, `loop-engine-contract`, `mission-orchestrator-contract`, `mobile-companion-protocol`, `observability-otlp-and-in-process-panel`, `permission-ruleset-and-coupling`, `provider-message-normalization`, `share-v2-contract`, `tool-plugin-autoload-security`, `workspace-trust-lattice`.

## Tiering principle

Importance = `engineering_priority × user_outcome × risk_reduction × unlock_value`. Items already on the engineering roadmap score highest by definition; items below it are scored against what they unlock next.

## Tier 1 — must, this week

### 1. **H8.1 — Put auth on the contract** (ROADMAP §H8)

- **Why first** — The engineering roadmap says this verbatim: "Order — E5 is closed (2026-08-24), so H8.1 is the next item on the contract. The P2 session-list SQL slice is independent and may run alongside it; do not start the remaining P2 URL, logging, or benchmark work until that SQL change has been measured." Unblocks SSO/oauth consolidation, Tailscale identity as first-class, open-mode + Basic-auth preservation on the wire.
- **What it buys** — One `HttpApiSecurity` / `HttpApiMiddleware` vocabulary attached to protected encoded groups composed by `PublicHttpApi` in `public.ts`. Public endpoints + raw SSE / prompt / upgrade exclusions preserved. OpenAPI asserts security on protected operations; clients regenerate.
- **Files** — `packages/nikcli/src/server/httpapi/public.ts`, `packages/nikcli/src/server/server.ts`, `packages/nikcli/src/server/server-router.ts`, `packages/nikcli/src/server/middleware/*`, new `packages/nikcli/src/auth/contract.ts`. Tests: `test/server/httpapi-auth.test.ts` (direct bridge + normal router + bearer + query token + Basic + open-mode + Tailscale + public-route).
- **Done when** — `bun run check:routes` clean, `bun run generate:httpapi-clients` regenerates without drift, all the named test scenarios pass, OpenAPI shows `security` on protected ops and omits it on public ones.
- **Risk if skipped** — Auth lives at the middleware/router seam rather than the contract. Future multi-tenant or per-workspace auth additions pile up as ad-hoc checks (the trust-lattice spec already says so: "Per-workspace permission rulesets, budgets, audit trail (ROADMAP §later)").

### 2. **P3 — Characterize, then optimize `normalizeMessages`** (ROADMAP §P3)

- **Why second** — Source carries the comment `// TODO: fix this stupid inefficient dogshit function` (`packages/nikcli/src/provider/transform.ts`). It runs on every LLM call. The spec is already written (`specs/v2/provider-message-normalization.md`) and names the seven passes + the invariants to preserve.
- **What it buys** — One allocation / one traversal pass instead of the current multi-pass. Cache-prefix stability preserved (DeepSeek reasoning stays absent when absent). All provider-specific invariants stay identical.
- **Files** — `packages/nikcli/src/provider/transform.ts`, new `test/provider/normalize-messages.test.ts` pinning the invariants from the spec.
- **Done when** — A loose-budget benchmark (`bun run test:bench`) records before/after for a representative batch; the seven invariants are tested individually (surrogate sanitization, Anthropic/Bedrock empty-prune, Claude tool-id scrub, Anthropic tool-use reorder, Mistral tool-id + sequencing, DeepSeek reasoning injection, interleaved reasoning extraction).
- **Risk if skipped** — Provider normalization becomes the slowest common path on every turn. Provider quirks accumulate in ad-hoc checks.

## Tier 2 — should, this month (engineering)

### 3. **T3 — Output codecs on structured built-ins** (ROADMAP §T3)

- **What it buys** — Tools declare an `output` zod codec; wrapper parses `result.value` after `execute` and rejects malformed success for that call only. Code Mode receives `Tool.encoded(result, codec)` — validated `value` when a codec exists. Built-ins don't have to declare one, but adding them unlocks Code Mode across the catalog.
- **Where to start** — `bash`, `read`, `glob`, `grep`, `webfetch`, `codesearch`, `websearch`, `lsp`, `todo`, `apply_patch`. These are the tools Code Mode would compose most.
- **Files** — `packages/nikcli/src/tool/tool.ts`, `packages/nikcli/src/codemode/tool-runtime.ts`, each tool file. Tests: extend `test/tool/tool.test.ts`.
- **Done when** — Each listed tool has a zod `output` codec; `Tool.encoded(result, codec)` returns the parsed value for Code Mode callers; `value` is the source of truth for structured assertions.
- **Risk if skipped** — Code Mode depends on the model-facing string, not the structured value. The wrapper has the seam; it is half-used.

### 5. **R1 — Keyed scoped instance runtime after lifecycle coverage** (ROADMAP §R1)

- **What it buys** — Multi-tenant instance isolation: per-workspace / per-account scope keys instead of the current per-directory map. Required for "share and distribute work safely" (product outcome).
- **Files** — `packages/nikcli/src/effect/instance-state.ts`, `packages/nikcli/src/workspace/*`, `packages/nikcli/src/server/server-router.ts`. Tests: `test/effect/instance-state-scoped.test.ts`.
- **Done when** — Two instances on the same data dir can carry independent caches, sessions, and event subscriptions; a reload broadcasts only to the keyed scope.
- **Why not Tier 1** — Depends on H8.1 (per-scope auth) and on the share/account paths being stabilized.

## Tier 3 — should, this month (product)

### 6. **Cross-device continuity surface** (PRODUCT_ROADMAP §Next)

- **Why now** — The seams exist: generated SDK clients (`createNikcliClient`), `EventFeed`, `SessionV2`, `session_pending`, `workspace` proxy. The product roadmap's Phase 3 explicitly says: "Reuse generated HttpApi clients and the shared event/session models."
- **What it buys** — TUI ↔ desktop ↔ mobile session handoff. Concrete user-visible win.
- **First cut** — Pick one path (recommended: TUI → mobile QR-pair handoff) and ship it. Measure state convergence and explicit recovery, not visual parity.
- **Files** — `packages/mobile/`, `packages/nikcli/src/server/mobile/*`, `packages/nikcli/src/server/httpapi/mobile.ts`. Tests: `test/server/mobile-handoff.test.ts` (state convergence on the existing seam, not new transport).

### 7. **First-use baseline instrumentation** (PRODUCT_ROADMAP §Now)

- **What it buys** — The promotion rule for "first-use" is "Rank blockers by affected users and elapsed-time cost". Without instrumentation you can't rank.
- **First cut** — One telemetry event per outcome: `install_completed`, `provider_configured`, `session_created`, `first_turn_started`, `first_turn_completed`, plus `categorized_failure`. Carry version, platform, elapsed time, coarse failure code only.
- **Files** — `packages/nikcli/src/observability/telemetry-bus.ts`, new `packages/nikcli/src/telemetry/first-use.ts`. Reuse `TelemetryRecord` from the observability spec.
- **Done when** — Events fire for at least one release boundary; the failure taxonomy matches the actual installer / auth / provider catalog / first-turn paths.

## Tier 4 — later (do not pre-commit)

- **Billing / paid value** — ROADMAP §later, no priced cohort, no entitlement boundary yet. Do not start.
- **Per-workspace rulesets, budgets, audit ("workspace trust lattice" the product)** — explicitly out of scope per `workspace-trust-lattice.md` until R1 lands.
- **Clustered ownership / hard-crash replay** — non-goal for restart-continuation; needs provider-dispatch ambiguity, tool idempotency, retry budgets designed together. Do not start.
- **Custom tool autoload UX** — security model is landed; the UX around discovery / errors / re-pin flow is a separate item.
- **`script/check-cli-table.ts`** — would be invented without evidence. Wait for a real drift to motivate it.

## Recommended execution order (8 weeks)

1. **Week 1** — H8.1 (auth on contract). Open the contract slice, ship with regenerated clients.
2. **Week 2** — P3 characterize (`normalizeMessages` benchmarks + invariant tests). Don't optimize yet.
3. **Week 3** — Promote `permission-ruleset-and-coupling`, `tool-plugin-autoload-security`, `mobile-companion-protocol` to _Accepted_ (test pins).
4. **Week 4** — T3 output codecs on bash / read / glob / grep / webfetch. Code Mode validates structured output.
5. **Week 5** — Promote `loop-engine-contract`, `mission-orchestrator-contract`, `brain-consolidation-pass`, `share-v2-contract` to _Accepted_. Now loops, missions, brain, shares all have test-pinned contracts.
6. **Week 6** — P3 optimize (`normalizeMessages` single-pass refactor) gated by the benchmarks from week 2.
7. **Week 7** — First-use baseline instrumentation + one release-boundary measurement window.
8. **Week 8** — Cross-device continuity first cut (TUI → mobile handoff via the existing SDK + EventFeed + SessionV2 + session_pending seams). Measure state convergence.

## Risks

- **H8.1 is on the critical path for everything else.** If it slips, R1 (Tier 2.5) and the cross-device story (Tier 3.6) both stall because both want per-scope identity.
- **P3 refactor without the characterize step is a trap.** The seven invariants are load-bearing; doing the perf work without pinning them first will silently regress one.
- **Promoting Proposed specs is high-value but low-glory.** Allocate a maintainer to shepherd each one through test-pin promotion; otherwise the spec list grows but the test surface doesn't.
- **Three Tiers collide on the same files** (`server.ts`, `server-router.ts`, `public.ts`). Sequence H8.1 before R1 and the cross-device work, or merge them carefully.
