## Problemi Identificati

### 1. **Frammentazione dello State** ⚠️

Lo state è disperso in più contesti con responsabilità sovrapposte:

```
sync.tsx    → provider, agent, session, message, part, todo, mcp, config
local.tsx   → model, agent (di nuovo!), mcp (di nuovo!), connectors
kv.tsx      → generico, usato per model.json come storage
```

**Problema**: `model.json` viene scritto/letto sia in `sync.tsx` (via SDK) che in `local.tsx` (direttamente da file).

### 2. **Error Handling Silenzioso** ⚠️

```typescript
// Pattern ripetuto - errori " divorati "
.catch(() => {})
.catch(() => {})
.catch(() => {})
```

### 3. **Binary Search Ripetuto** ⚠️

```typescript
// Stesso pattern ripetuto 15+ volte
const match = Binary.search(store.session, sessionID, (s) => s.id)
if (match.found) return store.session[match.index]
```

### 4. **Race Conditions negli Eventi SSE** ⚠️

```typescript
// sdk.tsx - timer logic fragile
if (elapsed < 16) {
  timer = setTimeout(flush, 16)
  return
}
flush()
```

### 5. **Type Safety Inconsistente** ⚠️

```typescript
// kv.tsx - any ovunque
const [store, setStore] = createStore<Record<string, any>>()

// sync.tsx - BackgroundJob duplicato (già definito altrove?)
type BackgroundJob = { ... }
```

### 6. **Ciclo di Vita Non Garatito** ⚠️

```typescript
// history.tsx - write su mount può fallire senza cleanup
onMount(async () => { ... })
```
