# nikcli Package Review - Comprehensive Analysis

Based on exploration by 10 parallel agents, here's a complete overview of the nikcli package.

---

## 📦 Package Overview

**Location:** `packages/nikcli/`
**Runtime:** Bun with TypeScript ESM
**Purpose:** AI-powered CLI agent with TUI interface, server backend, and plugin system

---

## 🏗️ Architecture Summary

### 1. Entry Points & CLI Structure

| File               | Purpose                                                     |
| ------------------ | ----------------------------------------------------------- |
| `bin/nikcli`       | Binary launcher (Node wrapper for platform-specific binary) |
| `src/index.ts`     | Main CLI entry - yargs-based command router (24 commands)   |
| `src/cli/cmd/tui/` | SolidJS-based TUI using `@opentui/solid`                    |

**Commands:** RunCommand, GenerateCommand, DebugCommand, AgentCommand, SessionCommand, etc.

---

### 2. Tool System (`src/tool/`)

**Pattern:** `Tool.define(id, { description, parameters, execute })`

| Built-in Tools | Purpose                   |
| -------------- | ------------------------- |
| `BashTool`     | Shell commands            |
| `ReadTool`     | File reading              |
| `EditTool`     | File editing              |
| `WriteTool`    | File writing              |
| `GlobTool`     | Pattern matching          |
| `GrepTool`     | Content search            |
| `TaskTool`     | Subagent delegation       |
| `MonitorTool`  | Background job management |

**File Naming:** kebab-case (e.g., `memory-search.ts`)
**Output Format:** `{ title, metadata, output, attachments? }`

---

### 3. Agent System (`src/agent/agent.ts`)

| Agent Type | Examples                               | Mode               |
| ---------- | -------------------------------------- | ------------------ |
| Primary    | `ralph`, `build`, `plan`               | Full permissions   |
| Subagent   | `explore`, `debugger`, `code-reviewer` | Restricted toolset |
| Internal   | `delegator`, `compaction`, `title`     | Hidden             |

**Delegation Pattern:** Primary agents launch subagents with `task(background: true)`

---

### 4. Server Architecture (`src/server/server.ts`)

**Framework:** Hono.js + Bun.serve()
**Port:** 4096 (with fallback)
**Auth:** Basic auth, Tailscale, Bearer tokens

| Route Group   | Endpoints                        |
| ------------- | -------------------------------- |
| `/session`    | CRUD, messages, prompts, sharing |
| `/project`    | Project listing, management      |
| `/provider`   | AI providers, OAuth              |
| `/pty`        | WebSocket PTY sessions           |
| `/mcp`        | Model Context Protocol           |
| `/tui`        | TUI control events               |
| `/connectors` | GitHub, external services        |
| `/chatbot`    | Discord, Slack, Teams webhooks   |

---

### 5. Storage System (`src/storage/storage.ts`)

**Format:** JSON files on disk (`~/.nikcli/storage/`)
**Key Pattern:** `["collection", "id", ...]`

| Collection | Storage Key                         |
| ---------- | ----------------------------------- |
| `project`  | `["project", id]`                   |
| `session`  | `["session", projectID, sessionID]` |
| `message`  | `["message", sessionID, messageID]` |
| `part`     | `["part", messageID, partID]`       |

**Operations:** `read()`, `write()`, `update()`, `remove()`, `list()`
**Concurrency:** Reader-writer locks per file

---

### 6. Session & Message Architecture

**Identifier Formats:**
| Type | Prefix | Ordering |
|------|--------|----------|
| Session | `ses_` | Descending (newest first) |
| Message | `msg_` | Ascending (chronological) |
| Part | `prt_` | Ascending (chronological) |

**MessageV2 Parts:** TextPart, ReasoningPart, FilePart, ToolPart, AgentPart, SnapshotPart, etc.

---

### 7. Type System

**Pattern:** Zod schemas with `.meta()` for SDK generation

```typescript
export const Info = z.object({...}).meta({ ref: "MyType" })
export type Info = z.infer<typeof Info>
```

**Found:** 215+ `.meta()` usages, 225+ `z.infer` usages

---

### 8. Error Handling

**Primary Pattern:** `NamedError.create(name, schema)`

```typescript
export const SomeError = NamedError.create("ErrorName", z.object({...}))
```

**Error Classes Found:**

- `Storage.NotFoundError`
- `Provider.ModelNotFoundError`
- `Session.BusyError`
- `Permission.RejectedError`
- `UI.CancelledError`

---

### 9. Logging Pattern

```typescript
const log = Log.create({ service: "module-name" })
log.info("message", { key: value })
using _ = log.time("operation") // Auto-dispose timing
```

**Levels:** DEBUG, INFO, WARN, ERROR

## 📝 Notes for Code Quality

- **No mocks/placeholders** - Tests use real implementations
- **No TODO/FIXME** - All code production-ready
- **File naming:** camelCase for files
- **Schema metadata:** Use `.meta({ ref: "..." })` for SDK generation
- **Storage keys:** Always use `["collection", "id", ...]` pattern
- **ID ordering:** Descending for sessions, ascending for messages/parts
