## 2. Core Patterns Analysis

### 2.1 Tool System ✅ (Excellent)

**Pattern:** `Tool.define(id, initFn)` with automatic Zod validation and output truncation.

```typescript
// Example from tool/tool.ts
export function define<Parameters extends z.ZodType, Result extends Metadata>(
  id: string,
  init: Info<Parameters, Result>["init"],
): Info<Parameters, Result> {
  return {
    id,
    init: async (initCtx) => {
      const toolInfo = await init(initCtx)
      toolInfo.execute = async (args, ctx) => {
        toolInfo.parameters.parse(args) // Auto-validation
        const result = await execute(args, ctx)
        return Truncate.output(result.output) // Auto-truncation
      }
      return toolInfo
    },
  }
}
```

**Strengths:**

- Clean abstraction with lazy initialization
- Automatic Zod schema validation
- Built-in output truncation
- Custom validation error formatting support
- Tool registry with plugin support

### 2.2 Session Management ✅ (Excellent)

**Pattern:** JSON file storage with AsyncLocalStorage context propagation.

```typescript
// Storage layout
storage/
├── project/{id}.json
├── session/{projectID}/{sessionID}.json
├── message/{sessionID}/{messageID}.json
├── part/{messageID}/{partID}.json
├── session_diff/{sessionID}.json
```

**Strengths:**

- Hierarchical storage with proper locking
- Event-driven updates via Bus
- Session forking with message cloning
- Automatic sharing (optional)
- Workspace-aware sessions

### 2.3 Event Bus Pattern ✅ (Excellent)

```typescript
// Bus.publish(Session.Event.Created, { info: session })
// Bus.subscribe() for SSE streaming
const Event = BusEvent.define("session.created", z.object({ info: Session.Info }))
```

**Strengths:**

- Type-safe event definitions with Zod
- AsyncIterable subscription interface
- Works with SSE streaming

### 2.4 Provider System ✅ (Excellent)

**Pattern:** Provider factory with model abstraction supporting 20+ AI providers.

**Strengths:**

- Unified model interface across providers
- Automatic provider discovery (Ollama, etc.)
- Cost calculation with caching support
- Token usage tracking

## 9. Monitor/Advisor Tool Bugs (Real Issues)

### Bug #1: Error messages not written to log file

**File:** `src/monitor/manager.ts:369-374`  
**Severity:** Medium

When a process emits an `'error'` event, the error is added to `pendingDelta` and scheduled for flush, but **not written to the log file**.

```typescript
runtime.process.once("error", (error) => {
  const text = `\n[monitor error] ${...}\n`
  runtime.pendingDelta += text
  runtime.outputTail = appendTail(runtime.outputTail, text)
  scheduleFlush(runtime)
  // Missing: runtime.logStream.write(text)
  void finalize(runtime, "error", 1, null)
})
```

**Impact:** Log files won't contain error messages when processes crash.

### Bug #2: Timeout timer not cleared on cancel

**File:** `src/monitor/manager.ts:542-550`  
**Severity:** Low

When `cancel()` is called, `clearRuntimeTimers()` is NOT called, so the timeout timer continues running.

```typescript
export async function cancel(sessionID: string, monitorID: string): Promise<Record> {
  const active = state().get(key(monitorID))
  if (active && active.record.sessionID === sessionID) {
    // Missing: clearRuntimeTimers(active)
    await Shell.killTree(active.process, { exited: () => active.exited }).catch(() => {})
    return active.record
  }
```

**Impact:** After cancelling, timeout callback may fire and attempt duplicate cleanup.
