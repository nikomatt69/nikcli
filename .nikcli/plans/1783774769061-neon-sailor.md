# Remove the mobile top queue banner

## Context

The overlap comes from `SessionQueueBanner` being rendered at the root of the session screen before the header container applies `paddingTop: top + 8`. On iPhones, that places the banner at `y=0`, underneath the status bar and Dynamic Island. The session composer already renders the agent/queue status in the safe bottom area, so the top banner is duplicate UI.

## Implementation

1. Update `packages/mobile/app/(app)/sessions/[sessionId].tsx`:
   - Remove the `SessionQueueBanner` import and top-level render above the safe-area-padded header.
   - Keep the existing header safe-area spacing unchanged so the title and controls remain below the Dynamic Island.
   - Pass the offline queued-message count to the existing composer status area, preserving feedback that was previously owned by the removed top banner.

2. Update `packages/mobile/components/session/SessionComposer.tsx`:
   - Accept the offline queued-message count.
   - Show offline saved-message feedback in the existing bottom status pill, with priority over normal processing/queued text and the existing warning treatment.
   - Keep the current agent-working and queued-message behavior in the composer unchanged for online sessions.

3. Delete `packages/mobile/components/SessionQueueBanner.tsx` after confirming it has no remaining references, avoiding an unused duplicate component.

## Verification

- Run `bun run typecheck` from `packages/mobile`.
- Search for `SessionQueueBanner` to confirm no stale imports or renders remain.
- Launch the iOS app and open an active session on a Dynamic Island device/simulator; verify no queue banner appears above the header and no content overlaps the clock or Dynamic Island.
- Verify the bottom composer pill still reports agent-working and queued-message states.
- Simulate an offline send and verify the saved-message count appears in the bottom composer status area rather than at the top of the screen.
- Check an Android device/emulator to ensure the session header and composer layout remain unchanged.
