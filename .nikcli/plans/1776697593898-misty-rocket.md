# nikcli vs opencode integration plan

## Goal

- Close the highest-value product gaps that opencode exposes today without copying areas where nikcli is already ahead.

## Recommended scope

- Prioritize four tracks together: `workspace restore + replay`, `TUI restore UX`, `run CLI ergonomics`, and `bash/shell portability`.
- Do not spend time duplicating docs/RAG, connectors, subagent breadth, `/review`, or compaction/revert flows; nikcli already covers those well enough.

## Phase 1 - real workspace restore and replay

- Expose a real restore endpoint in `packages/nikcli/src/server/routes/workspace.ts` instead of only create/list/remove.
- Expand `packages/nikcli/src/workspace/index.ts` so `Workspace.restore()` returns more than "wait until connected": include replayable session/event state for remote workspaces and reconnect catch-up semantics.
- Extend `packages/nikcli/src/workspace/db.ts` to persist restore/sync state that survives reconnects and client restarts.
- If replay needs workspace-side transport support, wire it through `packages/nikcli/src/workspace/workspace-server/routes.ts` and `packages/nikcli/src/workspace/session-proxy-middleware.ts`.
- Regenerate the SDK after route changes with `./packages/sdk/js/script/build.ts`.

## Phase 2 - make restore work in the TUI

- Replace the current optimistic `sessionRestore?` probe in `packages/nikcli/src/cli/cmd/tui/component/dialog-workspace-create.tsx` with typed SDK support.
- Update `packages/nikcli/src/cli/cmd/tui/component/dialog-workspace-list.tsx` to prefer restoring the latest/root workspace session before creating a new one.
- Teach `packages/nikcli/src/cli/cmd/tui/context/sync.tsx` to hydrate restored sessions from replay/history instead of only the current live sync path.
- Keep the UX centered on "resume where I left off" for remote/container workspaces.

## Phase 3 - bring `run` closer to opencode parity

- Add first-class fork flow in `packages/nikcli/src/cli/cmd/run.ts` using existing backend support from `packages/nikcli/src/session/index.ts` and `packages/nikcli/src/server/routes/session.ts`.
- Add optional reasoning output in `packages/nikcli/src/cli/cmd/run.ts`; the schema support already exists in `packages/nikcli/src/session/message-v2.ts`.
- Expand attach ergonomics in `packages/nikcli/src/cli/cmd/run.ts` with explicit auth and remote directory/workspace targeting instead of plain `baseUrl` only.
- Replace the current always-interactive permission prompt path in `packages/nikcli/src/cli/cmd/run.ts` with an explicit headless policy surface suited to local TTY, CI, and `--attach` use.

## Phase 4 - harden bash and shell portability

- Upgrade `packages/nikcli/src/tool/bash.ts` to parse more than Bash-only command structure, especially PowerShell-aware file/path extraction and safer permission pattern generation.
- Extend `packages/nikcli/src/shell/shell.ts` so shell selection is capability-aware, not just fallback-based.
- If shell behavior/instructions change, sync the wording in `packages/nikcli/src/tool/bash.txt`.
- Keep nikcli's current safety posture, but borrow opencode's richer parsing and env-injection model where it improves permission accuracy and cross-platform behavior.

## Verification

- Regenerate the SDK with `./packages/sdk/js/script/build.ts`, then run `bun run typecheck` and `bun run build` in `packages/nikcli`.
- Manual workspace flow: create a remote/container workspace, create a session inside it, disconnect/restart, then confirm the TUI restores the existing session instead of forcing a fresh one.
- Manual reconnect flow: generate session activity while disconnected, reconnect, and verify the restored workspace catches up without dropped or duplicated state.
- Manual CLI flow: validate `run` continue/fork behavior, optional reasoning output, attach auth/directory targeting, and headless permission modes.
- Manual shell flow: validate Bash and PowerShell-style commands with quoted paths, env-prefixed commands, redirects, timeouts, and aborts.

## Risks to validate while building

- Keep the restore payload small enough for the TUI while still covering replay/history needs.
- Route changes in workspace/session APIs require SDK regeneration and typed client updates immediately after the server work lands.
- The workspace replay design should preserve nikcli's existing remote/container model rather than forcing an opencode-style worktree-only abstraction.
