## 1. Architettura Generale e Entry Points

### Catena di avvio

```
bin/nikcli → src/index.ts (Yargs CLI) → cli/bootstrap.ts → Instance.provide() → InstanceBootstrap()
```

### Stack di layer (dal basso verso l'alto)

```
┌─────────────────────────────────────────────┐
│  CLI (Yargs) — ~30 comandi                  │
├─────────────────────────────────────────────┤
│  TUI (SolidJS + @opentui/solid) — 45 FPS    │
├─────────────────────────────────────────────┤
│  Bootstrap — inizializzazione                │
├─────────────────────────────────────────────┤
│  Instance (DI) — FiberRef/ScopedCache        │
├─────────────────────────────────────────────┤
│  Effect-TS — Context.Tag + Layer.scoped      │
├─────────────────────────────────────────────┤
│  Core Services (Session, Config, Storage)    │
├─────────────────────────────────────────────┤
│  Agent Runtime — 17 agenti                   │
├─────────────────────────────────────────────┤
│  Tool System — 30+ tools                     │
├─────────────────────────────────────────────┤
│  Server (Hono) — 17 route modules            │
└─────────────────────────────────────────────┘
```

### Pattern architetturali chiave

- **Namespace-as-Module**: 18+ namespace major (Agent, Tool, Session, Config, Storage, Log, etc.)
- **Effect-TS DI**: `Context.Tag` → `Interface` → `Layer` → `defaultLayer`
- **Instance-scoped DI**: via `FiberRef`/`ScopedCache`, cached per git root directory
- **`fn()` wrapper**: Validazione Zod con `.force()` per skip

## 2. Sistema Agenti e Tool System

### Agent System (`src/agent/agent.ts`)

Effect-TS DI con `Context.Tag + Layer.scoped`. Ogni `Agent.Info` ha: name, mode, permissions, model overrides, system prompt, config.

#### 17 agenti built-in

| Agente          | Modalità            | Ruolo                         |
| --------------- | ------------------- | ----------------------------- |
| `ralph`         | `primary`           | Agente principale             |
| `build`         | `primary`           | Build/coding agent            |
| `plan`          | `primary`           | Planning agent                |
| `explore`       | `subagent`          | Esplorazione codebase         |
| `fast-explore`  | `subagent`          | Esplorazione rapida read-only |
| `planner`       | `subagent`          | Pianificazione multi-step     |
| `code-reviewer` | `subagent`          | Code review                   |
| `debugger`      | `subagent`          | Debugging                     |
| `test-runner`   | `subagent`          | Esecuzione test               |
| `refactor`      | `subagent`          | Refactoring                   |
| `delegator`     | `subagent`          | Coordinamento background      |
| `researcher`    | `subagent` (hidden) | Ricerca background            |
| + 5 altri       | vari                | Vari ruoli specialisti        |

Agenti utente: creati via CLI come `.md` con YAML frontmatter.

### Tool System (`src/tool/tool.ts`, `src/tool/registry.ts`)

`Tool.define(id, def)` crea tools con parametri Zod-validati ed esecuzione Effect-wrapped.

#### 30+ tools registrati

| Categoria      | Tools                                                                        |
| -------------- | ---------------------------------------------------------------------------- |
| **File ops**   | `read`, `write`, `edit`, `apply_patch`                                       |
| **Search**     | `grep`, `glob`, `tree`                                                       |
| **Execution**  | `bash`, `exec_code`                                                          |
| **Delegation** | `task`, `delegation`, `delegator`                                            |
| **Context**    | `context_collect`, `context_related`, `context_diagnostics`, `memory_search` |
| **Web**        | `webfetch`, `websearch`, `codesearch`                                        |
| **Utilities**  | `todo`, `skill`, `speak`, `advisor`, `generate_image`, `question`            |

Tools filtrati per agente/modello in `resolveTools()`.

### Sistema Permessi (`src/permission/next.ts`)

Tre azioni: `allow`, `deny`, `ask`. Regole mergate da: agent defaults → user config → session overrides. `PermissionNext.evaluate()` trova l'ultima regola matching. Subagenti hanno isolamento stretto.

### Interazione Agent-Tool

```
SessionPrompt.loop()
  → resolveTools(agent, model)  // filtra registry
  → LLM decide tool calls
  → Tool.execute() con validazione Zod
  → task() → background delegation (worker + delegator pair)
  → DelegationManager lifecycle
```

## 3. Sessione, Messaggi e Conversation Loop

### Identifier System (`src/id/id.ts`)

- **Ascending IDs** (cronologici): per messages/parts
- **Descending IDs** (newest-first): per sessions
- Validazione via `Identifier.schema("type")`

### Session Lifecycle (`src/session/index.ts` — 827 linee)

```
create → fork → update → share → delete
```

Storage keys gerarchiche: `["session", projectID, sessionID]`

### Message V2 (`src/session/message-v2.ts`)

Storage normalizzato: messages e parts separati. 12 tipi di parte.

#### Stato tool parts

```
pending → running → completed
                  → error
```

### IL CONVERSATION LOOP — Il cuore di nikcli

**`SessionPrompt.loop()`** in `src/session/prompt.ts` (2473 linee!)

Questo è il loop principale che alimenta tutto il funzionamento di nikcli:

```
┌─────────────────────────────────────────────┐
│              SessionPrompt.loop()            │
│                                              │
│  while (true) {                              │
│    1. Check exit conditions                  │
│    2. Handle subtasks/compaction             │
│    3. Create assistant message               │
│    4. resolveTools(agent, model)             │
│    5. LLM.stream(messages, tools) ───────────┼──→ streamText() AI SDK
│    6. Process streaming chunks               │
│    7. If tool_calls present:                 │
│       a. Execute tools (parallel)            │
│       b. Append tool results to messages     │
│       c. Continue loop (goto 1)              │
│    8. If no tool_calls: break                │
│  }                                           │
│  Return final response                       │
└─────────────────────────────────────────────┘
```

### LLM Streaming (`src/session/llm.ts`)

`LLM.stream()` usa `streamText()` dell'AI SDK con middleware per reasoning extraction.

### Due modalità di esecuzione

- **Provider hierarchy**: ~20 context providers SolidJS

## 5. Server, Storage e Utilities

### Server (`src/server/server.ts`)

**Hono**-based HTTP server con `Bun.serve()`.

#### 17 Route Modules

```
/global, /project, /pty, /config, /experimental, /session,
/permission, /question, /provider, /companion, /user, /mobile,
/, /connectors, /chatbot, /mcp, /tui
```

#### 12 Effect-based HTTP API Groups (nuovo layer)

```
TopLevelHttpApi, ConfigHttpApi, ExperimentalHttpApi, FileHttpApi,
McpHttpApi, ProjectHttpApi, ProviderHttpApi, QuestionHttpApi,
PermissionHttpApi, SessionHttpApi, WorkspaceHttpApi
```

#### Middleware Stack (in ordine)

1. Error handler
2. Public share routes (bypass auth)
3. User auth (JWT)
4. Server auth (basic/Tailscale/bearer)
5. Request logging & timing
6. CORS (localhost, tauri://, capacitor://, nikcli.store, ts.net)
7. Workspace context
8. OpenAPI validator
9. HttpApiBridge (feature-flagged)

#### SSE Event Stream

`GET /event` — Server-Sent Events per real-time sync con TUI.

### Storage System (doppio)

#### JSON File Store (`src/storage/storage.ts`)

- Persistenza in `~/.local/share/nikcli/storage/`
- Cache in-memory con TTL 5-secondi
- File-level read/write locks
- Migration system sequenziale
- API: `read`, `write`, `update`, `remove`, `list`

#### SQLite Database (`src/storage/db.ts`)

- Drizzle ORM over Bun SQLite
- WAL mode, foreign keys, performance PRAGMAs
- Database: `users.db`, `accounts.db`, `workspace.db`, `mobile_auth.db`

### Configuration (`src/config/config.ts` — 68KB!)

Precedenza di caricamento (dal più basso al più alto):

1. Remote well-known configs
2. Global user config (`~/.config/nikcli/nikcli.json`)
3. Custom config path (`NIKCLI_CONFIG`)
4. Project-level `nikcli.json`
5. `.nikcli/` directory configs
6. Inline config content (`NIKCLI_CONFIG_CONTENT`)

Config.Info include: theme, server, remote, model, agent, provider, mcp, connectors, permission, command, plugin, formatter, lsp, compaction, rag, image, speak, notifications, experimental, ads.

### Plugin System (`src/plugin/index.ts`)

- Effect-based lifecycle
- 6 built-in auth plugins: CodexAuth, CopilotAuth, CursorAuth, CloudflareWorkers, CloudflareAIGateway, Notify
- External plugins: npm packages o `file://` URLs
- Hooks: `config`, `event`, `tool`, `provider`, lifecycle

### Utility Modules (32 files in `src/util/`)

| Module          | Purpose                                                |
| --------------- | ------------------------------------------------------ |
| `fn.ts`         | Validated function wrapper                             |
| `log.ts`        | `Log.create()` logging (levels, timing, file rotation) |
| `lock.ts`       | In-process reader-writer lock                          |
| `flock.ts`      | Cross-process file lock                                |
| `filesystem.ts` | File ops (readJson, findUp, globUp, etc.)              |
| `context.ts`    | AsyncLocalStorage context                              |
| `rpc.ts`        | JSON-RPC over postMessage for Workers                  |
| `queue.ts`      | AsyncQueue con work/workMap                            |
| `wildcard.ts`   | Glob pattern matching                                  |
| `effect-zod.ts` | Zod ↔ Effect Schema bridge                            |
| ...             | +22 altri                                              |

### Memory/Context System

- `memory_search.ts`: keyword-based search su sessioni passate
- `brain/`: consolidamento memoria automatico (feature-flagged)
- `session/compaction.ts`: gestione context window
- `session/summary.ts`: riassunto automatico sessioni

### Event Bus (`src/bus/`)

- Per-instance Bus con `publish`, `subscribe`, `once`
- GlobalBus singleton per cross-instance
- `BusEvent.define(type, schema)` per eventi tipizzati
