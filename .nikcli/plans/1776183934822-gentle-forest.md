# Background Agents & Advisors Analysis

## 1. OVERVIEW

The nikcli codebase implements two distinct background processing patterns:

- **Background Agents (BG Agents)**: Delegation-based tasks with session management
- **Advisors**: Strategic guidance via separate model calls

---

## 2. BACKGROUND AGENTS

### Core Components

| Component        | File                        | Purpose                                     |
| ---------------- | --------------------------- | ------------------------------------------- |
| `BackgroundRun`  | `src/background/run.ts`     | Persistent storage for background runs      |
| `Delegation`     | `src/delegation/manager.ts` | In-memory orchestration, timers, heartbeats |
| `TaskTool`       | `src/tool/task.ts`          | Tool for launching background subtasks      |
| `DelegationTool` | `src/tool/delegation.ts`    | Tool for managing delegations               |

### Lifecycle

```
Delegation.create()
├── BackgroundRun.create() -> Storage.write()
├── activeDelegations.set()
├── setTimer() -> setTimeout(10min)
└── setHeartbeat() -> setInterval(5sec)

Delegation.finalize()
├── BackgroundRun.finalize() -> Storage.update() + artifact
├── Bus.publish(DelegationCompletedEvent)
└── cleanup() -> clearTimer(), clearHeartbeat()
```

### Key Features

- **Timers**: 10-minute default timeout
- **Heartbeats**: Refresh every ~5 seconds
- **Lease system**: 15-second timeout for orphan detection
- **Reconciliation**: Runs every 15 seconds to detect orphaned runs
- **Artifacts**: Stored as markdown in `~/.local/share/nikcli/delegations/<parentSessionID>/<id>.md`

## 3. ADVISORS

### Core Implementation

| Component       | File                       | Purpose                                  |
| --------------- | -------------------------- | ---------------------------------------- |
| `AdvisorTool`   | `src/tool/advisor.ts`      | Strategic advisor tool using delegations |
| `Agent.advisor` | `src/agent/agent.ts:44-52` | Agent definition with advisor config     |

### Flow

```
Config (provider/modelID) -> Provider.parseModel() -> Agent.Info.advisor
-> ToolRegistry filters advisor by agent?.advisor
-> AdvisorTool.init({ agent }) receives context
-> generateText() called asynchronously
-> Delegation.finalize() with results
```

### Configuration

```json
{
  "agent": {
    "build": {
      "advisor": "anthropic/claude-sonnet-4",
      "advisor_max_uses": 5
    }
  }
}
```

### Key Observations

- `usesLeft` counter is **closure-based** (resets per tool instance)
- Uses fixed system prompt for strategic guidance
- Creates delegation and returns immediately
- Max uses default: 3
