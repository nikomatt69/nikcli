# Enterprise Background Agents Integration Plan

## Goal

Rendere i background agents deterministici, isolati per job, coerenti tra backend e TUI, e privi di stato duplicato o ambiguo.

Target invariants:

- Un background job ha una sola identita' stabile.
- Backend e TUI leggono la stessa fonte di verita'.
- Nessun task background puo' contaminare altri job dello stesso parent session.
- Aprire un job, cancellarlo, dismissarlo e seguirlo sono azioni distinte e coerenti.
- Nessun caching di tool puo' riusare closure o metadata di un turno precedente.

## Validated Blockers

### 1. Tool cache non sicuro tra turni

`packages/nikcli/src/session/prompt.ts` cachea tool instances per modello, ma quelle instances chiudono su `processor`, `messageID`, `agent`, `permissions` e `bypassAgentCheck` del turno corrente.

`packages/nikcli/src/session/llm.ts` muta inoltre la map dei tool in place durante filtering e `_noop` injection.

Effetto: metadata e permission flows possono finire sul messaggio sbagliato, tool disabilitati possono restare rimossi nei turni successivi, e il cache puo' rimanere contaminato da tool runtime-only come `StructuredOutput`.

### 2. Synthesis background a scope parent session invece che per job

`packages/nikcli/src/tool/task.ts` crea un worker delegation e un delegator delegation per singolo background task, ma poi usa `Delegation.waitForSettled(parentSessionID)` e `Delegation.collectResults(parentSessionID)`.

Effetto: job indipendenti lanciati dallo stesso parent session si aspettano a vicenda, si contaminano nelle synthesis e possono restare bloccati da task non correlati.

### 3. TUI con modello background session-centric e KV-centric

La TUI ricostruisce i background jobs da `sessionId` / `delegatorSessionId` presenti nei metadata del tool `task` e li salva in KV locale.

La fonte di verita' durabile esiste gia' in `packages/nikcli/src/background/run.ts` e `packages/nikcli/src/delegation/manager.ts`, ma `packages/nikcli/src/cli/cmd/tui/context/sync.tsx` non la espone.

Effetto: count, status, cancel, dismiss, resurface e dialog mostrano prospettive diverse dello stesso job.

### 4. Contratto del delegator incompleto

Il prompt del delegator supporta `Action: finalize | continue` e `Spawn`, ma `packages/nikcli/src/tool/task.ts` oggi legge solo `Action`.

Effetto: il percorso multi-round dichiarato esiste a livello prompt, ma non e' realmente implementato end-to-end.

### 5. Semantica di auth/cancel non uniforme

`delegation.ts`, `delegator.ts`, routes session e TUI usano scope leggermente diversi tra session, delegation e delegator session.

Effetto: cancellare dal worker, dal supervisor o dalla dialog non garantisce sempre che venga fermato lo stesso job logico.

## Recommended Architecture

## 1. Tool lifecycle a due livelli

- Cacheare solo definizioni immutabili o factory pure dei tool, mai `AITool.execute` gia' bindati al turno.
- Creare sempre closure nuove per ogni `SessionPrompt.prompt()`.
- Rendere `packages/nikcli/src/session/llm.ts` completamente non mutante: copiare la tool map prima di disabilitare tool o aggiungere `_noop`.
- Trattare `StructuredOutput` come tool runtime-only del singolo turno, mai persistito nel cache.

Risultato: performance preservata senza riuso di contesto stale.

## 2. Modello job-tree durabile per le delegations

Estendere `BackgroundRun.Record` con campi job-centrici:

- `jobID`
- `rootDelegationID`
- `parentDelegationID`
- `role` (`worker`, `delegator`, `followup`, `advisor`, `other`)

Regole:

- Il worker delegation iniziale e' il root del job.
- Il delegator e gli eventuali follow-up appartengono allo stesso `jobID`.
- Session IDs diventano riferimenti di navigazione, non l'identita' del job.

## 3. Orchestrazione task per job, non per parent session

`packages/nikcli/src/tool/task.ts` deve:

- creare worker + delegator dentro lo stesso job tree;
- finalizzare il worker senza aspettare job non correlati;
- raccogliere risultati solo dal job corrente;
- supportare davvero `continue + spawn` creando nuove child delegations nello stesso job;
- finalizzare il delegator quando l'intero job tree e' concluso.

## 4. Delegation come fonte di verita' TUI

`packages/nikcli/src/cli/cmd/tui/context/sync.tsx` deve esporre una projection dei background jobs durabili, keyed by `rootDelegationID`.

KV locale deve restare solo per view state locale:

- dismissed
- expanded/collapsed
- last-opened
- surfacing preferences

Mai per esistenza, stato o ownership del job.

## 5. UX TUI unificata

Un job visibile = una riga visibile.

Stati da mostrare esplicitamente:

- `running`
- `retrying`
- `synthesizing`
- `completed`
- `error`
- `cancelled`
- `timeout`
- `orphaned`

Azioni distinte:

- `open summary`
- `open worker`
- `cancel job`
- `dismiss`

Il delegator deve essere considerato parte interna del job. Non deve comparire come secondo job separato nelle liste principali.

## Implementation Plan

### Phase 1 - Fix tool cache correctness first

Modify:

- `packages/nikcli/src/session/prompt.ts`
- `packages/nikcli/src/session/llm.ts`

Changes:

- sostituire il cache attuale con descriptor/factory cache immutabile;
- bindare `execute()` ad ogni turno con `processor`, `messageID`, `ask`, `metadata`, `abort` correnti;
- evitare qualsiasi mutazione in place della tool map dentro `llm.ts`;
- trattare `StructuredOutput` come overlay locale del turno.

Acceptance criteria:

- due turni consecutivi sullo stesso modello non possono condividere context stale;
- disabling di un tool in un turno non lo rimuove nei turni successivi;
- `_noop` non resta nel cache.

### Phase 2 - Introduce durable job-tree metadata

Modify:

- `packages/nikcli/src/background/run.ts`
- `packages/nikcli/src/delegation/manager.ts`

Changes:

- aggiungere `jobID`, `rootDelegationID`, `parentDelegationID`, `role`;
- mantenere backward compatibility in lettura per record esistenti;
- aggiungere helpers job-scoped (`listByJob`, `collectResultsForJob`, `waitForSettledJob`, `cancelJobTree`);
- unificare access checks tra parent session, worker session e delegator session.

Acceptance criteria:

- i record esistenti continuano a leggersi;
- i nuovi record permettono di recuperare un job intero senza scansionare tutto il parent session.

### Phase 3 - Refactor task orchestration to per-job semantics

Modify:

- `packages/nikcli/src/tool/task.ts`
- `packages/nikcli/src/tool/task.txt`
- `packages/nikcli/src/agent/prompt/delegator.txt`
- `packages/nikcli/src/agent/prompt/delegation.txt`

Changes:

- creare root worker + delegator sotto lo stesso `jobID`;
- finalizzare il worker immediatamente quando il worker ha finito;
- fare synthesis solo sul job corrente;
- implementare realmente `continue + Spawn` con follow-up child delegations nello stesso job;
- lasciare il delegator come coordinatore del job, non come entita' parallela indipendente.

Acceptance criteria:

- due job lanciati dallo stesso parent session non si bloccano ne' si contaminano;
- un delegator puo' fare round successivi reali;
- la synthesis finale contiene solo risultati del job corrente.

### Phase 4 - Expose delegation jobs to client / SDK

Modify:

- `packages/nikcli/src/server/routes/session.ts`
- `packages/nikcli/src/tool/delegation.ts`
- `packages/nikcli/src/tool/delegator.ts`
- `packages/nikcli/src/tool/delegation.txt`
- `packages/nikcli/src/tool/delegator.txt`

Changes:

- aggiungere endpoints session-scoped per list / inspect / cancel / read dei background jobs;
- allineare tool `delegation` e `delegator` alla stessa semantica di accesso e presentazione;
- usare naming coerente tra job, delegation, delegator e summary.

Then:

- regenerate SDK: `./packages/sdk/js/script/build.ts`

Acceptance criteria:

- la TUI puo' bootstrapparsi da dati durabili senza scraping dei task metadata;
- cancel/read/inspect agiscono sul job corretto da ogni punto di ingresso.

### Phase 5 - Replace TUI session-centric background model with job-centric projection

Modify:

- `packages/nikcli/src/cli/cmd/tui/context/sync.tsx`
- `packages/nikcli/src/cli/cmd/tui/routes/session/index.tsx`
- `packages/nikcli/src/cli/cmd/tui/routes/session/dialog-bg-agents.tsx`
- `packages/nikcli/src/cli/cmd/tui/routes/session/dialog-subagent.tsx`
- `packages/nikcli/src/cli/cmd/tui/component/prompt/index.tsx`

Changes:

- aggiungere store/projection `backgroundJobs` keyed by `rootDelegationID`;
- derivare badge, lists, dialogs e auto-resurface tutti dalla stessa projection;
- usare KV solo per `dismissed` e preferenze view, keyed by delegation/job ID;
- rimuovere logica duplicata di add/remove/parse title/background session bookkeeping;
- non rimuovere un job dal tray solo perche' e' stato aperto.

Acceptance criteria:

- prompt badge, Background Agents dialog, subagent dialog e task cards mostrano lo stesso conteggio e gli stessi job;
- aprire il worker non equivale a dismiss;
- stati `error/cancelled/timeout/orphaned` sono visibili correttamente.

### Phase 6 - TUI polish for enterprise UX

Modify:

- `packages/nikcli/src/cli/cmd/tui/component/dialog-agent.tsx`
- `packages/nikcli/src/cli/cmd/tui/context/helper.tsx`
- `packages/nikcli/src/cli/cmd/tui/context/local.tsx`
- `packages/nikcli/src/cli/cmd/tui/context/prompt.tsx`

Changes:

- far emergere capability/role degli agenti in modo piu' chiaro;
- tenere supervisor/delegator come dettaglio secondario del job;
- migliorare naming, status copy e affordance per open/cancel/dismiss;
- evitare focus steal: resurface solo quando ha senso e senza interrompere un input/dialog attivo.

Acceptance criteria:

- il comportamento TUI e' prevedibile anche con job multipli, dialog aperte e prompt focused;
- la UI non mostra duplicazioni concettuali dello stesso background job.

## Edge Cases To Cover Explicitly

- due o piu' background jobs paralleli sotto lo stesso parent session;
- worker finito mentre il delegator sta ancora sintetizzando;
- delegator che ritorna `continue` con follow-up spawn;
- cancel dal worker view, dal supervisor view, dal parent view e dalla dialog;
- restart del processo con job `running`, `cancelled`, `timeout`, `orphaned`;
- job aperto in foreground e poi chiuso: non deve sparire dal background center a meno di dismiss esplicito;
- progress summary assente o vuota;
- task metadata legacy presenti per job vecchi o in-flight durante il rollout;
- mismatch tra `session.status` e stato delegation durabile;
- abort/retry/permission flows con stesso modello ma turni consecutivi.

## Verification

### Static / build verification

- `bun run typecheck`
- `bun test`
- `bun run build`
- regenerate SDK if routes/events change: `./packages/sdk/js/script/build.ts`

### Manual end-to-end verification

Run TUI from `packages/nikcli` with `bun run dev` and verify:

1. launch 2-3 `task(background=true)` calls in one parent session;
2. verify each job gets a single visible identity in TUI;
3. verify prompt badge, dialogs and task cards all agree on counts and statuses;
4. verify cancel from every UI entry point cancels the same durable job;
5. verify opening a job does not dismiss it;
6. verify worker completion transitions to `synthesizing` when delegator still runs;
7. verify final summary appears on the same job, not on a second pseudo-job;
8. verify restart recovery and orphan reconciliation;
9. verify a delegator `continue + Spawn` round creates a child delegation inside the same job;
10. verify no stale tool behavior across repeated turns on the same model with different permissions/settings.

### Regression focus

- inline `task(background=false)` must continue to work unchanged;
- advisor/delegation/delegator tool flows must stay functional;
- existing durable records must remain readable;
- TUI should gracefully fallback for legacy jobs until all in-flight jobs are migrated out.

## Recommended Execution Order

1. Fix tool cache and non-mutating tool filtering.
2. Add durable job-tree fields and manager helpers.
3. Refactor `task.ts` to per-job orchestration.
4. Add/align server + SDK delegation job APIs.
5. Move TUI to delegation/job projection.
6. Polish enterprise UX and remove duplicated session-centric leftovers.

This order minimizes risk because it first removes correctness bugs, then introduces the durable data model, then flips orchestration, and only after that migrates the TUI.
