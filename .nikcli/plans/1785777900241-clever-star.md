# packages/nikcli - roadmap completa

## Obiettivo

Ridurre il rischio operativo e la complessita di `packages/nikcli` senza cambiare comportamento o contratti pubblici: prima ripristinare una suite deterministica, poi separare i principali hotspot, convergere su SQL/session v2 ed Effect HttpApi, rendere il lifecycle realmente scoped e solo alla fine estrarre i package.

La roadmap va eseguita in PR piccole e ordinate. Ogni fase parte solo quando il gate della fase precedente e verde. Le modifiche preesistenti in `packages/inference-dashboard/.astro/` restano fuori scope.

## Vincoli

- Nessun refactor architetturale mentre `bun run test` e rosso.
- Una PR non mescola migrazione di boundary e cambi di comportamento prodotto.
- Conservare operation ID, error shape, status HTTP, eventi, config precedence e API esportate.
- Tenere fallback e feature flag fino a un ciclo di soak; rimuoverli in una PR separata.
- Rigenerare l'SDK dopo ogni modifica OpenAPI/server endpoint.
- Non iniziare `packages/core`, `packages/server` o `packages/cli` finche le dipendenze interne non sono orientate correttamente.

## Fase 1 - Stabilizzare SQLite e la suite

### PR 1.1: lifecycle esplicito del database

File principali:

- `packages/nikcli/src/database/database.ts`
- `packages/nikcli/test/helpers/sqlite.ts`
- `packages/nikcli/test/preload.ts`
- `packages/nikcli/test/database/database.test.ts`
- test che assegnano direttamente `NIKCLI_TEST_HOME`

Azioni:

1. Sostituire il singolo `_singleton` implicito con un registry di handle indicizzato per filename; l'accesso continua a risolvere il path corrente, ma cambiare path non chiude un handle che puo essere ancora usato da lavoro asincrono.
2. Esporre un lifecycle idempotente e ristretto (close di un filename e close-all per shutdown/test), cancellando anche timer/checkpoint associati prima di chiudere SQLite.
3. Correggere l'ordine di teardown: fermare risorse/istanze appartenenti al test, chiudere e rimuovere l'handle dal registry, poi eliminare database/WAL/SHM e directory temporanea.
4. Impedire a `withIsolatedDatabase` di cancellare un home mentre esistono handle o disposer attivi; il helper deve ripristinare l'ambiente anche in caso di errore.
5. Centralizzare il default test home in `test/preload.ts` e disabilitare il checkpoint periodico nella suite. Migrare le assegnazioni module-level di `NIKCLI_TEST_HOME` verso il helper/lifecycle comune, iniziando dai test session, server, worktree e plugin Island.
6. Non usare `Instance.disposeAll()` come cleanup indiscriminato se puo interferire con un altro test: registrare e disporre le sole directory/istanze create dal caso.

Gate:

- `bun test test/helpers/sqlite.test.ts test/database/database.test.ts test/worktree/sandbox.test.ts test/worktree/list.test.ts test/plugin/island/bridge.test.ts` passa.
- `bun run test` passa tre volte consecutive senza `SQLITE_IOERR*`.
- `bun run typecheck`, `bun run format:check` e `bun run lint` escono 0.

## Fase 6 - Estrazione package, solo dopo convergenza

Ordine:

1. estrarre schemi e servizi puri in `packages/core` senza dipendenze da CLI/server;
2. creare `packages/server` con `definition/*` e `api/*`, dipendente solo da core;
3. spostare OpenAPI, handler Effect e Bun host in server;
4. estrarre entrypoint/TUI in `packages/cli`;
5. mantenere temporaneamente `packages/nikcli` come package aggregatore/bin compatibile, poi ridurlo.

Regole di dipendenza:

- `core` non importa server, CLI, TUI o SDK;
- `server` importa core, mai nikcli/CLI;
- `cli` importa core/server e parla al runtime attraverso i boundary pubblici;
- SDK resta generato da un solo OpenAPI artifact.

Gate:

- controllo automatico dei cicli workspace/import.
- build multipiattaforma e smoke del bin invariati.
- consumer plugin, mobile, studio e SDK compilano senza import interni dal vecchio monolite.

## Track paralleli controllati

Dopo la Fase 1 possono continuare, in PR separate:

- native LLM: context-overflow -> compaction, fallback reason tags e abort HTTP nativo;
- TUI: modularizzazione dei mega-componenti e soak dei flag gia implementati;
- performance: audit del module graph e benchmark startup/heap.

Questi track non possono modificare contemporaneamente gli stessi hotspot durante una PR di estrazione.

Da `packages/nikcli`:

`bun run format:check`
`bun run lint`
`bun run typecheck`
`bun run test`
`bun run test:integration`
`bun run test:e2e`

Dal root:

`bun run typecheck`
`./packages/sdk/js/script/build.ts`
`git diff --exit-code -- packages/sdk` (oppure review esplicita del diff atteso)
`bun run build`

Verifiche comportamentali:

1. `nikcli` apre la TUI, crea una sessione, esegue un tool e riprende la sessione dopo restart.
2. `nikcli run` completa un prompt con AI SDK e con native LLM flaggato.
3. `nikcli serve` risponde su auth, session CRUD, prompt stream e SSE.
4. PTY websocket, mobile bootstrap e workspace remote proxy completano i rispettivi smoke test.
5. Dispose/reload non lascia handle, timer, watcher o scritture SQLite tardive.

## Definition of done della roadmap

- Suite completa deterministica e verde.
- Hotspot principali ridotti a moduli coesi con facade stabile.
- Session storage SQL e write path v2 sono gli unici percorsi canonici.
- Effect HttpApi/OpenAPI e la fonte SDK; Hono non implementa piu route duplicate.
- Risorse di istanza hanno lifecycle scoped verificato.
- Package core/server/cli hanno dipendenze acicliche e il bin mantiene compatibilita.
