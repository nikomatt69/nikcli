## What the roadmap + specs actually say (read 2026-08-15)

### Shipped (so a new feature must not duplicate)

- **One SQL DB** (`nikcli.db`, `bun:sqlite`, WAL, drizzle migrations, `foreign_keys=ON`, `mmap_size=0`). All domains — sessions, messages, parts, todos, permissions, sync events, loops, missions, monitors, shares, artifacts, projects, analytics, session goals, background runs, routines — are SQL-backed behind Effect repos. `session_diff` is the **only** remaining legacy JSON store, intentionally kept behind `SessionDiffRepo` (`packages/nikcli/src/session/diff-repo.ts`) because snapshot `write-tree` objects may be GC'd by `git gc --prune=7.days` while imported shares may carry only a ready-made `FileDiff[]`.
- **One HTTP surface** — ~286 Effect `HttpApi` endpoints; Hono is gone; clients are generated by `packages/httpapi-codegen`. Editing an endpoint = edit the group + `bun run generate:httpapi-clients` + commit the generated output.
- **One event log** — `sync_event` carries both session and workspace aggregates; one `EventFeed` encoder fans out to both SSE routes with a per-connection lag budget of 4,096 frames (`event-stream-architecture.md`).
- **V2 session model** — `session_entry` is the flat read model, ids lexicographic-order = conversation order. V2 writes land first, v1 = `toV1*`. Slices 1-3 of S4 landed. `SessionV2.prompt` / `create` / `admit` / `loop` are the public write API HTTP uses; `MessageV2` stays the LLM layer.
- **Prompt admission** — `SessionPrompt` exposes `admit` + `loop` (S1). Busy input lives in `session_pending`; Enter queues, Ctrl/Cmd+Enter steers. Promotion is one atomic batched transaction.
- **Tooling** — `ToolRegistry.register` returns a `Handle` (T1); tools may declare `output` zod codecs (T2); tool advertisement is byte-stable via `compareIds`; the wrapper owns validation, truncation, and per-call rejection.
- **Provider policy** — central `Policy` evaluator with full/trailing-prefix wildcards and last-match-wins; legacy `enabled_providers`/`disabled_providers` translate; `provider.use` is enforced in catalog + listings; TUI disconnect writes a deny statement.
- **Instance hot reload** — config watching with scoped, announced cache invalidation; explicit `Provider.refresh()`. Three services have moved over the wire as worked examples (`/tui/config`, connectors, mobile pairing, brain).
- **TUI** — themes lazy-load; semantic tokens (`foreground`/`surface`/…). U1 extraction (sections 1-3 landed) — TUI still has 46 static + 5 dynamic `@/` imports remaining, of which 11 are host files; section 4 (the actual `git mv`) is **prepared but not landed**; 6 host services still need to invert.
- **Graceful restart** — `session_info.time_suspended` partial index, single `UPDATE … RETURNING` claim, advisory resume (no hard-crash recovery).
- **Pending input + instruction sync** — durable `session_pending`; instructions via content-hash delta + `instruction_blob`.

### Explicit non-goals (must not propose)

- Nested `/project/:projectID/session/...` URLs.
- Automatic hard-crash session recovery.
- Clustered session ownership.
- A shared PubSub for the event feed.
- Rebuilding TUI features upstream opencode already has.
- Rewriting `SessionProcessor` or `toModelMessages` to consume `session_entry`.

### Open / not yet planned

- **Define contracts** — empty.
- **Plan later structure** — empty.
- Section 4 of U1 (the actual `git mv` to `packages/tui`) is prepared; six host services still need inverting before it lands.
- The TUI disconnect path's policy write has **no focused test** (`provider-policy.md`).

### Verified working rules (from the roadmap)

- Commit at phase boundaries, not per file.
- Every commit that changes a contract updates its spec in the same commit.
- Verify with `bun test` unit tests and `bun run typecheck` (never bare `tsc`; the repo's `.bin/tsc` is JS 5.x).
- Adding a migration breaks `test/database/database.test.ts`'s journal assertion — update it in the same commit.

## Three grounded feature options

### Option A — `/diff` HttpApi group + TUI diff panel (Recommended)

**Why now.** `SessionDiffRepo` (`packages/nikcli/src/session/diff-repo.ts`) already exists and has only `get` / `upsert` / `remove` against a single `session_diff` table — keyed by `session_id`, holding the full diff list as one JSON blob. Today the only caller is session revert. There is no way to list, search, or render diffs across sessions from any SDK consumer (desktop, mobile, cloud dashboard, companion). This is the **only** legacy storage artifact the roadmap calls out as intentionally retained, and it has zero HTTP surface.

**What it is.**

- A new HttpApi group `packages/nikcli/src/server/httpapi/diff.ts` exposing three read endpoints over `SessionDiffRepo`:
  - `GET /session/:id/diff` — full diff list for a session.
  - `GET /diff/search?path=…&prefix=…&sessionID=…` — search across sessions, using a SQL `LIKE` against the stored JSON for now (cheap, correct); can move to a derived column if a real index is needed.
  - `GET /diff/summary/:sessionID` — derived counts (added/removed/modified + touched paths) computed server-side, so SDK clients don't redo the fold.
- Register the group in `packages/nikcli/src/server/httpapi/top-level.ts` and run `bun run generate:httpapi-clients` to update `packages/sdk/js` and `packages/sdk-next`.
- A TUI panel under `packages/nikcli/src/cli/cmd/tui/feature-diff/` that opens from the session view (`g d` keybind) with the existing diff renderer in `cli/cmd/tui/util/revert-diff.ts` reused.
- One spec doc, modeled on `v2/tools.md` and `tui-package.md`: `specs/v2/session-diff-api.md`.

**Why it is small and safe.**

- `SessionDiffRepo` is done. We only add read methods.
- No new contract surface beyond one HttpApi group; one regen.
- No session lifecycle, no event-stream changes — reads only. `event-stream-architecture.md` is untouched.
- The diff blob is small per session, so a full-list endpoint is fine; the search endpoint is for cross-session browsing.

**Critical files.**

- `packages/nikcli/src/server/httpapi/diff.ts` (new group, modeled on `session.ts`).
- `packages/nikcli/src/server/httpapi/top-level.ts` (register group).
- `packages/nikcli/src/session/diff-repo.ts` (add `search` + `summary` helpers — synchronous `Database.syncDb()` over the existing table).
- `packages/nikcli/src/cli/cmd/tui/feature-diff/` (new module).
- `packages/nikcli/test/server/httpapi-diff.test.ts` (route test, mirroring `httpapi-profile.test.ts`).
- `packages/nikcli/test/session/diff-repo.test.ts` (repo test).
- `specs/v2/session-diff-api.md` (new spec — roadmap rule: contract change ⇒ spec in same commit).
- `packages/sdk/js` + `packages/sdk-next` (regenerated clients, committed alongside).

**Done when.**

- `bun run check:routes` covers the three endpoints.
- A unit test exercises `SessionDiffRepo.search` / `summary` against a fixture with two file diffs.
- The TUI panel renders a known session's diffs and the `g d` keybind is documented in the help overlay.
- `bun run typecheck` passes (33 packages) and `bun test` is at the documented baseline (two known failures: `profile command`, `EditTool`).

### Option B — `session_goal` HttpApi + TUI goal sidebar

**Why now.** `GoalRepo` exists (`remove-json-storage.md` step 4) but has zero HTTP surface — desktop, mobile, and the companion packages cannot see live session goals. The roadmap does not list a goal contract in "Define contracts" yet. Reactive updates ride the existing `EventFeed` (one encoder, per-connection lag budget) so this is pure surface work on a stable storage layer.

**What it is.**

- New HttpApi group `packages/nikcli/src/server/httpapi/goal.ts` modeled exactly on `mission.ts`:
  - `GET /session/:id/goal` (nullable — absent profile-style `null` round-trip, per the `/profile` precedent in `tui-package.md`).
  - `PUT /session/:id/goal` (upsert).
  - `POST /session/:id/goal/complete`, `POST /session/:id/goal/abandon`.
- New event kind `session.goal.updated` flowing through `EventFeed` (additive — same encoder, same wire shape `{type, properties}`, server.connected and 4,096-frame lag budget apply).
- TUI sidebar under `packages/nikcli/src/cli/cmd/tui/feature-goals/` showing the active goal, progress, and a `g g` keybind to jump to the goal conversation entry.
- Spec doc: `specs/v2/session-goal-api.md`.

**Why it is small and safe.**

- Storage is done. Only HttpApi surface + one event kind.
- Existing `EventFeed` (per E1) takes new event kinds without touching its fan-out — the "Not implemented: public filtering" caveat in `event-stream-architecture.md` is irrelevant here; `session.goal.updated` is a client-facing type.
- Mirrors the `mission.ts` HttpApi pattern exactly.
- The `/profile` "absent profile encodes as `null`" lesson applies.

**Critical files.**

- `packages/nikcli/src/server/httpapi/goal.ts` (new group).
- `packages/nikcli/src/server/httpapi/top-level.ts` (register).
- `packages/nikcli/src/storage/repo/goal.ts` (verify CRUD signatures; add if missing).
- `packages/nikcli/src/bus/` (add `session.goal.updated` to the public event schema — see the `cli/cmd/tui/event` → `src/bus/tui-event.ts` move in section 3 of `tui-package.md`).
- `packages/nikcli/src/cli/cmd/tui/feature-goals/` (new module).
- `packages/nikcli/test/server/httpapi-goal.test.ts` + `test/session/goal-repo.test.ts`.
- `specs/v2/session-goal-api.md` (new spec).
- `packages/sdk/js` + `packages/sdk-next` (regenerated).

**Done when.**

- All four endpoints return validated responses (no silent `undefined` traps — explicit `null` for absent goal).
- `session.goal.updated` flows through `/event` and `/global/event` with the documented wire shapes.
- TUI sidebar renders an in-flight goal and updates on the event.
- `bun run typecheck` and `bun test` at baseline.

### Option C — Close one U1 service cycle (smallest scope)

**Why now.** U1's "Next" paragraph lists six remaining host services (`@/effect` (11), `@/config/*` (8), `@/plugin/*` (8)) plus twelve lazily-imported subsystems (`@/chatbot` (3), `@/brain/scheduler`, `@/user/users`, `@/tool/speak/openrouter`). The worked pattern is documented: "check whether the route already exists, declare it if not, run `generate:httpapi-clients`, move the call site, then **curl the route against a real server**." Section 4 is prepared but not landed; closing one more cycle unblocks it.

**What it is.**

- Pick one small, well-bounded service. Suggested order of attack based on `tui-package.md`'s "What Actually Blocks The Move" table:
  - **First pick: `@/tool/speak/openrouter` (2 imports).** It needs an audio-models endpoint. Smallest new surface, clearest "what needs to be true": a `GET /audio/models` route backed by the openrouter auth the speaker module already reads.
  - **Second pick: `@/config/*` plugin install call sites (3).** Use the existing `TuiConfig.{sources,reload,get,waitForDependencies}` operations, which already have HttpApi coverage per the worked example.
- Confirm the HttpApi route exists or add it (per the per-service pattern). Move the TUI call site from a direct `@/effect` import to a generated SDK call. Verify with `bun run src/index.ts serve --port …` + a curl.
- Update `specs/tui-package.md` section 3 table with the new move.

**Why it is small and safe.**

- One service per commit — the roadmap's working rule.
- The pattern is documented end-to-end with worked examples (`/tui/config`, connectors, mobile, brain, profile).
- No design decisions; purely an ownership correction.

**Critical files.** Vary by chosen service; the mechanism is:

- `packages/nikcli/src/server/httpapi/<service>.ts` (route if missing — only for the audio-models pick).
- `packages/nikcli/src/cli/cmd/tui/<service>.ts` (move call site; replace `@/effect` with `sdk.client.<service>.<op>()`).
- `specs/tui-package.md` (append the move to the section 3 table; same commit).
- `packages/sdk/js` + `packages/sdk-next` (regenerated if a route was added).

**Done when.**

- TUI typechecks with `packages/nikcli` excluded from its `tsconfig` references for the chosen service.
- A real `--single` build starts the binary and the chosen feature works end-to-end against the live server.
- `bun test` at the documented baseline.

## Recommended pick

**Option A — `/diff` HttpApi + TUI diff panel.** It targets the only remaining legacy storage artifact the roadmap explicitly defends, ships value to every SDK consumer (desktop, mobile, cloud, companion) for free via codegen, and lives entirely inside well-trodden shapes (HttpApi group + `SessionDiffRepo` + existing diff renderer). Storage is done; only surface work is new.

**Option B** is the right pick if the user prefers pure surface work over the unique "durable artifact" angle of Option A.

**Option C** is the right pick if the user wants to keep closing U1 tech debt before any net-new feature.
