# GitHub device-flow token expiry fix — implementation plan

Repository: `/Volumes/SSD/Projects/nikcli` (branch `live-main`).

## Problem

GitHub App device-flow tokens expire after 8 hours by default ("expire user tokens" enabled). The mobile app stores them via the device-flow sign-in, but currently:

- The stored `expiresAt` is written in **milliseconds** while `ConnectorAuth.isTokenExpiredImpl` (`packages/nikcli/src/connectors/auth.ts:109`) compares it against **`Date.now() / 1000` (seconds)**. The unit mismatch means refresh-on-expiry never fires and `bootstrap.github.tokenAvailable` stays `true` forever (because `githubToken()` falls back to the still-present PAT-style credential).
- `refreshGithubToken` exists but, even when called, persists a fresh `expiresAt` in ms, so the cycle repeats.
- The mobile UI never surfaces `bootstrap.github.reconnectRequired` (= "token stored but live GitHub call failed") as a prominent, actionable reconnect prompt — only as one chip label.
- `MobileResponseError` 401s are surfaced as the generic `error.message` text via `ErrorBanner`, so the user sees e.g. "Bad credentials" instead of "Session expired — reconnect".

## Approach (3 commits-worth of work in one PR)

1. Make `ConnectorAuth.Entry.expiresAt` / `refreshTokenExpiresAt` **seconds** end-to-end, normalized **inside `storeGithubToken`** via a defensive threshold (auto-detects ms vs seconds).
2. Make `githubToken()` **proactively refresh** when within 60 s of expiry (instead of waiting for `isTokenExpired` to flip).
3. Surface `bootstrap.github.reconnectRequired` in the mobile UI with a `Reconnect with GitHub OAuth` action button, and translate `MobileResponseError` 401s into a clear "session expired, reconnect" message.

`MobileBootstrap.github.reconnectRequired` schema field **already exists** at `packages/nikcli/src/server/routes/mobile/helpers.ts:221`, `misc.ts:74` already computes it, `github.tsx:50,81,83` already reads it. **No SDK regeneration required** (verified: `packages/sdk/js/src/httpapi/generated/types.ts:1150` already has `reconnectRequired?: boolean`).

### 1. `packages/nikcli/src/server/routes/mobile/helpers.ts`

**A. Replace the dead constant at line 820** with a seconds-based margin:

```ts
const GITHUB_TOKEN_REFRESH_MARGIN_S = 60 // refresh this far before isTokenExpired returns true
const EXPIRY_MS_THRESHOLD = 1e12 // ~year 33658 in seconds — unambiguously ms values
function normalizeExpiryToSeconds(value: number | undefined): number | undefined {
  if (value === undefined) return undefined
  return value > EXPIRY_MS_THRESHOLD ? Math.floor(value / 1000) : Math.floor(value)
}
```

**B. `storeGithubToken` (lines 788-818)** — normalize both timestamps through `normalizeExpiryToSeconds` before persisting:

```ts
export async function storeGithubToken(tokenOrGrant: string | GithubTokenGrant) {
  const grant: GithubTokenGrant = typeof tokenOrGrant === "string" ? { accessToken: tokenOrGrant } : tokenOrGrant
  const { key } = await ensureGlobalGithubConnector({ enabled: true })
  const entryUpdate = {
    token: grant.accessToken,
    // ConnectorAuth.Entry.expiresAt is seconds since epoch (see ConnectorAuth.isTokenExpiredImpl).
    // Accept either unit on input; values > 1e12 are treated as ms.
    expiresAt: normalizeExpiryToSeconds(grant.expiresAt),
    refreshToken: grant.refreshToken,
    refreshTokenExpiresAt: normalizeExpiryToSeconds(grant.refreshTokenExpiresAt),
  }
  // ...rest unchanged
}
```

**D. `pollGithubDeviceAuth` (lines 969-1035)** — same fix at lines 1001-1004:

**E. `githubToken` (lines 869-892)** — apply the 60 s margin at the call site:

```ts
export async function githubToken() {
  const config = await configGet().catch(() => undefined)
  const { key, connector } = githubConnectorEntry(config)

  const shouldRefresh = await runConnectorAuth(
    Effect.gen(function* () {
      const auth = yield* ConnectorAuth.Service
      const entry = yield* auth.get(key)
      if (!entry?.expiresAt || !entry.refreshToken) return false
      const now = Math.floor(Date.now() / 1000)
      return entry.expiresAt - now <= GITHUB_TOKEN_REFRESH_MARGIN_S
    }),
  ).catch(() => false)

  if (shouldRefresh) {
    const refreshed = await refreshGithubToken(key)
    if (refreshed) return refreshed
  }

  const credential = await resolveCredential(key, connector)
  if (credential) return credential

  if (key !== "github") {
    return resolveCredential("github", connector)
  }

  return null
}
```

Note: `isTokenExpiredImpl` is intentionally **not** modified — keeping the predicate pure means other consumers (e.g. `mcp/index.ts:991`) keep correct behavior.

Read `ConnectorAuth.Service.get("github")`, assert `expiresAt ≈ nowSec + 28800` and `refreshTokenExpiresAt ≈ nowSec + 15811200`. **This test fails before the fix.**

4. **`refreshGithubToken` posts correct body and round-trips.** Pre-seed `ConnectorAuth.Service.set("github", { token: "old", refreshToken: "old-rt", expiresAt: nowSec - 60, refreshTokenExpiresAt: nowSec + 7 * 24 * 3600 })`. Assert body contains `grant_type: "refresh_token"`, `client_id`, `refresh_token: "old-rt"`. Call `githubToken()`. Assert returned token is `"new-a"`. Assert stored `expiresAt ≈ nowSec + 28800`, `refreshTokenExpiresAt ≈ nowSec + 15811200`, `refreshToken === "new-rt"`.

5. **`refreshGithubToken` skips when refresh token is past its expiry.** Pre-seed `refreshTokenExpiresAt: nowSec - 60`. Stub fetch. Assert it is **not** called. Call `githubToken()`. Assert it falls through to `resolveCredential`.
