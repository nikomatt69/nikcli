# Fix flickering bottom-left title in nikcli TUI

## Goal

Stop the bottom-left title (project directory path) in the nikcli TUI session footer from flickering. Reported in screen recording `/Users/nikoemme-os/Desktop/Registrazione schermo 2026-08-13 alle 02.42.06.mov`.

## Root cause (verified by reading the source)

File: `packages/nikcli/src/cli/cmd/tui/routes/session/footer.tsx`

The component returns a single horizontal `<box flexDirection="row" justifyContent="space-between">` containing:

- **Line 91**: `<text fg={theme.textMuted}>{directory()}</text>` — the bottom-left title the user sees flickering.
- Lines 92–141: a right-hand cluster whose reactive sources change repeatedly while the session is alive:
  - `setInterval(..., 60_000)` (lines 68–70) — brain poll, writes `brainEnabled` / `brainLastAt` / `brainSessionsPending` signals.
  - `setInterval(..., 5000 | 10_000)` (lines 34–40) — welcome hint toggle, writes `store.welcome`.
  - `sync.data.*` memos for MCP / LSP / permissions / active command, which update on every server event.

In SolidJS, any reactive read in a parent `<box>` causes the whole subtree to re-render. Because `<text>{directory()}</text>` shares the parent with all of the above, every 60 s (and every sync update) the parent re-runs and remeasures the leftmost text — which is exactly what the user perceives as flicker. The `space-between` layout makes the left edge the visual anchor where re-layout is most obvious.

The directory string itself is stable for the lifetime of the session; only its sibling signals change.

## Plan (minimal, targeted)

The smallest correct fix is to isolate the `<text>{directory()}</text>` element so it does **not** sit in the same reactive scope as the brain / welcome / MCP / LSP signals.

### Edit `packages/nikcli/src/cli/cmd/tui/routes/session/footer.tsx`

1. Replace the top-level parent so the directory text lives outside the row that holds the right-hand cluster:
   - Keep the existing `<box flexDirection="row" justifyContent="space-between" gap={1} flexShrink={0}>` as a container, but **move** the directory `<text>` to its own scoped wrapper so it only re-renders when `directory()` (or its theme colour) changes.
   - Concretely: extract `<text fg={theme.textMuted}>{directory()}</text>` into a small sub-component `const DirText = () => <text fg={theme.textMuted}>{directory()}</text>` (or wrap with a memo around `directory()` to keep it stable), so Solid creates a separate render scope for it.

   Preferred shape:

   ```tsx
   const DirText = () => <text fg={theme.textMuted}>{directory()}</text>
   ```

   Then in the JSX:

   ```tsx
   <box flexDirection="row" justifyContent="space-between" gap={1} flexShrink={0}>
     <DirText />
     <box gap={2} flexDirection="row" flexShrink={0}>
       ...
     </box>
   </box>
   ```

   This preserves the existing visual layout (left edge still anchors the directory text; right cluster is unchanged) but Solid will only invalidate `<DirText />` when `directory()` actually changes, not when the right-hand signals flip.

2. (Optional belt-and-braces) Memoize the `instanceDirectory()` source so it is not re-read on every reactive tick:
   - `const instanceDirectory = createMemo(() => sync.data.path.directory || process.cwd())` — only one extra line, prevents re-runs when unrelated `sync.data.*` keys mutate.

## Why this is the right fix

- Smallest possible diff (one file, a few lines).
- Targets the structural cause (shared parent reactive scope) rather than papering over one of the timers.
- Keeps the welcome-hint and brain-poll features intact — they were added intentionally and they don't actually need to invalidate the directory text.
- No risk to the contract / generated clients / HTTP API surface.
