# Integrazione native `@nikcli-ai/llm` (allineamento OpenCode)

## Obiettivo

Collegare il runtime route-based di `packages/llm` al loop chat di produzione **senza** modificare `session/processor.ts`, **senza** nuovi tipi di errore in session, **senza** cambiare `MessageV2.fromError` / `SessionRetry.retryable`, e con **rollback immediato** (`experimental.nativeLlm: false` = comportamento attuale).

## Vincoli espliciti (richiesta utente)

- **Non** introdurre nuove tassonomie errori in `packages/nikcli`.
- **Non** alterare la propagazione errori nel processor (stesso `catch` → `fromError` → retry).
- **Non** portare in fase 1 da OpenCode: `cache-policy.ts`, `provider-error.ts`, refactor errori in `packages/llm`.
- **Default**: `experimental.nativeLlm` assente o `false` → solo AI SDK (`LLMCore.stream`).

## Stato attuale (verificato)

| Componente                      | Ruolo                                                                                                                                   |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `session/llm.ts`                | `stream()` risolve `modelRef` via `Provider.getModelRef`, opzionale `prepareRequest` (debug), poi **sempre** `LLMCore.stream` (AI SDK). |
| `session/processor.ts`          | Consuma `stream.fullStream` con eventi **AI SDK** (`reasoning-start`, `tool-input-start`, `finish-step`, `error`, …).                   |
| `session/llm/native-runtime.ts` | `LLMClient.stream` + tools eseguibili (**rischio doppio tool loop**); **non** chiamato da `stream()`.                                   |
| `session/llm/native-request.ts` | `buildModel()` ad-hoc — **da sostituire** con `modelRef` + `buildLLMRequest`.                                                           |
| `packages/llm/src/runtime.ts`   | `streamRequest()` → `AsyncIterable<LLMEvent>` (già pronto).                                                                             |
| `config.experimental.nativeLlm` | Definito in `config.ts`; **nessun read** in session.                                                                                    |
| `provider/provider.ts`          | `mapToModelRef` copre già OpenAI/Anthropic/Google/Bedrock/Azure/OpenRouter/…                                                            |

**Gap eventi**: `LLMEvent` ≠ AI SDK (`step-finish` vs `finish-step`, `provider-error` vs `error`, mancano `reasoning-start/end`, `tool-input-start/end`; `tool-result` usa `result` non `output`).

## Strategia raccomandata: **adapter-only**

**Non** refactorare il processor in P0–P2.

Aggiungere un adapter `LLMEvent` → eventi compatibili AI SDK e restituire da `LLM.stream()` lo stesso contratto di oggi:

```ts
{
  fullStream: AsyncIterable<ProcessorStreamEvent>
  text: Promise<string>
}
```

- `text`: `Promise.resolve("")` + `.catch(() => {})` (equivalente a `suppressNoContentText`).
- Errori stream: `provider-error` e fallimenti Effect → **`throw new Error(message)`** (stesso percorso del case `"error"` AI SDK).
- **Non** esporre `LLMError` / `Cause` al processor.

Rationale: minimo rischio di regressione su tool loop, retry, compaction, `opentui` tool-input streaming.

## Fase P0 — Integrazione end-to-end (flag + adapter)

### P0.1 Feature gate

- **File**: `packages/nikcli/src/session/llm.ts`
- Leggere `cfg.experimental?.nativeLlm === true`.
- Condizione native (tutte vere):
  - flag on
  - `modelRef` definito
  - `LLMNativeRuntime.status(...)` → `supported` (estendere status per usare `modelRef` oltre all’allowlist npm attuale, senza cambiare provider non supportati)

Se una condizione fallisce → **path AI SDK invariato** (nessun log error per utente, al massimo `debug`).

### P0.2 Branch native in `LLM.stream`

- **File**: `packages/nikcli/src/session/llm.ts`
- Riutilizzare la stessa preparazione messaggi/tools/headers/params già calcolata prima di `LLMCore.stream` (non duplicare `ProviderTransform`).
- **Request builder (critico)**: usare `modelRef` da `Provider.getModelRef` + `buildLLMRequest()` in `llm.ts` — **non** `LLMNative.request` / `buildModel()` (oggi costruisce un oggetto finto, non un `ModelRef` valido).
- **Tool loop (critico)**: `LLMClient.stream({ request, tools })` senza `toolExecution: "none"` attiva `ToolRuntime` e **esegue i tool dentro llm** → doppio loop con `processor.ts`. P0 deve passare **solo schemi** (`toDefinitions` / tool defs senza execute) oppure `toolExecution: "none"` + stream request-only, allineato al contratto AI SDK (`streamText` + processor esegue tool).
- Eseguire stream via `LLMRuntime.streamRequest` o `llmClient.stream(request)` **request-only**; OAuth: `Stream.provideService(Fetch, …)` come in `native-runtime.ts`.
- Ottenere `LLMClient` con `runPromiseWithLayer(defaultLayer from provider/llm-client.ts, …)` nel branch native (layer non ancora nel runtime Effect globale).
- Rimuovere o ridurre a `debug` il blocco `prepareRequest`-only quando native è attivo (evitare doppio lavoro).
- Log debug: tag `llm.runtime=native` vs `ai-sdk` (solo osservabilità, no cambio errori utente).

### P0.3 Nuovo modulo adapter

- **File nuovo**: `packages/nikcli/src/session/llm/llm-event-adapter.ts` (nome indicativo)
- **Funzione**: `toProcessorStream(llmEvents: AsyncIterable<LLMEvent>): AsyncIterable<AISDKShapedEvent>`
- Stato interno per id testo/reasoning/tool (simile a `ai-sdk.ts` `adapterState`).

#### Tabella mapping (P0 minimo)

| `LLMEvent`                               | Evento verso processor           | Note                                                                                                      |
| ---------------------------------------- | -------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `request-start`                          | (skip o `start`)                 | Opzionale: emit `start` se serve busy status                                                              |
| `step-start`                             | `start-step`                     |                                                                                                           |
| `step-finish`                            | `finish-step`                    | Copiare `usage`, `providerMetadata`, `reason` → `finishReason`                                            |
| `request-finish`                         | `finish`                         |                                                                                                           |
| `text-start` / `text-delta` / `text-end` | omonimi                          | `providerMetadata`                                                                                        |
| `reasoning-delta`                        | `reasoning-delta`                | Sintetizzare `reasoning-start` al primo delta per id; `reasoning-end` prima del prossimo id o a fine step |
| `tool-input-delta`                       | `tool-input-delta`               | Mappare `text` → **`delta`** (campo opentui), `id` → `id` per processor `tool-input-start`/`delta`        |
| `tool-call`                              | `tool-input-start` + `tool-call` | Se manca start: sintetizzare `tool-input-start` con `toolCallId`/`toolName`                               |
| `tool-result`                            | `tool-result`                    | **Critico**: `output: { output: normalize(result), title, metadata }` come AI SDK                         |
| `tool-error`                             | `tool-error`                     | `error` come `Error` con `.message` (non nuovo tipo)                                                      |
| `provider-error`                         | **throw** `Error(message)`       | Stesso effetto di AI SDK `error` event                                                                    |
| altri / sconosciuti                      | skip + `log.debug`               | Come `default` processor oggi                                                                             |

#### Errori (invarianti)

- **Non** mappare `provider-error` a un nuovo `MessageV2.*` name.
- Stream Effect fallito: `runPromise` / iterator `throw` → stesso `catch` processor (L623+).
- Tool native: mantenere `ToolFailure` **dentro** llm; in session solo messaggi stringa su `tool-error`.

**Manuale E2E**

1. `experimental.nativeLlm` **non** impostato → chat identica (smoke).
2. `experimental.nativeLlm: true` + `openai` / `anthropic` → stream, tool call, retry su 429 simulato (se possibile) comportamento uguale al baseline.
3. Provider non supportato da native → fallback AI SDK senza errore utente.

## Rollback

- `experimental.nativeLlm: false` o rimuovere chiave → 100% AI SDK.
- Nessuna migrazione DB; nessun cambio OpenAPI obbligatorio in P0 (SDK già espone `nativeLlm`).

## Fuori scope (questo piano)

- Nuovi error schema / `LLMError` in UI o API.
- Modifiche a `SessionRetry.retryable` / `MessageV2.fromError`.
- Port `cache-policy` / `provider-error.ts` OpenCode.
- Refactor `processor.ts` in P0.
- Merge `packages/llm` + `src/provider` in un solo package.
- Model fallback chains (solo retry HTTP esistente).

## Regressioni da verificare in P0 (explore)

1. **Opentui** — `tool-input-delta` deve usare proprietà `delta`, non `text`.
2. **Reasoning** — emettere `reasoning-start` / `reasoning-end` sintetici (processor crea part reasoning).
3. **`finish-step`** — passare `usage` e `providerMetadata` da `step-finish` per cost/tokens/compaction.
4. **Retry** — errori stream devono finire in `throw` / shape che `MessageV2.fromError` già gestisce (no nuovi `_tag`).
5. **Tool-result** — `output.output` + `title`/`metadata` come AI SDK; processor non esegue tool su eventi `tool-result` dal modello (solo da AI SDK tool execution).
6. **Compaction** — stesso `processor.process` → test `retry.test.ts` / processor-effect-service.
7. **`stream.text`** — stub `Promise.resolve("")` con `.catch(() => {})` per turn solo-tool.

## Hot path oggi (riferimento)

`SessionPrompt.loop` → `SessionProcessor.process` → `LLM.stream` → `LLMCore.stream` / `streamText` → `fullStream`. Side path: `prepareRequest` only. Non toccare `processor.ts` in P0.
