# Step 2: LLMRequest Builder + LLMClient Layer + Prepare Validation

## Goal

Collegare `@nikcli-ai/llm`'s route-based provider system al flusso di `session/llm.ts`. In Step 1 abbiamo aggiunto `getModelRef()`. Ora costruiamo un `LLMRequest` completo dal `StreamInput` e lo validiamo con `LLMClient.prepare()` — che compila la richiesta HTTP senza mandarla.

## Strategy: Prepare-only (no HTTP cost)

Usiamo `LLMClient.prepare(llmRequest)` invece di `LLMClient.stream()`. Prepare compila ModelRef → route → protocol body → auth → endpoint URL senza fare chiamate HTTP. Zero costo, massima validazione.

Cosa valida:

- Route resolution (ModelRef.route esiste nel registry)
- Protocol body construction (body.from() per Chat/Responses/Messages/Gemini)
- Auth resolution (apiKey, bearer, header injection)
- Endpoint URL compilation (baseURL + path + queryParams)
- Header/query overlays

L'HTTP transport è già testato dalla test suite di `@nikcli-ai/llm`.

### 2. buildLLMRequest() in `session/llm.ts`

```ts
function buildLLMRequest(
  input: StreamInput,
  modelRef: ModelRef,
  params: { temperature?: number; topP?: number; topK?: number },
  headers?: Record<string, string>,
): LLMRequest {
  // System parts
  const system: SystemPart[] = input.system.map(SystemPart.make)

  // Messages: ModelMessage[] → LLM Message[]
  const messages = modelMessagesToLLMMessages(input.messages)

  // Tools: Record<string, Tool> → ToolDefinition[]
  const tools = toLLMToolDefinitions(input.tools)

  // Tool choice
  const toolChoice = input.toolChoice as ToolChoice | undefined

  // Generation options
  const generation = new GenerationOptions({
    temperature: params.temperature,
    topP: params.topP,
    topK: params.topK,
    maxTokens: params.maxOutputTokens,
  })

  // HTTP options
  const http = new HttpOptions({ headers, ... })

  return new LLMRequest({
    model: modelRef,
    system,
    messages,
    tools,
    toolChoice,
    generation,
    http,
  })
}
```

### 3. ModelMessage → LLM Message converter (in `message-v2.ts` o `llm.ts`)

```ts
function modelMessagesToLLMMessages(msgs: ModelMessage[]): Message[] {
  const result: Message[] = []
  for (const msg of msgs) {
    switch (msg.role) {
      case "user":
        result.push(Message.user(toContentParts(msg.content)))
        break
      case "assistant":
        result.push(
          Message.assistant([
            ...(typeof msg.content === "string"
              ? msg.content
                ? [TextPart.make({ text: msg.content })]
                : []
              : msg.content.map(toContentPart)),
            ...(msg.tool_calls?.map((tc) =>
              ToolCallPart.make({
                id: tc.id,
                name: tc.function.name,
                input: JSON.parse(tc.function.arguments),
              }),
            ) ?? []),
          ]),
        )
        break
      case "tool":
        result.push(
          Message.tool(
            ToolResultPart.make({
              id: msg.tool_call_id,
              result: {
                type: "text",
                value: typeof msg.content === "string" ? msg.content : JSON.stringify(msg.content),
              },
            }),
          ),
        )
        break
    }
  }
  return result
}
```

Note: `ModelMessage` è da `ai`, i tipi LLM sono da `@nikcli-ai/llm/schema`.

### 4. Tool converter

```ts
function toLLMToolDefinitions(tools: Record<string, Tool>): ToolDefinition[] {
  return Object.entries(tools).map(([name, tool]) =>
    ToolDefinition.make({
      name,
      description: tool.description ?? "",
      inputSchema: (tool.parameters as Record<string, unknown>) ?? {},
    }),
  )
}
```

### 5. Prepare call in `session/llm.ts`

Dopo la risoluzione del `modelRef`, nel blocco Effect di `stream()`:

```ts
// Costruisci LLMRequest e validalo con prepare (nessun HTTP)
if (modelRef) {
  try {
    const llmRequest = buildLLMRequest(input, modelRef, params, headers)
    const service = yield * LLMClient.Service
    const prepared = yield * service.prepare(llmRequest)
    l.info("LLM request prepared", {
      route: prepared.route,
      protocol: prepared.protocol,
      id: prepared.id,
    })
  } catch (e) {
    l.warn("LLM prepare failed (non-fatal)", {
      modelID: modelRef.id,
      providerID: modelRef.provider,
      error: String(e),
    })
  }
}
```

Il prepare è **non-bloccante** — se fallisce, il flusso esistente continua normalmente. Serve solo per validazione e logging.
