03 Habits — observed, not declared

Communication

  • Bilingual prompts (it/en) → English prose, code stays as-is
  • Brief rationale on non-obvious decisions, then move on

Verification

  • Pass/fail counts + exit codes in the same reply as the change
  • Quote the count — never paraphrase "tests pass"
  • CI red is non-negotiable; never skip or quarantine to make it green

Workflow

  • Read-only exploration delegated to subagents (explore / researcher)
  • Brain pass synthesizes after; no inlined long grep sessions
  • Plan-mode writes a deliverable to disk, not just chat

Code review

  • Critical / High / Medium / Low + a fix-or-leave line per finding
  • Hunts regressions and error-propagation leaks before style
  • Solid unmount-cleanup is a recurring bug class — checked every dialog

Domain focus

  • Auth & onboarding: PKCE S256, device-code, OAuth callbacks
  • TUI dialog lifecycle: cancellation, polling abort, signal teardown
  • Effect service boundaries validate inputs at the seam
  • Cross-package: nikcli ↔ identity in the same change

Audit / inventory

  • Per-item tables with classification (active/dormant, must/should/nice)
  • Recommendations ranked T1 / T2 / T3 / T4 across time horizons

04 The verification chain

Every change ships with its own proof. The chain is non-negotiable, in this order:

bun test <file> → narrowest targeted test first.

bun run typecheck → once, at the end of the edit batch (low-RAM constraint).

bun run build → through monitor, never bash.

Then ci-pipeline. Red is never fixed by skipping, deleting, or quarantining a test.
