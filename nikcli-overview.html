01 Cos'è nikcli

Non è solo una CLI per chattare con un modello: è una piattaforma agentica completa che orchestra modelli, strumenti, subagent e contesto di progetto. Mantiene sessioni persistenti, supporta esecuzione headless in cloud e gira sul terminale locale, in una web app o da mobile.

"Building on the OpenCode base, nikcli adds Goal, Routine, Mobile, Ads, Heap, Locale, the Loops/Mission system, ACP integration, the Session v2 engine and the Effect Schema migration."
⌘ TUI interattiva
Applicazione full-screen costruita su OpenTUI + Solid.js: sessioni, code di turni, cronologia, completamento, permessi, dialoghi modali, attach remoto. 45 FPS, mouse, kitty keyboard, copy-on-select.
⚡ Server headless
Hono con HTTP + SSE + WebSocket, specifica OpenAPI generata automaticamente e SDK TS/JS rigenerato. mDNS per discovery locale, proxy verso sandbox/container.
▶ One-shot CLI
Esecuzione non interattiva: run, goal, mission, agent, generate, github, pr, stats, export/import.
◐ Web companion
UI SolidStart/Cloudflare per sessioni e condivisione pubblica. nikcli web apre il browser, nikcli companion serve serve la UI integrata.
▣ Mobile companion
App Expo / React Native in packages/mobile con SSE realtime. Pairing via QR + deep link nikcli://connect?server=….
⊕ Bot multi-canale
Adapter unificato via @chat-adapter/* per Slack, Discord, Teams, Google Chat, GitHub Issues e Linear. Le sessioni bot sono sessioni nikcli complete.

03 Flusso end-to-end

Dalla digitazione del prompt fino all'azione sull'ambiente: una pipeline che passa per bus tipizzato, agenti con permessi granulari, subagent paralleli e validazione a valle.

01
Prompt utente
TUI, CLI, web, mobile, bot. Attach locale o remoto.
02
Session v2
Stato persistente, MessageV2, fork, revert, compaction.
03
Agente + Skills
build / plan + skill caricati per il contesto.
04
Tool + Subagent
Toolset, MCP, subagent paralleli via delegation/delegator.
05
Esecuzione
Worktree, sandbox, permessi, monitor con log persistenti.
⌬ PermissionNext · 3 livelli di arity
Ogni tool viene valutato con regole per tool/agente/path/comando. Il TUI chiede conferma contestuale quando serve. Le decisioni sono salvate e riutilizzate, evitando prompt ripetitivi senza rinunciare al controllo granulare su side-effect pericolosi.

04 Agenti & subagent

Due agenti primari (build con permessi completi, plan read-only) e una flotta di subagent specializzati invocabili via task, delegation o delegator. Agenti custom generati via LLM con nikcli agent create.

build Permessi completi: edit, bash, write, web primary

general Fallback generico subagent

@planner Piani d'azione strutturati subagent
@code-reviewer Review cognitiva di PR/diff subagent
@debugger Analisi failure/log e ipotesi di fix subagent
@test-runner Esecuzione test, generazione casi subagent
@refactor Refactoring conservativo subagent
scout Esplorazione esterna (librerie, API) subagent
researcher Ricerca evidence-based in background subagent
support Agente documentazione read-only subagent
delegator Batch delegation con supervisor session subagent
ultrareview-reviewer Reviewer parallelo per ultrareview subagent

07 Quickstart

Dall'installazione one-liner alla prima sessione, fino al remote attach.

# install
$ curl -fsSL https://nikcli.store/install | bash
$ nikcli

# accesso rapido
$ nikcli quickstart         # walkthrough 60s per nuovi utenti
$ nikcli doctor            # diagnostica: connettività, config, provider
$ nikcli auth login         # collega un provider LLM

# una sessione, tre modalità
$ nikcli run "refactor auth module"           # one-shot
$ nikcli goal "tutti i test verdi"            # lavora finché non è vero
$ nikcli                                     # TUI interattiva

# server headless + attach remoto
$ nikcli serve --hostname 0.0.0.0 --port 4096
$ nikcli attach http://other-host:4096        # stessa TUI, altra macchina

# build da sorgenti
$ bun install
$ bun run --cwd packages/nikcli --conditions=browser src/index.ts

08 Orchestrazione continua: Loops, Goal, Mission, Routine

Quattro primitive che compongono strumenti esistenti (Scheduler, Goal, task, delegation) senza reinventare nulla. Restano attive anche a TUI chiusa.

⌖ Goal
L'agente lavora finché una condizione verificabile non regge. Stato active | paused | blocked | usage_limited | budget_limited | complete, budget token, MAX_ITERATIONS = 50.
↻ Loops
Workflow persistenti con nome, lista ordinata di stages (ognuno un singolo goal), trigger manuale o a intervallo (Scheduler scope: "instance"). Gira server-side.
◈ Missions
Decomposizione ad alta quota: goal → milestones → DAG di feature. Validation checkpoint per milestone (scrutiny, user-test, none).
⚙ Routines
Workflow schedulati (cron) o attivabili via API/HTTP con auth token. Espongono procedure nikcli come endpoint.

10 Plugin, Skills, TUI sub-plugins

Tre livelli di estensibilità. I plugin aggiungono agenti, tool, hook e provider; le skill sono pacchetti Markdown leggeri; i TUI sub-plugins montano slot, route e keymap senza patchare il core.

⏣ Plugin in-process
Contratto in @nikcli-ai/plugin con hook auth, chat.headers, chat.params, tool.execute.before/after, experimental.session.compacting, experimental.text.complete, command.execute.before…

nikcli plug install @nikcli-ai/plugin-foo
▥ Skills
Formato leggero (Markdown + descrizione + tool associati). Caricate dinamicamente e filtrate contro i permessi dell'agente. Esempi: computer-use, orca-cli, effect, opentui, bun-file-io, orchestration, find-skills, emil-design-eng.
◫ TUI sub-plugins
feature-plugins/ con home, loops, sidebar, system montano viste senza patchare il core. Runtime tui/plugin/ con api.tsx, runtime.ts, slots.tsx, keymap.ts.
⎈ Plugin preconfigurati
agent-memory background background-agents context-analysis direnv dynamic-context-pruning envsitter-guard handoff safety-net smart-title

11 Server, web, mobile, remote

La stessa sessione nikcli è raggiungibile da terminale, browser, app mobile o via tunnel. Tutto passa per il server Hono con SSE realtime.

⌬ HTTP / SSE / WebSocket
packages/nikcli/src/server/server.ts · OpenAPI auto-generato (hono-openapi + generateSpecs) · SDK TS/JS rigenerabile · mDNS con bonjour-service · proxy verso container/sandbox · auth opzionale basic / Tailscale.
◐ Web apps
packages/web (Astro + Tailwind) sito pubblico e installer · packages/app (SolidStart) web app completa · packages/companion UI companion + routes per companion serve.
▣ Mobile companion
Expo / React Native in packages/mobile con SSE realtime, iOS + Android (ios/, android/, eas.json). Pairing via QR + deep link nikcli://connect?server=…&token=…&directory=….
⌖ Remote control
Tunnel: localtunnel, cloudflared, ngrok, remotosh · oppure cloud relay con bearer token (--cloud). packages/remote contiene il client web e il QR renderer.

13 Osservabilità

OpenTelemetry (OTLP) export + pannello live in-process. Configurabile via env all'avvio, non hot-reloadable.

Variabile Default Scopo
OTEL_EXPORTER_OTLP_ENDPOINT unset Endpoint OTLP/HTTP. Impostandolo si abilita l'export.
OTEL_EXPORTER_OTLP_HEADERS unset Coppie key=value separate da virgola (es. Authorization=Bearer%20…)
OTEL_RESOURCE_ATTRIBUTES unset Attributi key=value uniti a ogni risorsa di span
NIKCLI_DISABLE_OTEL_LIVE false Disattiva la cattura span in-process (pannello live)
